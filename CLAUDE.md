# Syllabus Engine — инструкции для разработки

Проект одновременно: (1) платформа обучения Syllabus Engine, (2) её основной пакет обучения Forge ML по ML/DS (`courses/ml-bigdata-ai/`), (3) личный учебный трекер владельца репозитория. Владелец — ученик курса, поэтому не решай за него задачи курса и не подсказывай ответы вне механики подсказок платформы.

## Пакеты обучения
- Каждое обучение — пакет `courses/<id>/` (`package.yaml`, `program.yaml`, `glossary.yaml`, `lessons/`, `components/`). Формат — `docs/template/course-package.md`. Активный — `active:` в `courses/active.yaml`.
- Движок (`apps/`) не должен знать о предмете: ничего про ML в коде платформы, всё предметное — в пакете.
- Новый курс по просьбе пользователя — по промпту `docs/template/course-generator-prompt.md`; что автор может попросить — `docs/template/course-brief-guide.md`.
- Прогресс ученика — `~/.syllabus-engine/<id>.sqlite3`, у каждого пакета свой. Не сбрасывать и не трогать без прямой просьбы; перед изменениями схемы — резервная копия.

## Ветки и рабочие копии
- Основная папка (ветка `main`) — та, из которой владелец проходит курс; там всегда рабочая версия.
- Разработка — в `.worktrees/dev` (ветка `dev`), платформа для проверок запускается на других портах и со своей базой: `SYLLABUS_API_PORT=8775 SYLLABUS_WEB_PORT=5183 SYLLABUS_DATA_DIR=<временная папка> npm run dev`.
- В `main` — только проверенное: тесты, `npm run check`, ревью субагентами, скриншоты.

## Источник правды
- Концепция и решения: `docs/`. Перед изменением архитектуры или методики сверяйся с ними; меняешь решение — обнови документ.
- Документы — на русском, секции не удалять без запроса.

## Принципы
- Локально и из коробки: `git clone` + одна команда. Никаких обязательных облачных сервисов, Docker — только опционально.
- Учебные материалы (`courses/`) отдельно от кода; каждый урок/задача валидируется схемой, каждое эталонное решение проходит свои тесты в CI.
- Всё, что можно проверить кодом, проверяется кодом; Claude проверяет только устные ответы, по рубрике.
- Claude — опциональный слой: без него платформа работает.
- UI без эмодзи, иконки — lucide-react, выровнены по центру текста.
- Уроки пишутся своими словами со ссылками на источники; текст закрытых книг не копировать (см. `docs/content/sources.md`).

## Стек
React + TS + Vite + CodeMirror 6 · FastAPI + SQLite · Pyodide / PGlite / isomorphic-git в браузере · Jupyter-ядро для тяжёлого ML · FSRS · MCP (streamable HTTP на localhost) · uv + pnpm.

## Работа с контентом курса
- Новая дисциплина создаётся тремя кругами из `docs/dev/review-protocol.md`: план → панель ревьюеров → теория → панель → тесты и задачи → панель. Основа — лучшие учебники, курсы и статьи, изложенные своими словами; не выдумка и не выжимка.
- Каждая тема проходит пайплайн оттуда же: написание → логика → факты и определения → понятность и язык → экзаменатор → `npm run check` и скриншоты → коммит.
- Определения — общепринятые, с источником (`formal` + `source` в `<Theorem>`), рядом — простыми словами (`docs/content/style-guide.md`, раздел 13).
- Замечания к курсу — журнал `npm run feedback` (ученик, преподаватель, ревьюеры; замечания ученика из чата заносить туда же). Разбирать до следующего блока по `docs/dev/backlog.md`: уровень «курс», «конвейер» (правило — в общие документы) или «платформа»; пройденное учеником не переписывать.
- Описание каждого субагента начинается с этапа (`design:`, `theory:`, `theory-review:`, `facts:`, `tests:`, `tasks:`, `platform:`); после раздела — `npm run costs -- --save`, отчёт в `courses/<id>/dev/` коммитится вместе с разделом.
- Работу преподавателя (проверку развёрнутых ответов) проверяет отдельная панель — `docs/dev/teaching-audit.md`, данные — `npm run teaching`.
- Структурные решения и отклонённые советы ревьюеров — в `docs/dev/decisions.md`.
