# Рабочая зона разработки курса

Здесь — не документация для ученика, а «кухня»: как устроена логика курса, какие решения приняты и почему. Нужна, чтобы при любом изменении программы не потерять связи между темами.

| Файл | Что внутри |
|---|---|
| [prerequisite-trees.md](../../content/forge-ml/docs/prerequisite-trees.md) | **Генерируется.** Для ключевых тем — всё, на что они опираются, по предметам; плюс разделы, на которые ничто не ссылается |
| [decisions.md](decisions.md) | Журнал решений: что поменяли, почему, какие советы ревьюеров отклонили |
| [review-protocol.md](review-protocol.md) | Как перепроверять программу и макет после каждого изменения |

## Как устроена логика программы

- Источник правды — `content/forge-ml/program.yaml`. Порядок в файле = порядок прохождения.
- Каждый раздел перечисляет `requires` — **настоящие** зависимости (то, без чего тему не понять), а не просто «предыдущий раздел». Иначе деревья предпосылок раздуваются и перестают помогать.
- Разделы математики обязаны иметь `used_by` — где они пригодятся. Математика «на всякий случай» не проходит проверку.
- Скрипт `tools/program/build.py` проверяет порядок, уровни предметов, наличие Алгоритмов на каждом курсе и пересобирает документы.

## Как добавлять и менять темы

1. Правка в `program.yaml` (тема, раздел, `requires`).
2. `uv run --with pyyaml tools/program/build.py` — проверка и генерация.
3. Посмотреть `content/<пакет>/docs/prerequisite-trees.md`: нет ли новой «висячей» темы и логичны ли цепочки.
4. Записать решение в `decisions.md`, если оно меняет структуру.
5. Прогнать ревью по [review-protocol.md](review-protocol.md).
