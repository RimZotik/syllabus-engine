# Сводный список замечаний — по нему перепроверяется всё непройденное

Сюда собраны все замечания ученика и автора (из журнала `npm run feedback` и из разговоров) в виде правил. Подробности и обоснования — в документах, на которые ссылается каждый пункт. Ревьюер, который перепроверяет готовые темы, проходит по **каждому** пункту. Новое замечание сразу дописывается сюда и в общий документ, затем перепроверяется всё непройденное ([backlog.md](backlog.md), «Новое правило — на всё непройденное»).

Уровни: **сервис** — правило Syllabus Engine для любого курса; **курс** — правило заказчика этого курса (`courses/<id>/docs/course-rules.md`).

## Проверка: тесты, контрольные, развёрнутые ответы

1. **Сервис.** Как и что проверять — по практике сильных университетов и курсов. Вопрос себе: «спросили бы об этом здесь на сильном курсе?». (`course-generator-prompt.md`, шаг 11)
2. **Сервис.** Темы о самом курсе и платформе (план, как здесь учатся, преподаватель, повторение, что будет без Claude, кто что проверяет) — короткий тест только об устройстве программы. Функции платформы не проверяются: ученик знает их, ещё выбирая курс. Развёрнутого ответа нет. (`style-guide.md` §12)
3. **Сервис.** Число вопросов — столько, чтобы раскрыть тему с разных сторон. Нормы «10–11 / 18–20» нет. Не по вопросу на подтему или пример. (§12)
4. **Сервис.** Строгость растёт от теста темы к контрольной и к экзамену, а также от курса к курсу, как в вузе. Вводный курс ориентирует: развёрнутые ответы только там, где они закрепляют главную мысль, и проверяются мягко. (§12, `teacher.md` п. 7)
5. **Курс.** «Думать — до последнего вопроса»: каждый вопрос заставляет рассуждать над каждым вариантом. Нельзя, чтобы ответ узнавался по фразе из теории. (`course-rules.md`, «Строгость»)
6. **Курс.** «Почти верно» — значит неверно. Но это приём для разнообразия, а не правило для каждого вопроса: цель — заставить подумать, а не задушить. (`course-rules.md`)
7. **Сервис.** Верный вариант не самый длинный и не самый конкретный. Ответа нет в самом вопросе. Нет слов с двумя прочтениями. Пояснения называют варианты по содержанию, а не по номеру: варианты перемешиваются. (§14)
8. **Сервис.** Рубрика не шире вопроса. Сквозная мысль раздела — не в каждом развёрнутом вопросе. Тест темы проверяет главную мысль вопроса, а не каждую деталь. (§14, §12)
9. **Сервис.** Контрольная не повторяет вопросы тестов и вопросы «Проверь себя»: в ней новые ситуации и вопросы на связь тем.
10. **Сервис.** Ловушки (`traps`) — изредка, 1–2 на тест, и только среди неверных вариантов.
11. **Курс.** Примеры бытовые (магазин, оценки, температура, таймер), не экзотические. Не считать арифметику ради арифметики, кроме тем по математике. (§16)
12. **Сервис.** Вопрос не требует того, чего ещё не было в курсе. Вопрос по формуле, которую нужно просто посчитать, ничего не проверяет.

27. **Курс.** В программировании проверяют кодом: в тестах и контрольных преобладают вопросы `code` (напишите, дополните, исправьте, измените) с нарастающей сложностью; развёрнутый ответ — только там, где нужно объяснить мысль словами. (`course-rules.md`, §12)
28. **Сервис.** Перед задачей с кодом — только короткий ввод: задача открывается на своей странице, текст перед ней уходит в левую колонку. Важная теория с примерами — на страницах до задачи. Задача решается тем, что уже пройдено. (§12)

## Теория

13. **Сервис.** Каждое слово и каждая причинная связь объяснены до первого использования. Обещание «разберём позже» не используется в той же теме. (§15)
14. **Сервис.** Ссылки на пройденное — по содержанию («помните шаблон накопителя»), не по номеру раздела.
15. **Курс.** Живой русский язык:
    - без тавтологий («спор превращается в спор о словах»);
    - без слов с двумя прочтениями («роли уже»);
    - без ошибок падежа («разочаровались в подход»);
    - верный вид глагола после «уметь/мочь»;
    - без двойных «и…, и…»;
    - без метафор «коробки» («лежит», «кладётся»): имя указывает на значение. (§17)
16. **Сервис.** Верный субъект действия: числа модели настраиваются сами при обучении, их не настраивают инженеры.
17. **Сервис.** Определения общепринятые, с источником, рядом — простыми словами. (§13)
18. **Сервис.** Формулы — в формульных блоках по центру, не в строке текста. (§16)
19. **Сервис.** Поговорки и цитаты — в настоящем виде, из русских источников. (§17)
20. **Сервис.** Пожелание ученика — ориентир по форме, а не источник содержания. Ответы на его вопросы в чате в уроки не вставляются. (`backlog.md`)

## Преподаватель (проверка развёрнутых ответов)

21. **Сервис.** Видит текст урока, место вопроса (тема / раздел / дисциплина), номер курса и уровень. Не называет ошибкой то, что сказано в уроке. (`teacher.md` пп. 7–10)
22. **Сервис.** Строгость — по ступеням (п. 4). Побочная ошибка, не задевающая сути вопроса, — ответ принят, ошибка поправлена.
23. **Сервис.** Читает каждое утверждение в той роли, которую дал ему ученик: дополнительный пример — не ответ на критерий.
24. **Сервис.** Подсказывает только внутри темы вопроса. Не выдаёт готовый ответ. В правках не больше трёх пунктов.
25. **Сервис.** Видит историю попыток и знает, дописал ученик ответ, отредактировал или написал заново. К дописыванию относится лояльно. Понимание, показанное в прежних попытках, засчитывается. Неизменённые верные части не хвалит повторно.
26. **Сервис.** Отзыв:
    - статус показывается один раз;
    - без ошибок — одна короткая фраза;
    - ученик сказал больше, чем требовалось, — похвала за это и, может быть, ещё пример;
    - с неточностями — сначала правки, в конце короткий вывод;
    - не принят — правки и наводящий вопрос отдельным блоком.
