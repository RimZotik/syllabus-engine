## 2026-11-22 — терминал в браузере, этап 3: как в Ubuntu 24.04

Авторы теории `infra1.shell` нашли места, где тренажёр расходился с настоящей Ubuntu 24.04; тексты уроков описывают Ubuntu, поэтому исправлен тренажёр. На каждое расхождение есть регрессионный тест (`apps/web/src/shell/__tests__/ubuntu.test.ts`).

- **Окружение.** `EDITOR` больше не задан (в Ubuntu нет ни `EDITOR`, ни `VISUAL`). `PATH` теперь как в `/etc/environment` (9 папок, вместе с `sbin`, `games` и `/snap/bin`). В `~/.bashrc` есть `alias ls='ls --color=auto'` и `alias grep='grep --color=auto'`, поэтому `type ls` отвечает как в Ubuntu. В домашней папке есть `.profile` и `.bash_logout`.
- **Полный путь при сломанном `PATH`.** `/usr/bin/ls` работает (раньше был `__exec: command not found`). Служебные команды тренажёра вызываются по абсолютному пути и скрыты из `ls /usr/bin` и из дополнения по Tab. Команды в `/bin` и `/usr/bin` получили права `rwxr-xr-x`.
- **`cp`/`mv` в `папку/`, которой нет:** `Not a directory`, как в coreutils; файл с этим именем больше не создаётся. Шаблон `*/` совпадает только с папками и даёт имена со слешем: интерпретатор совпадал и с файлами, поэтому такие шаблоны раскрывает сессия.
- **`ls` в терминале** заключает имена в кавычки, как GNU ls: кириллица и любые буквы — без кавычек; пробел и знаки оболочки — в кавычках; управляющие символы — как `$'\r'`. Если на экране есть имя в кавычках, перед остальными ставится пробел для выравнивания. Сначала печатаются ошибки, потом список. В конвейере ошибки ранних команд выводятся раньше вывода последней.
- **`nano` как 7.2 в Ubuntu 24.04.**
  - Шесть подсказок в ряду при ширине 80.
  - `^F`/`^B` двигают курсор вперёд/назад: поиск по `^F` появился только в nano 8. Поиск — `^W`, в тренажёре `F6`, потому что `Ctrl+W` забирает браузер; это исправляет запись этапа 1 про `^F`. `M-Q` ищет назад.
  - Файл с концами строк Windows: при чтении `Converted from DOS format`, запись обратно с `\r\n`, в строке имени `[DOS Format]`, `M-D` переключает.
- **Процессы.**
  - `top` обновляется раз в 3 секунды (по умолчанию в procps-ng), столбцы стоят под заголовками.
  - `ps aux | grep hog` показывает и сам `grep` (с `--color=auto` из псевдонима).
  - У каждого `ps` новый PID.
  - VSZ не бывает меньше RSS.
- **`find -name *.csv`** без кавычек, когда шаблон раскрылся в несколько имён: второе сообщение findutils `possible unquoted pattern after predicate`.
- **Python.** `python3` отвечает `bash: python3: command not found`: в настоящей Ubuntu `python3` есть, но тренажёр Python не запускает (мост к Pyodide отклонён на этапе 2). `python` — подсказка Ubuntu «Command 'python' not found, did you mean…», её ученик увидит и на своём компьютере. Python в тренажёре нет нигде, как в системе без пакета `python3`: `type python3` пишет `bash: type: python3: not found`, `which python3` и `command -v python3` ничего не печатают и возвращают 1, файла `/usr/bin/python3` нет. То же внутри скриптов.
- **Не исправлено.**
  - Порядок строк в файле при `> f 2>&1`: его задаёт интерпретатор — сначала stdout, потом stderr.
  - Подсказка command-not-found для незнакомых команд: остаётся `bash: X: command not found`, как в bash без этого пакета.
  - `.bashrc` короче настоящего (3771 байт): нет приглашения с цветами и `lesspipe` — только то, что тренажёр выполняет.

## 2026-11-22 — терминал в браузере, этап 2: права, процессы, окружение, скрипты

Для тем `infra1.shell` 4–6 и `infra1.scripts` 1. Формат — `docs/content/authoring.md`, 3.2 «Этап 2».

- **Права — в файловой системе, а не в командах.** Строгая ФС тренажёра хранит владельца и группу каждого пути и проверяет каждое обращение (чтение, запись, создание и удаление по правам папки, проход по x, sticky `/tmp`) для действующего пользователя. Поэтому права соблюдают и наши команды, и встроенные just-bash (`sort`, `grep`, `find`), и перенаправления. just-bash не умеет сообщать об отказе в перенаправлении — исключение ловится и превращается в `bash: f: Permission denied`; `cd` в папку без x отсекается до запуска.
- **sudo меняет действующего пользователя только на время своей команды**, а перенаправления строки выполняет оболочка ученика — ловушка `sudo echo > /etc/f` получается сама. Пароль — ученика (`setup.sudo_password`, по умолчанию `forge`), у root пароля нет (как в Ubuntu: `su` к root не пускает). Пользователи по умолчанию: root, student (student, sudo), anna (anna, team); `/etc/passwd`, `/etc/group` строятся из этой базы.
- **Процессы — таблица, а не настоящие программы.** Поведения задаются в задаче (`busy`, `ignore_term`, `logger`, `cleanup`); время — настоящие часы, догоняются перед каждой командой. Свои `sleep` (с регистрацией процесса, Ctrl+C/Ctrl+Z), `&` (sleep — просто запись в таблице; другое выполняется сразу, до 3 с, и если не закончилось — остаётся «работающим» заданием), `jobs/fg/bg`, `$!` (подставляется в дерево разбора — у интерпретатора нет заданий). Журнал сигналов — для проверки `signal_sent`.
- **Окружение между строками**: just-bash выполняет каждую строку заново, поэтому сессия хранит отдельно экспортированные переменные (передаются как окружение) и переменные оболочки (восстанавливаются присваиваниями перед строкой) — так `X=1; bash -c 'echo $X'` пуст, как в bash. Псевдонимы хранятся как у just-bash (`BASH_ALIAS_*`, с `shopt -s expand_aliases`), функции — текстом определения. «Новое окно» — новый bash с `~/.bashrc`; `sudo -i`/`su` — стек оболочек, `exit` снимает верхнюю.
- **Скрипты** выполняет just-bash (x-бит, shebang, дочерний процесс, `$0…$9`, `set -euo pipefail` у него есть); свои — запуск по пути (`__exec`: x для действующего пользователя, разбор shebang, `^M: bad interpreter`) и `bash ФАЙЛ` с Windows-концами строк (пустая строка `\r` → `$'\r': command not found` с номером строки).
- **Отклонено: мост `python3` → Pyodide.** Нужен режим драйвера Pyodide с синхронизацией ФС тренажёра в обе стороны, argv/env/код выхода, а для валидатора — Pyodide под Node (десятки секунд на запуск, отдельная зависимость сборки). Это сравнимо по объёму со всем этапом 2, а нужен он трём задачам из плана (2.1(6), 2.2(6), 2.5(1–2)); их честнее перенести в 3.4 на WSL (как и предлагал план курса) или сделать мост отдельной работой. `python3` в тренажёре — «command not found», shebang python — понятное сообщение.
- **Ограничения**: `read` с клавиатуры внутри скрипта не поддерживается (у just-bash `read` встроенный, переопределить нельзя) — ввод через `|`/`<<<`; порядок stdout/stderr внутри одного скрипта — сначала вывод, потом ошибки; функции из `source`-файлов переживают строку, только если записаны в виде `имя() {` … `}` с начала строки; нет `apt`, `umask` не меняется, нет ACL и setuid-исполнения.

## 2026-11-22 — терминал в браузере

Тренажёр для `infra1.shell` (позже — `vcs1`, `infra1.scripts`): песочница `sandbox: shell`, компонент `<Shell>`, код — `apps/web/src/shell/`. Формат задачи — `docs/content/authoring.md`, раздел 3.2.

- **Основа — just-bash 3.6.1 (vercel-labs, Apache-2.0)**, а не свой интерпретатор и не v86. Это готовый интерпретатор bash на TypeScript с ФС в памяти: разбор строки, конвейеры, перенаправления, `&& ||`, шаблоны, кавычки, `$(…)`, `$((…))`, `if/for/while`, функции — свой интерпретатор потратил бы на это недели. В браузере работает (проверено сборкой Vite и запуском в Edge); грузится отдельным куском только на страницах с терминалом: ≈1,27 МБ (≈350 КБ gzip) + xterm.js и наш код ≈410 КБ (≈110 КБ gzip). v86 с настоящим Linux — десятки мегабайт и проверка ФС через 9p; остаётся опцией «настоящий терминал без установки».
- **Где just-bash расходится с GNU — свои команды** (через `defineCommand`): `ls cat head tail wc cp mv rm mkdir rmdir touch tee uniq` написаны заново с дословными сообщениями coreutils (кавычки `'x'` и `‘x’` — как в Ubuntu с UTF-8), ширинами `wc`, `uniq -c` в 7 знаков, порядком «файлы, потом папки» в `ls`, колонками и цветами `ls` в терминале, `-i` с вопросом. `sort cut grep find file tree` — обёртки над встроенными: исправляют сообщения (`find: ‘x’`, `sort: cannot read:`), вывод `grep -r .`, рамки `tree`. ФС сделана строгой: родительская папка не создаётся сама (`echo > nodir/x` — ошибка), файл не затирает папку.
- **Строка выполняется по конвейерам**, `&&`/`||` решаются у нас по кодам возврата: just-bash отдаёт stdout и stderr целиком, и без этого `echo a; ls nope; echo b` печатал бы ошибку последней. Внутри одной нашей команды порядок stdout/stderr тоже сохраняется. Переменные и папка переносятся между строками.
- **Терминал — xterm.js 6.0.0** со своей строкой ввода (история, Tab, Ctrl+C/L/U/K/W/A/E). nano, less/man и минимальный vim — чистая логика «клавиша → экран» (`screens.ts`), тестируется без браузера. Клавиши браузера (Ctrl+S, Ctrl+O, Ctrl+F, Ctrl+K, Ctrl+U, Ctrl+X, Alt+…, F1–F10) перехватываются, пока фокус в терминале. **Ctrl+W, Ctrl+T, Ctrl+N браузер странице не отдаёт** — в nano поиск продублирован на F6 и Ctrl+F (как в nano 8), а кнопка «Во весь экран» включает Keyboard Lock API (Chromium): в полноэкранном режиме Ctrl+W достаётся nano.
- **Проверки — итог, а не набранные символы**: состояние ФС, вывод, `run` на копии ФС, команды по синтаксическому дереву. Эталон каждой задачи выполняется валидатором в том же движке под Node (`node apps/web/src/shell/headless.ts`, без сборщика — поэтому импорты внутри `shell/` с расширением `.ts`).
- **Ограничения этапа 1**: один пользователь `student`, права не проверяются (`ls -l` честный, `chmod` меняет биты, владельцы — из задачи или по месту файла); нет фоновых заданий, процессов и сигналов; функции и алиасы не переживают строку; `ls` в колонках, только когда он последний в конвейере без перенаправления; `cat` без файла не ждёт ввода с клавиатуры; `wc < file` выравнивает как канал (ширина 7); `gzip`, `python3`, сеть недоступны.
- **Этап 2**: пользователи и права с проверкой при каждом доступе, `sudo` (пароль из задачи, ловушка `sudo echo > /etc/…`), `chown/chgrp/id/groups/su`; искусственные процессы с поведением (`hog`, `stubborn`, `logger`, `cleanup`), `ps/top/kill/jobs/fg/bg`, Ctrl+Z, коды `128+N`, проверки `process_*`/`signal_sent`; окружение: переменная оболочки против `export`, `PATH` и поиск команд, `source`, `~/.bashrc` при «новом окне»; скрипты (`./script.sh` с `x` и shebang, дочерний процесс, `$'\r': command not found`); мост `python3` к Pyodide; упрощённый `apt`.

## 2026-11-20 · Задача — рабочее место как на LeetCode; вопросы с кодом в тестах

- **Клавиши в редакторе — редактору.** Стрелки, PgUp/PgDn, Home/End, Tab в редакторе кода работают внутри него; листание страниц стрелками срабатывает только вне полей ввода и редактора. Ctrl+Enter — «Проверить».

- **Каждой задаче — своя страница.** Читалка делит страницу с `<Sandbox>`: на каждую задачу — страница-«рабочее место» (слева условие, подсказки и текст перед задачей, справа редактор и тесты). Текст после последней задачи — отдельная страница. Содержание курса переписывать не пришлось.
- **Вопрос `code` в тестах и контрольных.** Засчитывается, если код проходит все тесты; при «Сдать» непроверенный код проверяется сам. Проверка курса прогоняет эталон на тестах и требует, чтобы стартовый код их не проходил. По просьбе ученика: в программировании проверки — в основном кодом (`course-rules.md`, `style-guide.md` §12).

## 2026-11-18 · План сервиса, каталог блоков, источники по предмету

- **PostgreSQL — в план, не сейчас.** Локально остаётся SQLite: ничего не нужно ставить, и это главный принцип локального инструмента. PostgreSQL нужен серверу с аккаунтами и общими данными. Чтобы переход был дешёвым, особенности SQLite держим в `db.py`. План — [hosting-roadmap.md](../platform/hosting-roadmap.md).
- **Каталог блоков** ([template/blocks.md](../template/blocks.md)): что есть сейчас и какие универсальные блоки нужны другим предметам — работа на проверку (изображение, PDF), холст, звук, ноты и MIDI, тренажёр слуха, карточки, кейсы. Агенты сначала берут блок из каталога. Звук Claude напрямую не оценивает, поэтому для музыки основной формат сдачи — ноты и MIDI, а аудио проверяется через анализ в браузере.
- **Источники подбираются по предмету** (таблица в `course-brief-guide.md`). Для областей, где ошибка вредит человеку, — только доказательная база.

## 2026-11-18 · Несколько обучений на одной платформе

- Платформа обслуживает сразу все обучения из `courses/`, у каждого свой адрес: `/<id>/learn/…`, `/<id>/test/…`, `/<id>/record`. На `/` — каталог, если обучений больше одного. `courses/active.yaml` стал обучением по умолчанию: в него ведут `/` при одном обучении и старые адреса без имени (`/learn/…`), так что закладки и «последнее место» не ломаются.
- Сервер выбирает обучение по заголовку `X-Syllabus-Package`, который сайт берёт из адреса страницы. У каждого обучения своя база ученика, она открывается при первом обращении. Сайт собирает материалы всех обучений, а при смене обучения монтируется заново, чтобы ни одно состояние не перетекало из одного обучения в другое.
- В паспорт (`package.yaml`) добавлена карточка каталога: `subtitle`, `icon` (lucide), `color`, `level`, `version`, `author`, `license`, `tags`. Имя обучения входит в адрес, поэтому валидатор запрещает имена, совпадающие с разделами платформы.
- Задел на площадку, где авторы публикуют и продают обучения: пакеты уже самостоятельны (паспорт, лицензия, свои данные учеников, свой адрес). Аккаунты, оплата и публикация — отдельный этап с сервером в интернете, сейчас не делаются.

## 2026-11-18 · Контрольная раздела — строгий режим

- Проверка темы остаётся учебной: разбор сразу, можно перепройти. Контрольная раздела — экзамен:
  - сначала экран правил и кнопка «Начать контрольную»;
  - пока идёт попытка, темы и содержание недоступны;
  - внизу вместо «К последней теме» стоит кнопка «Закончить попытку». Окно подтверждения перечисляет вопросы без ответа: они засчитываются как неверные;
  - ниже порога ученик видит только счёт «верно X из Y», процент и порог, без разбора. Так ошибки исправляются пониманием, а не запоминанием верных вариантов. Развёрнутые ответы в такой попытке преподавателю не отправляются;
  - если контрольная сдана, открывается полный разбор: отметки и пояснения;
  - следующий раздел открывается после сдачи.
- Каждая попытка сохраняется (`quiz_state.history`: номер, счёт, ответы). Ответы по вопросам пишутся в `attempt`. По ним преподаватель видит, как ученик исправляет ошибки от попытки к попытке.

## 2026-11-18 · История ответов, номер попытки, состояние демонстраций

- **Историю ответов храним полностью, показываем последнее.** Каждая сдача развёрнутого ответа — отдельная запись `attempt` с текстом и отзывом преподавателя. Так видно, как ученик пришёл к ответу. Это нужно на устных экзаменах и переходных испытаниях: преподаватель начинает со слабых мест (teacher.md, раздел 12). Ученик видит только последнюю редакцию и последний отзыв. Промежуточные черновики между сдачами не храним: они ничего не говорят о понимании.
- Подпись под отзывом: «Принят с N-й попытки» или «Попытка N». Проверки, аннулированные аудитом преподавания, в N не входят.
- Второй аудит преподавания (`intro1.what.4`) — KEEP: зачёт верный, но на одной попытке преподаватель придрался — просил пересказать уже сказанное и задал неоднозначный вопрос. В инструкцию добавлено:
  - ответ оценивается целиком;
  - вопросы задаются только к главному пробелу;
  - сначала одной фразой называется, чего не хватает;
  - вопросы однозначные и опираются на урок или демонстрацию.
- В урок про k ближайших соседей добавлена фраза о том, что при очень большом k всё поле достаётся классу, у которого точек больше. Демонстрация больше не красит ничью молча в зелёный.
- Компоненты курсов сохраняют своё состояние через `usePageState` из `@syllabus/sdk`. Песочница помнит вывод последнего запуска.

## 2026-11-18 · Аудит преподавания и исправление проверки развёрнутых ответов

- Появилась отдельная проверка работы преподавателя на живых ответах: [teaching-audit.md](teaching-audit.md), данные — `npm run teaching`.
- Первый аудит (вопрос `intro1.what.4 / explain-tradeoff`) вынес вердикт REGRADE:
  - критерий отмечен «не выполнен», хотя в отзыве сам преподаватель эту мысль похвалил;
  - назван «misconception», которого нет в типичных ошибках, причём с готовым ответом внутри;
  - наводящие вопросы содержали слова ответа («островки», «шум», «как называется это явление?»);
  - три блока вопросов — слишком много для новичка.
- Исправлено:
  - у критерия теперь три состояния (`met / partial / missing`);
  - преподаватель не требует ни терминов, ни подробностей сверх рубрики;
  - в отзыве — 1–2 наводящих вопроса без слов ответа;
  - `misconception` заполняется только по списку `wrong_answers`;
  - рубрика вопроса переписана: «переобучение» своими словами, без обязательного термина.
- **Отклонено:** засчитывать ответ, если все критерии выполнены хотя бы частично. Курс строгий: «частично» значит «доработайте», но доработка должна быть посильной и без подсказки ответа.

## 2026-11-18 · Без самооценки уверенности

- Кнопки «Насколько вы уверены? 1–5» у развёрнутых ответов убраны. Ученик их не отмечал: ответ он и так пишет по прочитанной теории, и вторая оценка того же ничего не добавляет. Преподаватель эти цифры не использовал.
