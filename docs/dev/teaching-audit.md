# Аудит преподавания

Отдельная от создания курса проверка: насколько хорошо **преподаватель** (Claude, `apps/server/syllabus_server/grader.py`) проверяет развёрнутые ответы ученика и наставляет его. Материалы курса проверяют ревьюеры из [review-protocol.md](review-protocol.md), а здесь проверяют работу преподавателя на живых ответах.

## Когда проводится

- По просьбе ученика или автора, если отзыв преподавателя кажется неточным, слишком строгим или слишком подсказывающим.
- После каждого раздела, который ученик прошёл: выборочно, по последним проверкам.
- После любого изменения инструкции преподавателя (`grader.py`, `docs/product/teacher.md`): на нескольких старых ответах, чтобы сравнить «до» и «после».

## Входные данные

`npm run teaching` (или `uv run --project apps/server python -m syllabus_server.teaching --scope <тема> --last <N>`) печатает из базы ученика вопрос, рубрику, типичные ошибки, ответ ученика, оценку по каждому критерию и отзыв преподавателя. Команда только читает базу.

## Панель

Субагенты на старшей модели, описание начинается с `teaching-audit:`. Роли — как кафедра, которая оценивает компетентность преподавателей:

- **профессор дидактики и оценивания** — справедливость оценки, обратная связь, не задавлен ли ученик;
- **профессор предмета** — верно ли по существу всё, что сказал преподаватель;
- **методист для начинающих взрослых** — соответствие уровню курса и пройденному материалу.

## Что проверяется

1. **Точность оценки.** Каждый критерий «выполнен / не выполнен» справедлив с учётом ответа, рубрики и того, что **уже пройдено** в курсе. Вердикт соответствует уровню курса. Заблуждение, которое назвал преподаватель, действительно есть в ответе, а не придумано.
2. **Педагогика.**
   - Отзыв показывает, что ученик уже понял и чего не хватает.
   - Он поддерживает, но не размыт, и по нему понятно, что делать дальше.
   - Он **не выдаёт ответ**: наводящий вопрос, в котором уже есть нужное слово («есть ли островки?»), — это подсказка, а не проверка.
   - Он не требует терминов, которых в курсе ещё не было.
   - Объём посильный для новичка.
3. **Вердикт для оператора:** `KEEP` — оценка остаётся, ученик дорабатывает ответ; `REGRADE` — оценка или отзыв заметно неверны, и после исправления инструкции преподавателя ответ проверяется заново.
4. **Исправления:** точный текст правок инструкции преподавателя и/или рубрики вопроса.

## Что делать с результатом

- `REGRADE`: сначала исправить инструкцию или рубрику (через обычный порядок: коммит в `dev`, тесты, `main`). Затем, сделав резервную копию базы ученика, снять у этого вопроса оценку (`grades[<id>]` в `quiz_state`) — **только у развёрнутого ответа**: тестовая часть и текст ответа остаются, ученик нажимает «Сдать ответ снова». Записи `attempt` не удаляются: это история.
- `KEEP`: ничего не трогать, ученик дорабатывает ответ.
- Выводы и отклонённые советы панели записываются в [decisions.md](decisions.md).
