# Журнал замечаний к курсу

Всё, что не так в материалах обучения, собирается в одном месте: базе ученика (таблица `feedback`). Разбор идёт по правилам ниже, чтобы одна найденная ошибка исправляла не только себя, но и всё, что будет написано дальше.

## Откуда приходят замечания

| Источник | Как попадает | `source` |
|---|---|---|
| Ученик | кнопка «Предложить правку» в теме и в контрольной, с выделенным маркером фрагментом | `learner` |
| Преподаватель | при проверке развёрнутого ответа замечает, что неточен сам вопрос или рубрика (поле `content_issue`); ученик этого не видит | `teacher` |
| Ревьюеры, аудит преподавания, Claude при разработке | `npm run feedback -- --add "текст" --topic <id>` | `system` |
| Замечания ученика в чате с Claude | Claude сам заносит их тем же `--add` | `system` |

## Как разбирать

`npm run feedback` показывает открытые замечания. Их разбирают до того, как писать следующий раздел. По каждому замечанию решают, **на каком уровне** ошибка:

1. **Курс** (`--level course`) — частная ошибка этого обучения: неточная формулировка, спорный вариант ответа, опечатка. Исправить в материалах. Если ошибка типичная для этого курса, записать правило в `courses/<id>/docs/course-rules.md`, и авторы следующих разделов его соблюдают.
2. **Конвейер** (`--level pipeline`) — ошибка, которую может допустить любой курс: в вопросе спрятан ответ, вариант верен лишь наполовину, кальки с английского, пословица в переводе. Исправить в курсе и обязательно дописать правило в общие документы (`docs/content/style-guide.md`, `docs/dev/review-protocol.md`, промпт генерации), чтобы ревьюеры всех будущих курсов это ловили.
3. **Платформа** (`--level platform`) — ошибка кода: пропадает текст, не открывается страница. Исправить в `apps/` через обычный порядок: dev, тесты, main.

Закрыть: `npm run feedback -- --resolve <id> --level <уровень> --note "что сделано"` (или `--status wontfix` с причиной).

## Что уже пройдено — не трогаем

Правки содержания вносятся только в то, что ученик ещё не прошёл: темы без отметки «пройдено», контрольные, которые ещё не сданы. Пройденное остаётся как было: не меняются ни отметки, ни оценки, ни история попыток. Если ошибка серьёзная (например, неверный факт), в пройденную тему добавляется уточнение, а не переписывается текст. Исключение — опечатки и явные ошибки фактов: их можно исправить, прогресс от этого не меняется.

## Новое правило — на всё непройденное

Замечание ученика или новое правило (о вопросах, вариантах, проверке, языке) применяется не только к разделам, которые ещё будут написаны, но и ко всему написанному, что ученик ещё не прошёл: темы, тесты, контрольные, задачи. Порядок: сначала правило — в общие документы (`style-guide.md`, `course-rules.md`, инструкция преподавателя), затем перепроверка непройденного по этому правилу ревьюерами, и только потом — новые разделы. Пройденное — по правилам раздела выше.

Запас наперёд. Написанное, но не пройденное — это то, что придётся перепроверять после каждого нового правила. Поэтому запас держится по темпу ученика: примерно на одну-две недели его занятий (темп — по датам прохождения в базе), а не «как можно больше».

## Пожелание — не источник

Ученик (или автор, заказавший курс) может не знать материал и того, как его лучше объяснить. Его пожелание говорит, что ему непонятно и каким он хотел бы видеть объяснение, — это ориентир по форме. Содержание и способ объяснения берутся из лучших учебников и статей и упрощаются уже после. После правки по пожеланию страница снова проходит ревью: не появилось ли новой путаницы.

## Не перегнуть, исправляя

Исправление не должно ломать то, что было хорошо. Особенно в вопросах тестов: устраняя двусмысленность, легко положить ответ в сам вопрос. Каждая правка вопроса снова проходит экзаменатора по всем пунктам `style-guide.md` §14, а не только по тому, на который пожаловались.
