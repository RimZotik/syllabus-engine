# Протокол перепроверки

## Пайплайн добавления контента (обязателен для каждой новой темы, раздела или дисциплины)

Применяется к любому блоку — от одной темы до целой дисциплины. Шаги идут **строго по порядку**: каждый следующий ревьюер получает уже исправленный материал.

| Шаг | Кто | Что проверяет | Результат |
|---|---|---|---|
| 1. Написание | автор (Claude, основная модель) | по [style-guide](../content/style-guide.md): вводная лекция, круг истории, определения с источником, примеры, визуализации, тест по объёму темы | файлы темы, тесты, термины в глоссарии |
| 2. Логика | субагент-методист | порядок изложения, опора только на пройденное (деревья предпосылок), полнота, вопросы теста покрывают все страницы и проверяют понимание | список правок → исправить |
| 3. Факты и определения | субагент-фактчекер (с поиском в интернете) | каждое определение сверено с признанными источниками; даты, имена, утверждения верны; нет упрощений, искажающих смысл | список правок с источниками → исправить |
| 4. Понятность и язык | субагент «ученик-новичок» + редактор русского языка | понятно ли без подготовки, нет ли «замудрённости», ошибок русского языка | список правок → исправить |
| 4б. Вопросы тестов | субагент-экзаменатор | по [style-guide](../content/style-guide.md), раздел 14: вопрос однозначен; варианты не копируют текст лекции (с учётом нарастания); неверные варианты правдоподобны, но точно неверны; правильный не выделяется длиной; ловушки помечены и их немного | список правок → исправить |
| 5. Техническая проверка | автор | `npm run check` (валидатор: термины, ответы, структура), скриншоты страниц на 1440 px и 390 px | всё зелёное |
| 6. Фиксация | автор | коммит; если менялась структура — запись в [decisions](decisions.md) | — |

После прохождения учеником: замечания из `npm run feedback` (от ученика и от преподавателя) разбираются и возвращают блок на шаг 2.

## Ревьюеры структуры и интерфейса

После любого заметного изменения программы или интерфейса — независимые ревьюеры (субагенты). Отчёты на английском, решения — в [decisions.md](decisions.md).

| Ревьюер | Когда | Что проверяет |
|---|---|---|
| **Аудитор логики** (старшая модель) | любое изменение `program.yaml` | Каждую тему с Курса 0: всё ли, что она использует, пройдено раньше; чего не хватает; дубли |
| **Методист** | изменение структуры курсов и предметов | Названия, деление на уровни, баланс часов, место практики, чего не хватает в 2026 году |
| **Ученики** (3 профиля: вайб-кодер, взрослый новичок, нетерпеливый студент) | изменение начала обучения | Где бросят, где скучно, где перегруз |
| **Работодатели** (ML, DS, DE, AI) | раз в несколько крупных изменений | Пройдёт ли выпускник отбор; что устарело |
| **UI-дизайнер** | изменение макета или интерфейса | Контраст, палитра, типографика, отступы, обрезанный текст — по скриншотам |
| **UX-дизайнер** | изменение сценариев | Понятно ли, что делать дальше; навигация; пустые и ошибочные состояния |

Снимки интерфейса: Edge в headless-режиме на 1440 px и на 390 px (через iframe — окно браузера на Windows не бывает уже ~480 px).
