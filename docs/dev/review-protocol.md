# Протокол перепроверки

## Три круга создания дисциплины

Новая дисциплина (или крупный раздел) создаётся **тремя кругами**. Следующий круг начинается, только когда предыдущий прошёл свою панель ревьюеров без серьёзных замечаний.

**Основа — лучшие источники, а не выдумка и не выжимка.** До плана автор собирает для дисциплины признанные учебники, университетские курсы (MIT, Stanford, CMU, Harvard, ВШЭ, МФТИ, ШАД), сильные онлайн-курсы, статьи и документацию. Для каждой темы записывается, из каких источников она собрана и что взято у каждого (`courses/<id>/docs/sources/<дисциплина>.md`). Тема объединяет лучшее из них и излагается своими словами, простым языком, в порядке, который выбран для ученика.

| Круг | Что делает автор | Панель ревьюеров (субагенты, каждый со своей ролью) |
|---|---|---|
| **1. План** | источники → темы с целями («после темы ученик умеет…»), порядок, предпосылки по `requires`, где будут практика и задачи | **преподаватель** (методика, порядок, объём), **учёный-предметник** (полнота и корректность, ничего важного не упущено), **работодатель** (это нужно в работе? чего не хватает до Junior+), **ученик-новичок** (где будет страшно и непонятно), **независимый аудитор логики** (каждая тема опирается только на пройденное) |
| **2. Теория** | темы по style-guide: формулировки с источником, примеры, демонстрации | **методист** (логика, дозировка формулировок, только главное), **фактчекер с поиском** (каждое утверждение и определение по источнику), **учёный-предметник** (нет упрощений, которые станут ошибкой позже), **литературный редактор учебников** (язык, ритм, понятность, единые термины), **ученик-новичок** (понятно ли без подготовки) |
| **3. Тесты и задачи** | `quiz.yaml`, `test.yaml`, задачи с тестами и подсказками | **экзаменатор** (каждый вопрос отдельно, раздел 14 style-guide), **проверяющий задач** (условие однозначно, эталон проходит тесты, тесты ловят типичные ошибки, подсказки ведут, но не решают), **работодатель** (задачи похожи на реальную работу), **ученик** (решаемо ли по пройденному, нет ли подвоха в формулировке) |

Каждый ревьюер работает независимо и отчитывается списком «проблема → где → как исправить». Автор исправляет, спорное решает сам и записывает отклонённые советы в [decisions](decisions.md). Если исправления существенные, тот же круг повторяется.

Шаги внутри кругов 2 и 3 расписаны ниже.

## Пайплайн добавления контента (обязателен для каждой новой темы, раздела или дисциплины)

Применяется к любому блоку — от одной темы до целой дисциплины. Шаги идут **строго по порядку**: каждый следующий ревьюер получает уже исправленный материал.

| Шаг | Кто | Что проверяет | Результат |
|---|---|---|---|
| 1. Написание | автор (Claude, основная модель) | по [style-guide](../content/style-guide.md): вводная лекция, круг истории, определения с источником, примеры, визуализации, тест по объёму темы | файлы темы, тесты, термины в глоссарии |
| 2. Логика | субагент-методист | порядок изложения, опора только на пройденное (деревья предпосылок), полнота, вопросы теста покрывают все страницы и проверяют понимание; дозировка теории (style-guide, раздел 15): нет монотонной череды формулировок (определений, теорем) — длинные серии разбавлены объяснением и примерами, связанный набор понятий допустим вместе; терминов не больше, чем нужно для главной мысли; лишние термины и «определения ради определений» — убрать или отложить | список правок → исправить |
| 3. Факты и определения | субагент-фактчекер (с поиском в интернете) | каждое определение сверено с признанными источниками; даты, имена, утверждения верны; нет упрощений, искажающих смысл; **пословицы, поговорки, крылатые фразы и цитаты** — дословно в том виде, как их знают по-русски, сверены с русскими источниками (Даль, Михельсон, словарь Жукова, Грамота.ру, Викицитатник), а не переведены с английского; изменённая поговорка допустима, только если текст прямо говорит, что это переделка | список правок с источниками → исправить |
| 4. Понятность и язык | субагент «ученик-новичок» + редактор русского языка | понятно ли без подготовки, нет ли «замудрённости», ошибок русского языка; нет калек с английского (оборотов, метафор, порядка слов, которых нет в живом русском), там где есть устоявшийся русский термин — используется он; конструкции не сложнее смысла: обычное перечисление — через одно «и», двойное «и…, и…», «как…, так и…», «не только…, но и…» — только для логического усиления (style-guide, раздел 17). Шаг повторяется после любых правок текста, в том числе вопросов тестов: экзаменатор проверяет смысл, редактор — язык | список правок → исправить |
| 4б. Вопросы тестов | субагент-экзаменатор | по [style-guide](../content/style-guide.md), раздел 14: каждый вопрос проходится **отдельно**: вопрос проверяет главное в теме, а не второстепенную деталь лекции (историю, даты, примеры «для атмосферы») — иначе убрать или заменить вопросом на суть; ровно один (или заявленные) вариант защитимо верен; у каждого варианта один смысл (нет двойного прочтения «предмет или действие»); правильный не копирует лекцию (с учётом нарастания) и не использует слово, которым лекция называла другое понятие; неверные правдоподобны, но точно неверны; баланс — ни один вариант не выделяется, но и не все выглядят обманом; грамматика без лишних союзов; ловушки помечены и их 1–2 на тест. Экзаменатор работает на старшей модели и проверяет **все** вопросы, включая переписанные | список правок → исправить |
| 5. Техническая проверка | автор | `npm run check` (валидатор: термины, ответы, структура), скриншоты страниц на 1440 px и 390 px | всё зелёное |
| 6. Фиксация | автор | коммит; если менялась структура — запись в [decisions](decisions.md) | — |

**Учёт затрат.** Описание каждого субагента начинается с этапа (`design:`, `theory:`, `theory-review:`, `facts:`, `tests:`, `tasks:`, `platform:`). После каждого раздела — `npm run costs -- --save`, отчёт `courses/<id>/dev/token-costs.md` коммитится вместе с разделом (подробнее — `docs/template/course-package.md`, раздел 10).

После прохождения учеником: замечания из `npm run feedback` (от ученика и от преподавателя) разбираются и возвращают блок на шаг 2.

## Ревьюеры структуры и интерфейса

После любого заметного изменения программы или интерфейса — независимые ревьюеры (субагенты). Отчёты на английском, решения — в [decisions.md](decisions.md).

| Ревьюер | Когда | Что проверяет |
|---|---|---|
| **Аудитор логики** (старшая модель) | любое изменение `program.yaml` | Каждую тему с Курса 0: всё ли, что она использует, пройдено раньше; чего не хватает; дубли |
| **Методист** | изменение структуры курсов и предметов | Названия, деление на уровни, баланс часов, место практики, чего не хватает в 2026 году |
| **Ученики** (3 профиля: вайб-кодер, взрослый новичок, нетерпеливый студент) | изменение начала обучения | Где бросят, где скучно, где перегруз |
| **Работодатели** (ML, DS, DE, AI) | раз в несколько крупных изменений | Пройдёт ли выпускник отбор; что устарело |
| **UI-дизайнер** | изменение макета или интерфейса | Контраст, палитра, типографика, отступы, обрезанный текст — по скриншотам |
| **UX-дизайнер** | изменение сценариев | Понятно ли, что делать дальше; навигация; пустые и ошибочные состояния |

Снимки интерфейса: Edge в headless-режиме на 1440 px и на 390 px (через iframe — окно браузера на Windows не бывает уже ~480 px).
