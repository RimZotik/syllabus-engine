# Путь к сервису: от локального инструмента к площадке

Сейчас Syllabus Engine — локальный инструмент: `git clone` и одна команда, данные ученика у него на компьютере, преподаватель — его собственный Claude Code. Этот документ собирает заметки о том, как вырасти в сервис, где авторы публикуют обучения, а ученики проходят их в браузере. **Пока это план, а не задача:** решения здесь принимаются, когда этап начинается. Всё, что делается сейчас, не должно мешать этому пути.

## Этапы

| Этап | Что это | Кто платит за преподавателя |
|---|---|---|
| **0. Локальный инструмент** (сейчас) | форк репозитория, своё обучение в `courses/`, всё на своём компьютере | ученик — своей подпиской Claude |
| **1. Хостинг проверенных обучений** | сайт с готовыми обучениями, которые прошли проверку; ученик только учится | подписка ученика на сервис |
| **2. Площадка авторов** | авторы делают обучения локально, публикуют, продают доступ; сервис берёт процент | ученик платит за обучение, автор получает долю |

Разработка обучений остаётся локальной на всех этапах. Агенты, проверки и ревью работают на машине автора, а на сервис попадает готовый проверенный пакет.

## Что понадобится на сервере

**Аккаунты.** Вход (почта, OAuth), роли «ученик», «автор», «модератор». Данные ученика привязываются к аккаунту, а не к компьютеру.

**База данных — PostgreSQL.** Локально SQLite остаётся: ничего не нужно ставить, и это главный принцип этапа 0. На сервере нужен PostgreSQL: много учеников одновременно, резервные копии, аналитика, отчёты для преподавателя.
- Схема та же, к каждой таблице добавляются `user_id` и `package_id`. Сейчас файл базы свой у каждого обучения, на сервере это станет колонкой.
- Чтобы переход был дешёвым, SQL пишем переносимым. Особенности SQLite (например `json_extract`, `datetime('now')`) держим в слое `db.py`, а не размазываем по коду. Миграции — те же пронумерованные скрипты.
- Локальный PostgreSQL в Docker можно добавить опцией для разработчиков сервиса. Обязательным он не становится.

**Преподаватель через API.** Локально проверка идёт через `claude -p` ученика. На сервере — через Anthropic API с ключом сервиса. Вся проверка уже собрана в одном модуле (`apps/server/syllabus_server/grader.py`), меняется только способ вызова.
- **Квоты:** лимит проверок в день на ученика, зависит от тарифа. Длина ответа ограничена.
- **Защита от злоупотреблений:** проверка только ответов на вопросы курса, ответ ученика остаётся данными (уже так, тег `<answer>`), ограничение частоты запросов.
- **Учёт стоимости:** каждая проверка записывает токены (как `npm run costs` для разработки), отсюда считается себестоимость тарифа.
- **Модели:** дешёвая модель для проверок, старшая для устных экзаменов.

**Память преподавателя об ученике.** История попыток уже хранится полностью (решение 2026-11-18): все версии ответов, отзывы, попытки контрольных. На сервере к ней добавляется сводка по ученику: слабые места, типичные ошибки, темп. Преподаватель читает её перед экзаменом. Сводку пересчитывает фоновая задача, а не каждая проверка.

**Файлы учеников.** Для блоков загрузки работ (фото рисунков, аудио, проекты; см. [каталог блоков](../template/blocks.md)) нужно хранилище файлов, совместимое с S3, с ограничением размера и сроком хранения.

**Публикация обучений.**
- Пакет загружается как есть (папка `courses/<id>/`), с версией из паспорта.
- Перед публикацией сервис сам прогоняет `npm run check`. Модератор смотрит отчёты ревью и лицензию.
- Новая версия обучения не ломает прогресс тех, кто уже учится: темы адресуются по id, а не по порядку.

**Оплата и доли авторов.** Платёжный провайдер, выплаты авторам, отчёты продаж. Это отдельный большой этап с юридической частью: договор-оферта, налоги, возвраты.

**Персональные данные.** Для пользователей из России — 152-ФЗ: хранение персональных данных на серверах в РФ, согласие на обработку. Для ЕС — GDPR: выгрузка и удаление своих данных по запросу.

## Что уже сделано с прицелом на этот путь

- Обучения — самостоятельные пакеты: паспорт, лицензия, свой адрес (`/<id>/…`), свои данные ученика.
- Каталог обучений на главной и карточка с автором, версией и лицензией.
- Преподаватель — отдельный модуль. Его роль и стиль задаются паспортом обучения.
- Полная история ответов и попыток для памяти преподавателя.
- Учёт токенов разработки (`npm run costs`) — основа будущей цены.
- Аудит работы преподавателя ([teaching-audit.md](../dev/teaching-audit.md)) — основа контроля качества на сервисе.
