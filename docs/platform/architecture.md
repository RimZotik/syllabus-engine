# 04. Архитектура платформы

> Платформа — **Syllabus Engine**; первый курс на ней — **Forge ML**.
> Принципы: локально и из коробки (`git clone` + одна команда), контент отдельно от кода, всё лёгкое работает прямо в браузере, тяжёлое — на локальном сервере, Claude подключается опционально.

## 1. Стек и почему именно он

| Слой | Выбор | Почему |
|---|---|---|
| Фронтенд | React + TypeScript + Vite | Стандарт, богатая экосистема для редакторов и визуализаций |
| Редактор кода | **CodeMirror 6** | Лёгкий (~200 КБ против ~5–10 МБ у Monaco), есть Python и SQL с диалектом PostgreSQL, легко снимать телеметрию нажатий (время, правки, вставки из буфера) |
| Линтер Python в браузере | Ruff (WASM) | Мгновенно подсвечивает синтаксис и неизвестные имена |
| Формулы | KaTeX (показ), MathLive (ввод формул с виртуальной клавиатурой) | |
| Визуализации | Mafs (интерактивная математика), Observable Plot / D3, matplotlib через Pyodide; анимации Manim — заранее отрендеренным видео | |
| Иконки | lucide-react | Без эмодзи в интерфейсе |
| Бэкенд | **Python + FastAPI** | Нужен Python в любом случае: запуск ML-кода, Jupyter-ядра, PyTorch/Spark, официальный MCP SDK. Один язык для всей «тяжёлой» части |
| База платформы | **SQLite** (SQLAlchemy 2 + Alembic) | Ноль установки — это главное для «запустил из коробки». PostgreSQL изучается в курсе, но для хранения прогресса одного ученика он избыточен |
| Повторение | FSRS (`fsrs` для Python) | Расписание живёт на сервере, один источник правды |
| Запуск | **uv + pnpm** | uv сам ставит нужный Python и зависимости, работает на Windows/macOS/Linux; Docker — опциональный режим |

Почему не Rust/Node на бэкенде: они быстрее для обычного CRUD, но всё равно пришлось бы держать рядом Python для ML-ядер и проверок. Два бэкенда — двойная сложность без выгоды.

## 2. Песочницы (раннеры)

У каждого задания есть поле `runtime`, фронтенд выбирает нужный раннер. Все раннеры реализуют один интерфейс: «выполни код → верни вывод, результаты тестов, ошибки».

| Раннер | Где работает | Для чего | Как проверяется |
|---|---|---|---|
| `python-browser` | Pyodide в Web Worker | Python, NumPy, pandas, scikit-learn, SymPy, matplotlib на маленьких данных | Скрытые тесты в стиле pytest внутри воркера; зависание — перезапуск воркера по таймауту (держим запасной «тёплый» воркер) |
| `python-kernel` | Локальное Jupyter-ядро на сервере | PyTorch, Spark, большие датасеты, Kaggle | Те же тесты, но в ядре; прерывание через ядро |
| `sql` | **PGlite** (настоящий PostgreSQL в WASM) | Весь модуль SQL, pgvector для RAG | Запрос ученика и эталон на свежей базе: колонки, типы, строки как множество (порядок важен только при ORDER BY), допуск для дробных |
| `sql-olap` | DuckDB-WASM | Parquet, аналитика, Big Data-lite | То же |
| `git-browser` | isomorphic-git + виртуальная ФС + терминал xterm.js | Основы Git: init, add, commit, branch, merge | Снимок состояния: ветки, граф коммитов (по структуре и сообщениям, не по хэшам), индекс, файлы — сравнивается с декларативными условиями |
| `git-real` | Настоящий git во временной папке через сервер | rebase, stash, конфликты, reflog | То же, через `git status --porcelain` и `git log` |
| `shell` | Симулятор bash на виртуальной ФС в браузере; для продвинутого — настоящий терминал через сервер | Модуль 0 | Состояние ФС + история команд |
| `math` | Compute Engine (быстро) → SymPy в Pyodide (сложные случаи) | Модуль 2 | Символьная эквивалентность, проверка в случайных точках, допуск для матриц |
| `quiz` | Фронтенд | Выбор одного/нескольких, порядок строк | Детерминированно |
| `free-text` | Claude | Устные ответы | Рубрика (см. ../product/learning-method.md, раздел 6) |

### Визуализация в песочницах

Песочница не только проверяет, но и **показывает**, что происходит:

| Песочница | Что видно |
|---|---|
| SQL | Схема базы (таблицы и связи), результат запроса таблицей; для JOIN — какие строки с какими соединились; для GROUP BY — как строки собрались в группы |
| Git | Живой граф коммитов и веток, указатели HEAD и веток, три зоны (рабочая папка → индекс → репозиторий) |
| Терминал | Дерево файловой системы, которое меняется по мере команд |
| Python | Пошаговое выполнение: значения переменных, ссылки между объектами (как Python Tutor) |
| Линейная алгебра | Преобразование плоскости матрицей, векторы, собственные направления |
| Матанализ | График функции, касательная, шаги градиентного спуска |
| Вероятности | Симуляции: гистограмма сходится к распределению, ЦПТ вживую |
| ML | Разделяющая поверхность модели, разбиения дерева, шаги бустинга, кривые обучения |
| Нейросети | Схема сети с весами (толщина и цвет связей), активации, поток градиентов при обратном проходе |
| Трансформеры | Карта внимания: какие токены на какие смотрят |
| RAG | Чанки документа, векторы в 2D-проекции, какие чанки нашлись по запросу |

Для слабых компьютеров: всё до модуля M6 включительно работает в браузере. Для M7+ — либо локальное ядро, либо инструкция «запусти этот ноутбук в Kaggle/Colab и вставь результат», который проверяется по метрикам.

## 3. Контент: где и как хранится

Контент — обычные файлы в git, отдельно от кода платформы. Править урок = править текстовый файл.

```
content/
  program.yaml                    # учебный план: курсы → дисциплины → разделы → темы (проверяется скриптом)
  concepts.yaml                   # граф концептов и предпосылок
  courses/
    I-foundation/
      sql1/                       # дисциплина
        discipline.yaml           # порог экзамена, открываемые библиотеки, устные вопросы экзамена
        joins/                    # раздел
          section.yaml            # контрольная раздела
          01-join-types/          # тема
            topic.mdx             # теория: Markdown + компоненты (<Viz/>, <Check/>, <Sandbox/>)
            checks.yaml           # встроенные мини-проверки
            media/
        tasks/
          left-join-orders/
            task.yaml             # условие, песочница, концепты, сложность, лестница подсказок
            starter.sql           # заготовка
            solution.sql          # эталон (не отдаётся на фронт)
            tests.yaml            # проверки результата
      project.yaml                # курсовой проект и его рубрика
  question_families/              # семейства вопросов: шаблон + генератор + рубрика
    linalg/matmul.py
```

- Формат урока — **MDX** (Markdown, внутри которого можно вставить интерактивный компонент). Формулы — `$...$` через KaTeX.
- Схемы всех YAML проверяются валидатором (pydantic) в CI: битая ссылка на концепт, отсутствующие тесты или решение — ошибка сборки.
- Эталонные решения и скрытые тесты не отдаются фронтенду, проверка идёт через сервер или изолированный воркер.

## 4. Данные ученика

SQLite-файл в `~/.forge-ml/` (вне репозитория, не попадает в git). Основные таблицы:

- `learner` — профиль, настройки (целевое удержание, часы в неделю)
- `concept_state` — FSRS-состояние по каждому концепту
- `attempt` — каждая попытка: задание, вариант, время, попытки, подсказки, результат, уверенность, тип ошибки
- `editor_telemetry` — агрегаты по правкам в редакторе
- `note` — заметки к урокам и задачам, с типом: «для себя», «непонятно», «предложение по улучшению»
- `cheatsheet` — личные карточки (метод, концепт, пример) — участвуют в повторении
- `review` — оценки Claude, комментарии наставника, оспаривания
- `session` — учебные сессии (время, что пройдено)

Экспорт/импорт прогресса одним JSON-файлом.

## 5. Интеграция с Claude

Полное описание роли преподавателя, протокола экзамена, MCP-инструментов и экономии токенов — в [07-teacher-claude.md](../product/teacher.md). Здесь — только техническая суть.

- Claude — опциональный слой: без него платформа работает, устные и рукописные ответы встают в очередь.
- Платформа находит `claude` в PATH (`claude --version`) и сама запускает его в режиме `claude -p --input-format stream-json --output-format stream-json` со своим MCP-конфигом и системным промптом преподавателя. Схема взята из montage-studio, где уже работает.
- MCP-сервер встроен в FastAPI: `127.0.0.1`, случайный порт и токен на каждый запуск.
- **Лимиты подписки** берутся из события `rate_limit_event` в потоке Claude (окна `five_hour` и `seven_day`: загрузка, время сброса, статус) и хранятся в базе. Если данные старше 15 минут — короткий служебный запрос к самой дешёвой модели. Учётные данные Claude платформа не читает.
- Проверяющий подключаемый: `claude-cli` (по умолчанию), `anthropic-api` (ключ), `local` (на будущее).
- **Правила использования подписки.** По состоянию на ноябрь 2026, вызовы `claude -p` под своей учётной записью расходуют лимиты подписки и разрешены для личного использования. Политика менялась несколько раз: каждый пользователь логинится сам, платформа не хранит чужие учётные данные и не работает как хостинг; перед публикацией правила перепроверяются.

```
ml-bigdata-learning/

    web/            # React-фронтенд

  tools/

  docs/             # концепция, методика, архитектура, решения (ADR)
```

## 7. Запуск из коробки

```
git clone ... && cd ml-bigdata-learning
uv run forge setup     # ставит Python-зависимости, собирает фронтенд, создаёт базу
uv run forge start     # открывает браузер на http://localhost:8765
```

Требования: установленные `uv` и Node.js (pnpm ставится автоматически через corepack). Опционально: `docker compose up` для тех, кто не хочет ставить ничего, кроме Docker. Тяжёлые зависимости (PyTorch, Spark/JDK) ставятся отдельной командой только при переходе к модулям M7+ — чтобы старт был лёгким.

Особенности Windows: никаких bash-скриптов в запуске, `PYTHONUTF8=1`, настоящий терминал — через ConPTY (`pywinpty`), Spark — через WSL или с предупреждением.

## 8. Движок и контент-пакет

Платформа разделена на **движок** (ничего не знает о предмете) и **контент-пакет** (`content/`). Песочницы и предметные визуализации подключаются как плагины с единым интерфейсом. Это позволяет собрать курс по другому направлению, не трогая движок, — см. [template/new-domain.md](../template/new-domain.md).

```
apps/web/src/
  engine/        # навигация, страницы, повторение, экзамены, глоссарий — без предметного кода
  content/       # компоненты разметки тем: Mark, Term, Aside, Formula, Figure, Viz, Check, Sandbox
  viz/blocks/    # базовые блоки визуализаций (Plane2D, TableViz, GraphViz, StepPlayer…)
  plugins/       # песочницы: python-browser, sql, git, shell, math, … (каждая — SandboxPlugin)
apps/server/
  engine/        # API, FSRS, рубежи, генераторы, MCP, преподаватель
  plugins/       # серверная часть песочниц (ядро Python, настоящий git, терминал)
```

| Курсы | Минимум | Где считается тяжёлое |
|---|---|---|

## 10. Реализация этапа 1 (что уже работает)

**Запуск.** `npm install`, затем `npm run dev` — поднимает API-сервер (uvicorn, порт 8765) и веб-приложение (Vite, порт 5173) одной командой; если порты заняты, второй экземпляр не запускается. Вместо pnpm используется npm — он идёт вместе с Node.js, одной зависимостью меньше.

**Сервер** (`apps/server/forge_server/`):

| Файл | Что делает |
|---|---|
| `app.py` | HTTP API: учебный план, прогресс, попытки тестов, заметки, замечания к курсу, журнал ошибок, статус Claude |
| `db.py` | SQLite и упорядоченные миграции (только добавлять новые, никогда не менять применённые) |
| `program.py` | Читает `content/program.yaml`, перечитывает при изменении файла |
| `claude.py` | Проверяет, установлен ли `claude`, и его версию |
| `feedback.py` | Выводит открытые замечания к курсу в Markdown — «входящие» автора курса |

**Данные ученика** — `~/.forge-ml/` (или `FORGE_DATA_DIR`): база `forge.sqlite3` и журнал `logs/server.log` (ротация по 2 МБ). В репозиторий не попадают.

**Журналирование и ошибки.**
- Любая необработанная ошибка сервера пишется в `server.log` и в таблицу `event`, а пользователю возвращается понятное сообщение.
- Ошибки в браузере (`error`, `unhandledrejection`) отправляются на `/api/log` и попадают туда же.

**Замечания к курсу — отдельный поток, не путать с вопросами по теории.** Таблица `feedback` (`kind`: проблема в материале, ошибка платформы, идея, вопрос по курсу; `source`: ученик, преподаватель, система).
- Ученик пишет замечание кнопкой «Предложить правку» в теме.
- Преподаватель Claude добавляет замечание сам, когда видит, что трудность вызвана подачей материала, а не пробелом ученика (см. [teacher](../product/teacher.md), раздел 11).
- Автор курса разбирает входящие командой `npm run feedback`, правит материалы и меняет статус замечания.

**Веб** (`apps/web/src/`): `content/registry.ts` находит темы, тесты и контрольные в `content/courses/` по структуре папок; `content/components.tsx` — компоненты разметки тем; `pages/Reader.tsx` разбивает тему на страницы, добавляет страницу «План урока» и страницу «Проверка»; `components/Quiz.tsx` — тесты с выбором и развёрнутыми ответами (последние ждут проверки преподавателем).

**Проверки.** `npm run check`:
- `tools/program/build.py --check` — учебный план, деревья предпосылок, ссылки на глоссарий, корректность тестов, процент готовности в README;
- проверка типов TypeScript;
- тесты сервера (pytest).

**Что дальше:** интервальное повторение и тренажёр (этап 2), песочницы Python/SQL/Git (этап 3), подключение преподавателя через MCP и проверка развёрнутых ответов (этап 4).

### 10.1 Проверка развёрнутых ответов и сохранение тестов
- `POST /api/grade` — вызывает `forge_server/grader.py` (`claude -p --output-format json --json-schema … --tools "" --no-session-persistence --strict-mcp-config`), сохраняет попытку с отзывом, возвращает `verdict`, `feedback`, `attempt`. Claude недоступен → 503 с понятным текстом.
- `GET/PUT /api/quiz-state/{scope}` — порядок вопросов, ответы, отзывы; флаг `passed` только накапливается. Если тест в контенте изменился (другие вопросы), сохранённое состояние не используется.
- Поиск Claude: `PATH`, затем типовые папки установки (`~/.local/bin`, `%APPDATA%/npm`). Пока Claude не найден, сервер перепроверяет его каждые 15 секунд, а интерфейс — каждые 30 секунд и при возврате в окно: установка или вход замечаются без перезапуска.
- Лимиты подписки: каждый вызов `claude -p` идёт в режиме `stream-json --verbose`, из события `rate_limit_event` берутся загрузка 5-часового и недельного окна и время сброса. Источники: проверки ответов, короткий запрос на haiku при старте сервера и по кнопке «Обновить» (не чаще раза в 5 минут). В шапке — две мини-полоски, в окне Claude — проценты и время сброса; цвет: зелёный до 70%, янтарный до 90%, красный выше. Учётные данные Claude платформа не читает.
- Всё, что делает ученик, сохраняется в базе и восстанавливается при возврате: ответы, итог теста (`score`, время сдачи), вердикты и комментарии преподавателя по каждой попытке (`attempt.feedback`, история — `GET /api/attempts?scope=…`). Это же правило — для будущих решений задач в песочницах: код, результат тестов, отзыв.
- Соединение с SQLite своё у каждого потока сервера (`PerThread` в `db.py`): одно общее соединение ломалось при одновременных запросах.
- Ошибка отрисовки страницы показывает сообщение «Страница не открылась» и пишется в журнал, а не оставляет белый экран; при переходе на другую страницу всё сбрасывается.

### 10.2 Песочница python-browser — реализовано
- `apps/web/src/sandbox/`: `py.worker.ts` (Pyodide в Web Worker), `runner.ts` (таймаут → воркер убивается и заменяется новым; ошибки Python объясняются по-русски), `driver.py` — общий код запуска и тестов. Тот же `driver.py` запускает `tools/program/taskcheck.py` при `npm run check`: эталон проверяется ровно так же, как код ученика.
- Pyodide раздаётся из npm-пакета по адресу `/pyodide/` (плагин в `vite.config.ts`), при сборке копируется в `dist/` — интернет не нужен. Пакеты NumPy/pandas подгружаются позже, при первом `loadPackage`.
- Редактор — CodeMirror 6 с подсветкой Python, цвета берутся из токенов темы.
- Вторая копия платформы (например, ветка в отдельной папке) запускается на других портах: `FORGE_API_PORT`, `FORGE_WEB_PORT`, база — `FORGE_DATA_DIR`.
