# prog1 — Основы Python: материалы для плана (раунд 1)

> Дисциплина `prog1`, Курс I, 60 ч. Ученик знает только Курс 0 (кода не писал). Среда — Python в браузере (Pyodide), задачи со скрытыми тестами (stdin/stdout или assert, см. `docs/product`/`docs/content/authoring.md` §3.1).
> Пометки: **[проверено]** — оглавление/факт открыт на первоисточнике при подготовке; **[из практики]** — широко известно из преподавания, но здесь по источнику не перепроверялось; **[проверить]** — гипотеза о платформе/Pyodide, нужно проверить до написания задач.

## 1. Цель дисциплины

После prog1 ученик **сам, без подсказок** пишет на Python программы, читает чужой код и чинит свой. Измеримо:

1. Трассирует программу вручную (значения переменных по шагам) и предсказывает вывод для кода с условиями, циклами и вызовами функций — на бумаге, без запуска. *(нужно для algo1.thinking «трассировка вручную».)*
2. Пишет программы «ввод → обработка → вывод» по условию в стиле контеста: читает числа/строки из stdin, выводит в точном формате. *(algo1, Тренажёр алгоритмов с Курса II.)*
3. Пишет чистые функции с параметрами, значениями по умолчанию и `return`; различает `print` и `return`; разбивает задачу на 3–5 функций. *(prog2: классы, pytest.)*
4. Выбирает структуру данных — список, кортеж, словарь, множество — и объясняет, почему; понимает, что такое ссылка, и не попадает в ловушки изменяемости. *(algo1.thinking/basic; db1.model — «таблица = список словарей»; prog2.)*
5. Обрабатывает данные comprehension'ами и сортировкой с `key`; считает частоты словарём. *(data/pandas позже: «своя мини-таблица» → pandas.)*
6. Читает и пишет текстовые файлы, CSV и JSON; разбирает текст методами строк и простыми регулярными выражениями; работает с датами. *(dl3.text — «своя токенизация», TF-IDF с нуля; db1.modify — sqlite3.)*
7. Обрабатывает ошибки (`try/except`), читает traceback, пишет собственные проверки через `assert`, отлаживает по трассировке. *(prog2.testing — pytest; eng1.vocab — сообщения об ошибках.)*
8. Подключает модули стандартной библиотеки, делит свой код на модули (`if __name__ == "__main__"`), понимает, что такое pip и PyPI. *(infra1.scripts — uv/venv; prog3.quality — пакет.)*

Что ученик **не** умеет по итогам (намеренно): классы (prog2), генераторы/декораторы/замыкания (prog3), рекурсия и O-большое (algo1), NumPy/pandas (после «открытия» своими руками), асинхронность, потоки.

**Наблюдения.**
1. Все начинают с «значение, имя, ввод/вывод» и условий/циклов. Спор — где функции: до коллекций (CS50P, Think Python, CS61A) или после (Matthes, Stepik, Яндекс). Для нас **функции раньше коллекций** — чтобы автопроверяемые задачи с `def` и `assert` были с первых дней, а «трассировка и вызовы» тренировались на числах и строках, а не на сложных структурах. Строка — уже последовательность, на ней учимся индексам и циклам по элементам.
2. Исключения/assert/отладка у лучших источников стоят **рано** (CS50P нед. 3; Automate гл. 5 «Debugging»; MIT л. 12–13), не в конце. В нашем плане они в последнем разделе, а файлы (где `FileNotFoundError`) — раньше. Это противоречие → переставляем (§5).
3. Мутация и aliasing (MIT л. 10–11, CS61A 2.4, Яндекс «модель памяти») — **отдельная** тема сразу после списков, не пункт среди других.
4. Рекурсию, O-большое, поиск и сортировки CS61A/MIT проходят внутри вводного курса; у нас они в algo1 — убираем из prog1 целиком.
5. Строки: у всех базовые операции — в самом начале (нужны для ввода-вывода), «глубокие» методы и regex — позже.

**Рекомендуемый порядок:** значения/имена → числа → строки и ввод-вывод → условия → циклы → функции (с декомпозицией) → коллекции (список → изменяемость → словари/множества → comprehension → сортировка) → исключения/assert/отладка → строки глубже, regex → файлы и форматы → время → модули → мини-проект. Обоснование: (а) каждая следующая тема использует ровно то, что уже есть; (б) «модель исполнения» вводится в первой же теме и далее только уточняется; (в) файлы и сторонние данные не появляются до исключений.

## 4. Разделы и темы

Условные обозначения: **[было: …]** — тема в текущем плане; **[новая]** — предложенная; **[перенос]** — меняет место. Задачи — идеи для `sandbox: python-browser`; «тест:» — что проверяют (hidden-тесты там, где указано).
Сквозные правила задач (из метода «сначала своими руками»): в ранних темах **запрещены встроенные «ответы»** (`sum`, `max`, `sorted`, `str.split`… там, где тема — их реализация); проверка запретов — через AST (**[проверить]** поддерживает ли платформа; иначе — проверка по поведению, см. §5, п. 10).

### Раздел prog1.basics — Основы языка (≈7 ч, 3 темы)

#### 1.1 Программа, значения и имена **[было: «Переменные и типы» — первая половина]**
- **Цели:** показать, что программа — последовательность инструкций; создаёт значения и привязывает к ним имена; знает `int, float, str, bool, None`; предсказывает результат присваиваний `a = b; b = a + 1`.
- **Ключевые идеи:** выражение vs инструкция; имя указывает на значение (модель «ярлык», не «коробка» — вводим сразу, пригодится в изменяемости); тип значения, а не имени; `type()`; правила именования, PEP 8 (snake_case); комментарии. Порядок исполнения сверху вниз.
- **Источники:** MIT 6.100L л. 1; CS61A 1.2 Elements of Programming; Think Python 3e гл. 2; Python Tutorial 3.1; Яндекс «Введение».
- **Заблуждения:** `=` читается как «равно» из математики, а не «присвоить» (ProgMiscon: **AssignCompares**); `a = b` копирует значение/объект (**AssignmentCopiesObject**); «переменная хранит выражение, а не результат» (**VariablesHoldExpressions** — после `y = x + 1` смена `x` меняет `y`); имя хранит объект «внутри себя» (**VariablesHoldObjects**) **[проверено в реестре]**; `x = x + 1` «невозможно» **[из практики]**.
- **Визуализации:** пошаговый визуализатор «код — таблица имён → объекты» (стрелки), по шагу; карта `int/float/str/bool/None` с примерами.
- **Задачи:** (1) «Обмен» — поменять `a`,`b` без стандартного трюка, тест: значения после; (2) «Что выведет» — угадать вывод 5 фрагментов (проверка выбором ответа/`<Check>`, не песочница); (3) `type`-зоопарк: вернуть тип выражения как строку (assert); (4) исправить код с опечаткой в имени (NameError → починить; тест — вывод); (5) трассировка: заполнить таблицу значений (форма-проверка).
- **НЕ включаем:** `id()`, интернирование, `is` (позже в «Изменяемости»); `complex`, `Decimal`, `Fraction` (не нужны ближайшие курсы; Decimal — по месту в math1).

#### 1.2 Числа и арифметика **[было: «арифметика» из первой темы]**
- **Цели:** уверенно использует `+ - * / // % **`, `abs/round/divmod`, преобразование типов; понимает, что `/` всегда даёт `float`, `//` и `%` — «деление с остатком», отрицательные числа.
- **Идеи:** приоритет операций; `int()` обрезает к нулю vs `//` вниз; составное присваивание `+=`; `float` неточен — только показать `0.1 + 0.2` и отослать к math1.numbers (там причины); `round()` — банковское округление; пример: часы/минуты по секундам, последняя цифра числа.
- **Источники:** Python Tutorial 3.1.1 + гл. 15 (Floating-Point Arithmetic — для ссылки); MIT 6.100L л. 1–2, 5 (float, approximation) ; Think Python 3e гл. 2; Stepik, модуль «Типы данных».
- **Заблуждения:** `7 / 2` даёт `3` (унаследовано из школы/других языков) и `//` как «округление» для отрицательных (`-7 // 2 == -4`) **[из практики]**; `5 % 3` — «процент» ; `**` vs `^` (в Python `^` — XOR) **[из практики]**; `round(2.5) == 3` **[из практики]**; сравнение float через `==`.
- **Визуализации:** числовая ось: `//` и `%` как «сколько шагов ушло и сколько осталось»; часы-циферблат для `%`.
- **Задачи:** (1) секунды → ч:мин:с (stdin/stdout); (2) сумма цифр трёхзначного числа через `//` и `%` (тест на 100, 999, 101); (3) «Сдача» — монеты 10/5/2/1 через `divmod`; (4) среднее трёх чисел, вывод с двумя знаками; (5) вычислить, что выведет `-7 // 2`, `-7 % 2` — в виде функции с assert (тест на отрицательные).
- **НЕ включаем:** битовые операции, `math` — в теме 7.2; точность float — math1.numbers.

#### 1.3 Строки, ввод и вывод **[было: «ввод и вывод»; **перенос** базовых строк из «Текст и файлы»]**
- **Цели:** читает данные из `input()` (всегда строка!), разбирает несколько значений в строке (`split`, `map(int, …)`), выводит в нужном формате (`sep`, `end`, f-строка); индексирует строку и берёт `len`.
- **Идеи:** `input()` возвращает `str`; преобразование; f-строки; индексы с 0, отрицательные индексы; строки неизменяемы; `+` и `*` для строк; escape `\n`, `'` и `"`; тройные кавычки; кириллица и UTF-8 (ссылка на infra1.machine).
- **Источники:** CS50P нед. 0 (функции, переменные; «Strings, f-strings, split») ; MIT 6.100L л. 2; Automate гл. 1; Think Python 3e гл. 2 + 8; Матиас PCC гл. 2, 7; Stepik модуль «Ввод-вывод данных».
- **Заблуждения:** `input()` вернул число (`"2" + "3"` даёт `"23"`, не `5`); `print` «возвращает» значение (**ReturnCall** косвенно — см. 3.1); путают `print(x)` и `"x"`; пробелы в конце вывода **[из практики]**; `s[0]` vs `s[1]` — «первый символ» (off-by-one на индексах) **[из практики]**; строка меняется методом на месте (`s.upper()` без присваивания) **[из практики]**.

- **Идеи:** CSV = «Comma-Separated Values», таблица текстом; JSON = «JavaScript Object Notation», вложенные структуры (словарь/список/число/строка/bool/null); YAML = конфигурации (в стандартной библиотеке **нет** парсера) — знакомимся как с форматом, читаем руками; `ensure_ascii=False` для кириллицы; преобразование типов вручную (мост к pandas).
- **Источники:** Python Docs `csv`, `json`; Automate гл. 18 (CSV, JSON, XML); Think Python 3e гл. 13; Яндекс (глава «Коллекции»: файлы и JSON); Python Tutorial 7.2.2.
- **Заблуждения:** в CSV числа уже числа; JSON — это словарь Python (почти, но `True` → `true`, `None` → `null`, ключи — только строки) **[из практики]**; кавычки/запятые внутри значений; `split(",")` как парсер CSV **[из практики]**.
- **Визуализации:** «одна и та же запись» в CSV, JSON, YAML — три колонки рядом; таблица ↔ список словарей.
- **Задачи:** (1) прочитать CSV (в виде строки через `io.StringIO`) и вернуть среднее по столбцу; (2) сгруппировать продажи по городу → JSON-строка (сравнение по `json.loads`, а не по тексту); (3) CSV с запятой внутри кавычек — проверка на «наивный `split`»; (4) преобразовать список словарей в CSV и обратно (round-trip); (5) вытащить значения из вложенного JSON по пути.
- **НЕ включаем:** `pickle`, XML, `toml` (кроме упоминания); запись YAML и установка PyYAML **[проверить, есть ли в Pyodide без сети]** — до подтверждения YAML только «читаем глазами»; `pandas.read_csv` — после «открытия» pandas.

#### 6.5 Дата и время **[было: «Дата и время — datetime и часовые пояса»]**
- **Цели:** создаёт и сравнивает `date/datetime/timedelta`; форматирует и разбирает `strftime/strptime/isoformat`; понимает UTC, aware и naive; считает разницы.
- **Идеи:** время — это число (секунды от эпохи) + правила показа; ISO 8601 как стандарт обмена; **naive vs aware**; часовые пояса — `zoneinfo` (нужна база tz) **[проверить в Pyodide]**; переход на летнее время — ловушка; хранить в UTC, показывать локально.
- **Источники:** Python Docs `datetime`, `zoneinfo`; Automate гл. 19 (Keeping Time); Think Python 3e (по месту) — **слабее покрыто**, поэтому опираемся на документацию.
- **Заблуждения:** «в сутках всегда 24 часа» (DST); `datetime.now()` даёт UTC; месяц — это 30 дней в `timedelta`; сравнение aware и naive вызывает ошибку **[из практики]**; `%m` vs `%M` в форматах **[из практики]**.
- **Визуализации:** временная ось с UTC и местным временем (смещение); календарь для `timedelta`.
- **Задачи:** (1) сколько дней до даты (тест с фиксированной «сегодняшней» датой — **без** `now()` в тестах); (2) день недели по дате; (3) разбор «12.05.2024 14:30» и вывод в ISO; (4) конвертация времени между поясами с **фиксированными смещениями** (`timezone(timedelta(hours=3))`), пока `zoneinfo` не проверен; (5) возраст в полных годах (граница: день рождения 29 февраля).
- **НЕ включаем:** `time.sleep/time.time` (по месту в профилировании prog3); календарь праздников; `dateutil`, `pendulum`, `arrow`.

- В начало добавлены микротемы, без которых задачи первых тем опираются на непройденное: «Первая программа» (запуск, print и input, как читать условие задачи и результат проверки, `assert` — только читать), «Читаем сообщение об ошибке», `import` вместе с модулем `math`, «Списки — первое знакомство» перед циклом `for`.
- Модель исполнения — явными контрольными точками: присваивание («сначала вычисляется правая часть, потом имя привязывается к значению»), вызов функции (параметр — новое локальное имя для того же объекта, «передача присваиванием»), псевдонимы и копирование. Один и тот же визуализатор «имена → объекты» во всех трёх местах.
- Добавлено: `None` и `is None` (функция без return), истинность значений, правило «дробные не сравнивают через ==» (`math.isclose`), распаковка, `enumerate` и `zip`, множества отдельной темой, ловушки «изменение списка во время обхода» и «`list.sort()` возвращает None», `UnboundLocalError`, неизменяемость строк.
- «Генераторы списков» → «Списковые включения»: слово «генераторы» занято в Программировании III (`yield`).
- «Функции как значения» перенесены прямо к сортировке с `key`; `compose` убран (замыкания — Программирование III).
- Отдельная тема «Чтение traceback и отладка»; «assert и свои проверки» включает проверку кода от ИИ-ассистента.
- Сокращено: часовые пояса (только наивное время, `timedelta`, ISO 8601), YAML (только упоминание, без разбора), `pathlib` (кратко, основное — `open`), регулярные выражения (минимум: search, findall, sub и когда regex не нужен).
- `db1.modify` теперь требует `prog1.modules`.

**Сквозные правила для тем и задач prog1:**
1. В каждой теме — хотя бы одна задача «трассировка вручную»: предсказать вывод или значения переменных без запуска.
2. В каждом разделе — хотя бы один настоящий traceback для разбора: какая строка моя, какая библиотечная, последняя строка — первой.
3. Задачи «ИИ написал решение — найдите ошибку или недостающий граничный случай» (off-by-one, изменяемое значение по умолчанию, `==` на дробных, затенённое встроенное имя). Правило «код, который вы не можете проследить вручную, — не ваш».
4. Задачи «напишите сами» — с `forbid` (без `max`, `sum`, `sorted`), библиотечная версия открывается после.
5. В конце каждого раздела — маленькая настоящая программа (касса, угадай число, записная книжка), а не только упражнения.
6. Данные в виде «список словарей» — основная форма с раздела «Коллекции»: группировка, сортировка, топ-N. Мост к SQL и pandas.
7. Не называть встроенными именами переменные (`sum = 0`) — предупреждение уже в теме об именах.
8. Мини-проект: заготовка структуры и шаблон требований; вход — неаккуратный CSV или журнал, выход — отчёт JSON или Markdown, свои `assert` для каждой функции, README на 10 строк. Варианты: учёт расходов, журнал сервера, анализатор текста, сводка по датасету.

**Что нужно от платформы (до написания задач):** визуализатор «имена → объекты» с пошаговым выполнением; задачи-«пазлы» (собрать программу из перемешанных строк, Parsons); файлы-фикстуры и задачи из нескольких файлов; проверка своих тестов ученика на наборе сломанных решений; запрет конструкций (`forbid`) — сделан.
