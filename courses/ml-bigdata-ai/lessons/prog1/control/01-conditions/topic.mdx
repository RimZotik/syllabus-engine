## Детский или взрослый

Кинотеатр продаёт детские билеты до 14 лет за 150 рублей, остальные — за 300. Программа читает возраст и называет цену. Напечатать нужно *одну* из двух строк вывода, и какую — заранее неизвестно.

```python
age = int(input())
if age < 14:
    print("Детский билет: 150 руб.")
else:
    print("Взрослый билет: 300 руб.")
print("Хорошего сеанса!")
```

```input
10
```

```
Детский билет: 150 руб.
Хорошего сеанса!
```

`if age < 14:` читается «если возраст меньше 14». Python вычисляет `age < 14`. Если это истинно, выполняются строки кода под `if`, а строки под `else` («иначе») пропускаются; если ложно — наоборот. Последний `print` не относится ни к одной ветви и выполняется всегда. Предскажите вывод для ввода `14`, потом проверьте себя на следующей странице.

<Theorem kind="definition" title="Условная инструкция"
  formal="Инструкция if используется для условного выполнения: она выбирает ровно одну из ветвей, вычисляя выражения по очереди, пока одно из них не окажется истинным; тогда выполняется эта ветвь. Если все выражения ложны, выполняется ветвь else, если она есть."
  source="Python Language Reference, 8.1 «The if statement» (пересказ)">

<Term id="if-statement">Условная инструкция</Term> `if` — развилка в программе: проверить условие и выполнить одну ветвь, пропустив остальные. Проверка происходит **один раз** — когда выполнение дошло до `if`. Потом условная инструкция ничего не повторяет и за данными не «следит».

</Theorem>

## Двоеточие и отступ

Какие строки кода относятся к ветви, Python понимает по двум признакам:

- строка кода с `if` или `else` заканчивается **двоеточием**;
- строки кода ветви сдвинуты вправо — с **отступом** в 4 пробела.

Строки кода с одинаковым отступом образуют блок — тело ветви. Блок кончается на первой строке кода, которая снова стоит у левого края. Без отступа будет ошибка `IndentationError: expected an indented block after 'if' statement on line 2` — «после `if` в строке 2 ожидался блок с отступом».

Ветвь `else` необязательна: если её нет и условие ложно, Python просто идёт к следующей строке кода после блока.

</Page>

## Шесть сравнений

Условие — это выражение, значит, у него есть значение. Какое?

```python
print(5 > 3)
print(2 + 2 == 5)
print(type(5 > 3))
```

```
True
False
<class 'bool'>
```

Сравнение даёт `True` (истина) или `False` (ложь) — <Term id="bool">логические значения</Term> типа `bool`. Пишутся с большой буквы и без кавычек: `"True"` в кавычках — уже строка.

<div className="table-scroll">

| Операция | Смысл | Пример | Результат |
|---|---|---|---|
| `==` | равно | `5 == 5.0` | `True` |
| `!=` | не равно | `3 != 3` | `False` |
| `<`, `>` | меньше, больше | `2 < 7` | `True` |
| `<=`, `>=` | меньше или равно, больше или равно | `14 >= 14` | `True` |

</div>

Теперь ответ к вопросу про билет: для ввода `14` условие `14 < 14` даёт `False`, поэтому программа назовёт взрослый билет. Ровно 14 — это уже не «меньше 14».

Результат сравнения можно привязать к имени: `is_adult = age >= 18`, а потом написать `if is_adult:`.

У каждого символа есть номер в таблице символов — кодировке, и строки сравниваются по этим номерам, буква за буквой — почти как по алфавиту: `"арбуз" < "банан"` даёт `True`. Но все большие буквы стоят раньше маленьких, поэтому `"Яблоко" < "арбуз"` — тоже `True`; перед сравнением слов приводите их к одному регистру. А буква ё в кодировке стоит после я: `"ёж" > "яблоко"` даёт `True`. Строка и число не равны никогда: `"5" == 5` даёт `False`. А дробные числа, как вы помните, через `==` не сравнивают.

<Callout kind="warning" title="Ловушка: = вместо ==">
`=` — присваивание, `==` — вопрос «равно ли?». Строка кода `if x = 5:` — синтаксическая ошибка: `SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?` Вам нужен `==`; редкая форма `:=` в курсе не понадобится.
</Callout>

## Цепочка проверок

90 баллов и выше — «отлично», от 75 — «хорошо», от 60 — «удовлетворительно», ниже — «не сдано». Четыре варианта, а `if` и `else` дают два. Для промежуточных ветвей есть `elif` — «иначе, если»:

```python
score = int(input())
if score >= 90:
    print("отлично")
elif score >= 75:
    print("хорошо")
elif score >= 60:
    print("удовлетворительно")
else:
    print("не сдано")
```

```input
80
```

```
хорошо
```

Python проверяет условия сверху вниз и останавливается на **первом** истинном. Для 80 условие `score >= 90` ложно, `score >= 75` истинно — печатается «хорошо», остальная цепочка пропускается, хотя `80 >= 60` тоже верно. Поэтому во второй ветви не нужно писать `score < 90`: раз до неё дошли, первое условие уже ложно.

Отсюда — **порядок условий важен**. Поставьте `score >= 60` первым, и для 95 баллов программа скажет «удовлетворительно». Для порогов с `>=` сначала проверяют самый высокий (90), потом ниже.

<Callout kind="warning" title="Ловушка: if вместо elif">
Три отдельных `if` проверяются каждый сам по себе. Для 95 баллов сработают все три, и выведутся «отлично», «хорошо» и «удовлетворительно». Отдельные `if` — для независимых вопросов, `elif` — для выбора одного варианта из нескольких.
</Callout>

Предскажите вывод, потом проверьте:

```python
x = 15
if x > 10:
    print("больше 10")
elif x > 5:
    print("больше 5")
if x > 0:
    print("положительное")
```

Здесь две независимые инструкции. В первой сработает только «больше 10», вторая проверяется отдельно — выведутся `больше 10` и `положительное`.

Внутри ветви может стоять другой `if`, со своим, ещё большим отступом. Но три-четыре уровня вложенности читать тяжело — обычно их заменяет цепочка `elif` или составное условие с `and` — о нём на следующей странице.

## Составные условия

Гулять — если теплее 20 градусов **и** нет дождя. Скидка — детям до 7 **или** людям от 65. Условия соединяют три логические операции:

- `a and b` — если `a` ложно, результат `a`, иначе `b`; в условии это значит «**оба** истинны»;
- `a or b` — если `a` истинно, результат `a`, иначе `b`; в условии — «истинно **хотя бы одно**»;
- `not a` — всегда `True` или `False`, наоборот: `not True` — это `False`.

```python
age = 25
has_ticket = True
print(age >= 18 and has_ticket)
print(age < 7 or age >= 65)
print(not has_ticket)
```

```
True
False
False
```

Обратите внимание: `and` и `or` возвращают одно из значений слева или справа от себя, не обязательно `True` или `False`. Пустая строка и ноль в условии считаются ложью (какие ещё значения ложны — на следующей странице), поэтому `"" or "аноним"` даёт `"аноним"`, а `0 and 5` даёт `0`. В условии `if` это неважно — там всё равно учитывается только истинность, — но объясняет ловушку в конце страницы.

Сначала выполняется `not`, потом `and`, потом `or` — как умножение раньше сложения. Сомневаетесь — ставьте скобки: `(a or b) and c`. Проверку «число между» пишут цепочкой, как в математике: `0 < x < 10` — то же, что `0 < x and x < 10`.

## Python не вычисляет лишнего

Средний чек — `total / count`, но если покупок не было, `count` равен 0:

```python
count = 0
total = 0
if count != 0 and total / count > 50:
    print("средний чек больше 50")
else:
    print("данных нет или чек маленький")
```

```
данных нет или чек маленький
```

Ошибки нет. `and` вычислил левую часть, получил `False` — и правую не трогал: ответ «оба истинны?» уже ясен. Так же `or` пропускает правую часть, если левая истинна. Это **ленивое вычисление**. Поменяйте части местами — и программа упадёт с `ZeroDivisionError`: деление случится раньше проверки.

<Callout kind="warning" title="Ловушка: x == 1 or 2">
«Если x равно 1 или 2» хочется записать как `if x == 1 or 2:` — но такая ветвь выполнится **при любом** `x`. Python читает `(x == 1) or 2`: если левая часть ложна, `or` отдаёт правую — число `2`, а оно считается истиной (почему — на следующей странице). Правильно: `x == 1 or x == 2`.
</Callout>

</Page>

## Что ещё можно поставить в условие

После `if` может стоять любое значение, не только сравнение:

```python
name = input().strip()
if name:
    print(f"Привет, {name}!")
else:
    print("Вы не ввели имя")
```

Если пользователь нажмёт Enter или введёт одни пробелы, после `strip()` останется пустая строка, и программа выведет `Вы не ввели имя`. Пустая строка в условии — ложь, непустая — истина. Это частный случай общего правила.

<Theorem kind="rule" title="Истинность значений"
  formal="Любое значение можно проверить на истинность в условии if или while и как операнд логических операций. Ложными считаются: константы None и False; ноль любого числового типа — 0, 0.0; пустые последовательности и коллекции — '', [] и другие. Все остальные значения истинны."
  source="Документация Python, Built-in Types, 4.1 «Truth Value Testing» (пересказ)">

<Term id="truthiness">Истинность</Term> — то, как значение ведёт себя в условии. Из значений, которые вы уже знаете, ложны: `False`, ноль (`0`, `0.0`), пустая строка `""`, пустой список `[]` и особое значение `None` — «ничего». То же правило потом распространится на любые пустые коллекции. Остальное — истина.

</Theorem>

Функция `bool` показывает, чем значение станет в условии:

```python
print(bool(0), bool(""), bool(None))
print(bool(-1), bool(" "), bool("0"), bool("False"))
```

```
False False False
True True True True
```

Вторая строка вывода — то, на чём ошибаются: пробел, `"0"` и даже `"False"` — непустые строки, значит, истинные. Python не читает смысл текста, он смотрит, пуст ли он. Со списками познакомимся позже в этом разделе, с `None` — в разделе «Функции».

Короткое `if name:` удобно, но пользуйтесь им осознанно. Если `count` может законно быть нулём, `if count:` спутает «ноль покупок» с «данных нет» — тогда пишут явно: `if count > 0:`.

<Callout kind="warning" title="Ловушка: if flag == True">
Если `is_member` указывает на `True` или `False`, пишут `if is_member:` и `if not is_member:`, а не `if is_member == True:`. Из той же серии: вместо четырёх строк кода «`if x > 0:` — `is_positive = True`, `else:` — `is_positive = False`» достаточно `is_positive = x > 0`. Сравнение уже даёт логическое значение.
</Callout>

Иногда ветви отличаются только значением для одного имени. Тогда есть условное выражение: `kind = "чётное" if n % 2 == 0 else "нечётное"`. Пользуйтесь им только для таких коротких выборов, в остальных случаях понятнее обычный `if`.
