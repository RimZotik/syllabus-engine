## Сколько лет копить

Вы положили 100 000 рублей на вклад под 10% годовых. Через сколько лет сумма станет не меньше 200 000? Можно считать вручную: прибавить 10%, проверить, ещё раз прибавить, ещё раз проверить… Но сколько раз — заранее неизвестно, а программа из строк кода, написанных подряд, выполняет каждую ровно один раз.

Нужна инструкция «повторяй, пока сумма меньше 200 000»:

```python
money = 100000
years = 0
while money < 200000:
    money = money + money // 10
    years += 1
print(years, money)
```

```
8 214358
```

`while` переводится как «пока». Строка кода `while money < 200000:` устроена как `if`: условие, двоеточие, а под ним блок строк с отступом — **тело цикла**. Разница в том, что после тела Python возвращается наверх и снова проверяет условие. Пока оно истинно, тело выполняется ещё раз. Как только условие оказалось ложным, Python переходит к первой строке кода после цикла — здесь это `print`.

Чтобы числа оставались целыми, проценты считаем через `//`: `money // 10` — десятая часть суммы без копеек.

<Theorem kind="definition" title="Цикл while"
  formal="Инструкция while используется для повторного выполнения, пока выражение истинно: она раз за разом проверяет выражение и, если оно истинно, выполняет тело; если выражение ложно (это может случиться и при первой же проверке), цикл завершается."
  source="Python Language Reference, 8.2 «The while statement» (пересказ, без ветви else)">

<Term id="loop">Цикл</Term> — инструкция, которая повторяет блок строк кода. Цикл `while` повторяет тело, **пока условие истинно**: проверка — тело — проверка — тело — … — проверка дала `False` — выход. Если условие ложно с самого начала, тело не выполнится ни разу.

</Theorem>

Пройдите программу по шагам. Перед каждым шагом предскажите, куда перейдёт выполнение после строки кода с `years += 1` и что станет с `money`:

<Trace>

```python
money = 100000
years = 0
while money < 200000:
    money = money + money // 10
    years += 1
print(years, money)
```

</Trace>

Обратите внимание на присваивание `money = money + money // 10`: правило то же, что и раньше. Сначала вычисляется правая часть по текущему значению `money`, потом имя привязывается к результату. Цикл только повторяет это присваивание раз за разом.

## Один проход тела — одна итерация

Одно выполнение тела цикла называют <Term id="iteration">итерацией</Term>. В программе про вклад было 8 итераций — по одной на год. Условие при этом проверялось 9 раз: восемь раз оно дало `True`, а на девятый — `False`, и цикл закончился.

Цикл удобно проследить таблицей: одна строка таблицы — одна проверка условия. Посчитаем, сколько цифр в числе 4071. Последнюю цифру отбрасывает целочисленное деление на 10, это вы знаете из темы о числах. Будем отбрасывать цифры, пока от числа что-то остаётся, и считать, сколько раз это удалось:

```python
n = 4071
digits = 0
while n > 0:
    n = n // 10
    digits += 1
print(digits)
```

<div className="table-scroll">

| Проверка | `n` | `digits` | `n > 0` | Что дальше |
|---|---|---|---|---|
| 1 | 4071 | 0 | `True` | тело: `n` станет 407, `digits` — 1 |
| 2 | 407 | 1 | `True` | тело: 40 и 2 |
| 3 | 40 | 2 | `True` | тело: 4 и 3 |
| 4 | 4 | 3 | `True` | тело: 0 и 4 |
| 5 | 0 | 4 | `False` | выход, печать `4` |

</div>

<Mark>Ведите такую таблицу каждый раз, когда не уверены, что делает цикл</Mark>: значения имён в момент проверки, результат проверки, что изменит тело. Это та же трассировка, что и в разделе «Основы языка», только строки кода в теле повторяются.

Предскажите по такой же таблице, что выведет программа для `n = 0`, и подумайте, верен ли этот ответ — ведь в записи числа 0 одна цифра. Ответ — в конце страницы.

## Условие проверяется только наверху

Частое заблуждение — будто `while` следит за условием всё время и выходит, как только оно нарушилось. На деле условие проверяется **один раз за итерацию** — перед телом. Внутри тела оно может временно стать ложным, и цикл этого не заметит:

```python
x = 0
while x < 3:
    x = x + 5
    print("внутри", x)
    x = x - 4
print("после", x)
```

```
внутри 5
внутри 6
внутри 7
после 3
```

На каждой итерации `x` ненадолго становится больше 3, но печать всё равно происходит: тело выполняется до конца, а решение «продолжать или нет» принимается только при следующей проверке.

## Цикл, который не заканчивается

Чтобы цикл когда-нибудь закончился, тело должно менять что-то, от чего зависит условие. Забудьте одну строку кода — и условие будет истинным вечно:

```python
i = 1
while i <= 5:
    print(i)
```

`i` всё время указывает на 1, проверка `1 <= 5` всегда даёт `True`, и программа печатает единицы без конца. Это **бесконечный цикл**. На платформе запуск принудительно останавливается через 5 секунд, а в настоящем терминале программу прерывают клавишами Ctrl+C. Попробуйте сами в любой песочнице платформы: запустите `while True:` с `print("ещё")` в теле и без `break` — и посмотрите, как запуск остановится. Если программа «зависла» и ничего не выводит, первым делом проверьте циклы: меняется ли в теле то, от чего зависит условие, и может ли условие стать ложным.

## Ошибка на единицу

Вторая частая ошибка — промах на границе. Нужно вывести числа от 1 до 5:

```python
i = 1
while i < 5:
    print(i)
    i += 1
```

```
1
2
3
4
```

Пятёрки нет: когда `i` стал 5, проверка `5 < 5` дала `False`. Нужно `i <= 5`. Такие ошибки называют <Term id="off-by-one">ошибками на единицу</Term> (off-by-one). Защита одна — проверить вручную **крайние значения**: что происходит на первой итерации, на последней и сразу после неё.

## Неизвестно, сколько будет данных

Метеостанция присылает температуру за каждый день, а в конце — слово `стоп`. Сколько было дней с морозом? Количество чисел заранее неизвестно — это работа для `while`:

```python
frosty = 0
line = input()
while line != "стоп":
    if int(line) < 0:
        frosty += 1
    line = input()
print("Морозных дней:", frosty)
```

```input
-3
2
-10
0
стоп
```

```
Морозных дней: 2
```

Заметьте: `input()` встречается дважды. Первый раз — до цикла, чтобы условию было что проверять. Второй — в конце тела, чтобы перед следующей проверкой в `line` уже была новая строка ввода. И ещё: слово `стоп` сравнивается со строкой, пока она ещё текст, и только потом строка превращается в число. Если бы мы сразу написали `int(input())`, на слове `стоп` программа упала бы с `ValueError`.

## while True и break

Ту же программу часто пишут иначе — без повторного `input()`. Прежде чем проходить её по шагам, предскажите: что она выведет, если первой строкой ввода будет сразу `стоп`?

<Trace>

```python
frosty = 0
while True:
    line = input()
    if line == "стоп":
        break
    if int(line) < 0:
        frosty += 1
print("Морозных дней:", frosty)
```

```input
-3
2
-10
0
стоп
```

</Trace>

`while True` — цикл, условие которого всегда истинно: сам по себе он бесконечный. Выход из него — инструкция `break`, «прервать»: она немедленно завершает цикл, и выполнение продолжается с первой строки кода после него. Остаток тела на этой итерации не выполняется. Такую форму удобно читать: «повторяй: прочитай строку; если это стоп — выходи; иначе обработай».

Теперь ответ на вопрос перед трассировкой: при вводе сразу `стоп` тело прервётся на первой же итерации, а печать после цикла выполнится — `Морозных дней: 0`.

</Page>

## Выйти раньше

`break` работает и в цикле с обычным условием. Вход по паролю, не больше трёх попыток:

```python
attempts = 0
while attempts < 3:
    password = input()
    attempts += 1
    if password == "qwerty":
        print("Вход выполнен")
        break
    print("Неверный пароль")
print("Попыток:", attempts)
```

```input
123
qwerty
```

```
Неверный пароль
Вход выполнен
Попыток: 2
```

Цикл закончится одним из двух способов: условие `attempts < 3` станет ложным или сработает `break`. Если пароль так и не угадали, хорошо бы после цикла написать «доступ заблокирован». Но как после цикла узнать, каким способом он закончился? Для этого есть приём «флаг» — он будет в последней теме раздела.

## Пропустить итерацию

Инструкция `continue`, «продолжить», заканчивает только **текущую итерацию**: остаток тела пропускается, и Python сразу идёт на проверку условия. Сложим цены из чека, пропуская явно ошибочные отрицательные. Конец чека отмечен словом `итого`:

```python
total = 0
while True:
    line = input()
    if line == "итого":
        break
    price = int(line)
    if price < 0:
        print("Пропускаю ошибочную цену", price)
        continue
    total += price
print("Итого:", total)
```

```input
100
-5
250
итого
```

```
Пропускаю ошибочную цену -5
Итого: 350
```

Для `-5` сработал `continue`: строка кода `total += price` на этой итерации не выполнилась.

<Callout kind="warning" title="Ловушка: что именно прерывают break и continue">
`break` завершает только **тот цикл, внутри которого стоит**, а не всю программу: строки кода после цикла выполняются. `continue` пропускает только остаток **тела**, а не всё, что идёт ниже в программе. Когда циклы окажутся вложены друг в друга (в теме о цикле `for`), `break` во внутреннем цикле выйдет только из внутреннего.
</Callout>
