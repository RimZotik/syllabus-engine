## Пять вопросов к одному списку

Маленькая кофейня записывает выручку за каждый день недели:

```python
sales = [1200, 0, 850, 2300, 1500, 0, 900]
```

Хозяйка хочет знать: сколько заработано за неделю? Сколько было дней без продаж? Какой день лучший? Был ли хоть один день без продаж? Все ли дни дали больше 500 рублей? Вопросы разные, а ответы устроены одинаково: имя, заведённое до цикла; цикл `for` по списку; `if` в теле; ответ после цикла. Такие повторяющиеся решения называют шаблонами. Зная их, новую задачу собирают из готовых кирпичиков.

## Сначала план — потом код

Прежде чем писать цикл, запишите план обычными словами в комментариях. Потом под каждым пунктом допишите код:

```python
sales = [1200, 0, 850, 2300, 1500, 0, 900]
# План:
# 1. Завести итог — пока ноль
# 2. Для каждого дня прибавить выручку к итогу
# 3. После цикла напечатать итог
total = 0
for s in sales:
    total += s
print("За неделю:", total)
```

```
За неделю: 6750
```

План заставляет заранее решить, что должно быть *до* цикла, *в* цикле и *после* него, и остаётся подсказкой читателю. Тот же приём помогает проверять код от ИИ-ассистента: напишите план сами и сверьте, делает ли код именно это.

</Page>

## Итог, который растёт

Имя `total` в программе выше работает особым образом: до цикла оно указывает на 0, а на каждой итерации к нему прибавляется очередной элемент. Пройдите по шагам и следите, как меняется `total`:

<Trace>

```python
sales = [1200, 0, 850, 2300]
total = 0
for s in sales:
    total += s
print(total)
```

</Trace>

<Theorem kind="definition" title="Накопитель"
  formal="Накопитель (accumulator) — переменная, которая используется в цикле, чтобы складывать или накапливать результат."
  source="A. Downey, «Think Python», 3rd ed., гл. 10, §10.7 и глоссарий (accumulator)">

<Term id="accumulator">Накопитель</Term> — имя для промежуточного итога.

</Theorem>

У накопителя три обязательных места: **начальное значение до цикла**, **обновление в теле**, **ответ после цикла**. В любой момент накопитель хранит ответ для той части списка, которую цикл уже просмотрел: после двух итераций в `total` — сумма первых двух дней.

Начальное значение — ответ для пустого списка: сумма ничего — 0. Для произведения начинают с 1: умножение на 0 всё обнулило бы.

**Счётчик** — частный случай накопителя: прибавляется не элемент, а единица, и только когда выполнено условие.

```python
sales = [1200, 0, 850, 2300, 1500, 0, 900]
zero_days = 0
for s in sales:
    if s == 0:
        zero_days += 1
print("Дней без продаж:", zero_days)
```

```
Дней без продаж: 2
```

Накопителем может быть и список: «пустой список, цикл, `append`» из прошлой темы — тот же шаблон.

Среднее — сумма, делённая на количество, но для пустого списка это деление на ноль. Пустой ввод — обычный крайний случай, его проверяют явно: `if len(sales) > 0:` — среднее, иначе «Данных нет».

<Callout kind="warning" title="Ловушка: накопитель внутри цикла и имя sum">
Если строка кода `total = 0` окажется в теле цикла, итог обнуляется на каждой итерации и в конце равен последнему элементу. Начальное значение — **до** цикла. И не называйте накопитель `sum`, а лучший элемент — `max`: эти имена встроенные (вспомните ловушку из темы об именах), и в конце этой темы они нам понадобятся.
</Callout>

## Максимум своими руками

Какой день был самым тёплым? Идея — та же, что с накопителем: держим имя `best` для лучшего значения среди уже просмотренных и обновляем его, когда встречаем значение лучше.

<Trace>

```python
temps = [-5, -2, -8, -1]
best = temps[0]
for t in temps:
    if t > best:
        best = t
print(best)
```

</Trace>

Начальное значение — **первый элемент списка**, а не ноль. С `best = 0` программа для этих морозных дней ответила бы `0`: ни одна температура не больше нуля, и `best` не обновился бы ни разу. Ответ выглядит правдоподобно, ошибку легко не заметить. На первой итерации первый элемент сравнивается сам с собой — это лишнее сравнение, но вреда от него нет.

Зато в пустом списке первого элемента нет, и `temps[0]` даст `IndexError`. Поэтому сначала проверяют, что список не пуст:

```python
if len(temps) == 0:
    print("Данных нет")
else:
    best = temps[0]
    for t in temps:
        if t > best:
            best = t
    print(best)
```

Предскажите, что выведет этот код для `temps = []` и для `temps = [-5, -2, -8, -1]`, потом проверьте, запустив его в любой песочнице.

## Где лучший

Часто нужен не сам максимум, а его место — номер лучшего дня. Тогда помнят индекс:

```python
sales = [1200, 0, 850, 2300, 1500, 0, 900]
best_day = 0
for i in range(1, len(sales)):
    if sales[i] > sales[best_day]:
        best_day = i
print("Лучший день:", best_day + 1, "выручка", sales[best_day])
```

```
Лучший день: 4 выручка 2300
```

Минимум ищут так же, с `<`, а самое длинное слово — это максимум по `len(w)`.

## Есть ли хоть один

Был ли день без продаж? Отвечать «да» можно, как только нашёлся первый такой день, — дальше смотреть незачем.

<Theorem kind="definition" title="Поиск"
  formal="Поиск — шаблон вычисления: перебор последовательности, который останавливается, когда найдено искомое."
  source="A. Downey, «Think Python», 3rd ed., §7.6 «Search» и глоссарий (linear search)">

Поиск — цикл, который останавливается на первой находке. Ответ «найдено» становится ясен сразу, а ответ «не найдено» — только когда просмотрен весь список.

</Theorem>

Как после цикла узнать, нашли или нет? Заводят <Term id="flag">флаг</Term> — имя с логическим значением, которое до цикла указывает на `False` («пока не нашли») и переключается на `True` при находке:

```python
sales = [1200, 0, 850, 2300]
has_zero = False
for s in sales:
    if s == 0:
        has_zero = True
        break
if has_zero:
    print("Был день без продаж")
else:
    print("Продажи были каждый день")
```

```
Был день без продаж
```

`break` здесь — ранний выход: второй элемент оказался нулём, и смотреть 850 и 2300 уже не нужно. Флаг можно проверять как угодно — но по правилу из темы об условиях: `if has_zero:`, а не `if has_zero == True:`.

<Callout kind="warning" title="Ловушка: флаг сбрасывается в else">
Хочется написать «если ноль — `True`, иначе — `False`» прямо в цикле:

```python
for s in sales:
    if s == 0:
        has_zero = True
    else:
        has_zero = False
```

Для `[1200, 0, 850, 2300]` получится `False`: ноль нашли, но следующий же день снова сбросил флаг. В итоге флаг говорит только о **последнем** элементе. Флаг переключают в одну сторону: начальное значение — до цикла, в цикле — только при находке.
</Callout>

## Все ли

Все ли дни дали больше 500 рублей? Это поиск наоборот: ищем **контрпример** — день, когда выручка была 500 или меньше. Флаг начинается с `True` («пока нарушений не видели») и падает в `False` на первом нарушении:

```python
sales = [1200, 300, 850, 2300]
all_ok = True
for s in sales:
    if s <= 500:
        all_ok = False
        break
print(all_ok)
```

```
False
```

Граничное значение решает знак: «больше 500» значит, что день с выручкой ровно 500 — нарушение, поэтому в проверке `<=`, а не `<`. Для пустого списка ответ — `True`: нарушений не нашлось. Так принято в математике и во встроенных функциях Python.

## Флаг в условии while

Помните вход по паролю из темы о `while`? Мы не смогли после цикла написать «доступ заблокирован», потому что не знали, чем закончился цикл. С флагом это просто, и даже `break` не нужен — флаг стоит прямо в условии:

```python
attempts = 0
logged_in = False
while attempts < 3 and not logged_in:
    password = input()
    attempts += 1
    if password == "qwerty":
        logged_in = True
if logged_in:
    print("Вход выполнен")
else:
    print("Доступ заблокирован")
```

```input
1
2
3
```

```
Доступ заблокирован
```

Цикл идёт, пока попытки не кончились **и** вход ещё не выполнен. После цикла флаг говорит, каким из двух способов он закончился.

</Page>

## То же самое одной строкой

Теперь, когда вы написали всё сами, можно открыть готовые функции. Они делают то же, что ваши циклы:

```python
sales = [1200, 0, 850, 2300, 1500, 0, 900]
print(sum(sales), max(sales), min(sales), len(sales))
print(any([0, 0, 3]), any([0, 0, 0]))
```

```
6750 2300 0 7
True False
```

- `sum` — накопитель с начальным значением 0: `sum([])` даёт `0`. С дробными числами встроенная `sum` в Python 3.12 считает точнее простого цикла: `sum([0.1] * 10)` даёт `1.0` (умножение списка на число повторяет его элементы — здесь получится десять чисел `0.1`), а цикл с `total += x` — `0.9999999999999999`.
- `max` и `min` — «лучший из просмотренных». Пустой список они не принимают: `max([])` даёт `ValueError: max() iterable argument is empty` — та же проблема, что и `temps[0]` в вашей версии.
- `any` — поиск с флагом: есть ли среди элементов хоть один истинный (по правилу истинности). Его пара — `all`, «все ли истинны»: `all([1, 2, 0])` даёт `False` — ноль ложен.

Чтобы спросить `any` о своём условии, например «есть ли день с нулевой выручкой», используют короткую запись `any(s == 0 for s in sales)`. Как она устроена, разберём в теме «Списковые включения» раздела «Коллекции».

<Mark>Встроенная функция — не магия, а цикл, который за вас уже написали.</Mark> Зная, что внутри, вы знаете и её крайние случаи. В задачах с пометкой «напишите сами» встроенные функции запрещены — там проверяется, что вы собираете шаблон своими руками. В остальных пользуйтесь ими свободно.

<Callout kind="warning" title="Ловушка: sum = 0 ломает sum()">
После `sum = 0` имя `sum` указывает на число, и вызов `sum([1, 2])` дальше в программе упадёт с `TypeError: 'int' object is not callable`. Теперь видно, зачем называть накопитель `total`.
</Callout>
