## Три вызова — три пары

Журнал оценок: функция `average` считает средний балл, `report` печатает его для каждого ученика; у Бориса оценок нет. Предскажите, в какой строке программа упадёт и какие функции в этот момент ещё не закончили работу. Потом пройдите по шагам, следя за блоками справа:

<Trace>

```python
def average(marks):
    return sum(marks) / len(marks)

def report(journal):
    for name, marks in journal.items():
        print(name, average(marks))

journal = {"Аня": [5, 4, 3], "Борис": []}
report(journal)
```

</Trace>

В момент ошибки справа три блока: «Программа», `report()` и `average()`. Если сохранить программу в файл `marks.py` и запустить на компьютере, Python выведет:

```
Аня 4.0
Traceback (most recent call last):
  File "C:\work\marks.py", line 9, in <module>
    report(journal)
  File "C:\work\marks.py", line 6, in report
    print(name, average(marks))
                ^^^^^^^^^^^^^^
  File "C:\work\marks.py", line 2, in average
    return sum(marks) / len(marks)
           ~~~~~~~~~~~^~~~~~~~~~~~
ZeroDivisionError: division by zero
```

Над последней строкой три пары «файл — номер строки» — как три блока справа. Каждая пара — вызов (или основная программа), который не успел закончиться. Читаем снизу вверх:

1. **Последняя строка.** `ZeroDivisionError` — деление на ноль.
2. **Нижняя пара, `line 2, in average`.** Здесь программа упала: длина списка оказалась нулём. Значки `~` и `^` подчёркивают выражение, где это случилось, — деление.
3. **Пара выше, `line 6, in report`.** Отсюда вызвали `average` — для ученика с пустым списком оценок.
4. **Верхняя пара, `line 9, in <module>`.** Отсюда основная программа вызвала `report`.

Сверху вниз — порядок вызовов, снизу вверх — путь исключения.

<Theorem kind="definition" title="Стек вызовов"
  formal="Каждый вызов функции получает свою запись — набор её локальных имён. Записи образуют стек: запись вызванной функции добавляется к записи вызвавшей и убирается, когда вызов завершается. Traceback перечисляет записи, бывшие в стеке в момент исключения."
  source="A. Downey, «Think Python», 3-е изд., гл. 3 «Functions», разделы «Stack diagrams» и «Tracebacks» (пересказ)">

<Term id="call-stack">Стек вызовов</Term> — вызовы, которые начались, но ещё не закончились, в порядке «кто кого вызвал». Запись о вызове — это его имена; в пошаговом выполнении она видна как блок справа. Английское stack — «стопка»: последний начатый вызов заканчивается первым. Только рисуют эту стопку вверх дном: в traceback и в пошаговом выполнении последний вызов — внизу.

</Theorem>

Теперь понятно название из сообщения об ошибке: traceback — это «трассировка стека», его пары и есть стек вызовов в момент исключения.

</Page>

## Чужая пара и своя

Заменим `average` готовой функцией: вместе с Python поставляется модуль `statistics`, в нём `mean` — среднее:

```python
import statistics

def report(journal):
    for name, marks in journal.items():
        print(name, statistics.mean(marks))

journal = {"Аня": [5, 4, 3], "Борис": []}
report(journal)
```

```
Аня 4
Traceback (most recent call last):
  File "C:\work\marks.py", line 8, in <module>
    report(journal)
  File "C:\work\marks.py", line 5, in report
    print(name, statistics.mean(marks))
                ^^^^^^^^^^^^^^^^^^^^^^
  File "C:\Python312\Lib\statistics.py", line 486, in mean
    raise StatisticsError('mean requires at least one data point')
statistics.StatisticsError: mean requires at least one data point
```

Нижняя пара указывает на `statistics.py` — код библиотеки, а не ваш: `mean` сама выбросила исключение через `raise`. Тип записан вместе с модулем, а текст значит «для среднего нужно хотя бы одно значение». Библиотека не стала считать, потому что вы передали ей пустой список.

## Пара в traceback — где заметили

Считаем сумму по чеку. Каждая позиция — текст вида `"хлеб;45"`, функция `parse_price` достаёт из него цену:

```python
def parse_price(line):
    name, price = line.split(";")
    int(price)

total = 0
for line in ["хлеб;45", "сыр;320"]:
    total += parse_price(line)
print(total)
```

```
Traceback (most recent call last):
  File "C:\work\receipt.py", line 7, in <module>
    total += parse_price(line)
TypeError: unsupported operand type(s) for +=: 'int' and 'NoneType'
```

К целому числу нельзя прибавить `None`. Строка 7 сама по себе верна; вопрос — *почему* `parse_price` вернула `None`? В строке 3 цену посчитали, но не вернули: нет `return`.

Пары `in parse_price` в traceback нет: к моменту ошибки функция уже закончила работу и ушла из стека вызовов.

<Callout kind="warning" title="Ловушка: «ошибка в указанной строке»">
Строка кода, на которую указывает traceback, — место, где ошибку *заметили*, а допустить её могли раньше: в другой функции, в данных. Если строка верна, спросите: откуда пришло неправильное значение — `None`, пустой список, лишний пробел?
</Callout>

## Программа не падает, но врёт

Бывает хуже: программа отработала, а ответ неверный, и подсказки нет. Ошибку в программе называют <Term id="bug">баг</Term>, а поиск и исправление — <Term id="debugging">отладка</Term>. Менять код наугад — самый медленный способ. Быстрее действовать как в науке: выдвинуть предположение и проверить его опытом.

<Theorem kind="rule" title="Цикл отладки"
  formal="Отладка похожа на экспериментальную науку: когда есть предположение о том, что идёт не так, вы меняете программу и проверяете его. Если предположение верно, результат изменения можно предсказать заранее; если предсказание не сбылось — нужно новое предположение."
  source="A. Downey, «Think Python», 1-е изд., 1.3.4 «Experimental debugging» (пересказ); шаги ниже — план курса">

1. **Воспроизвести.** Найти вход, на котором ошибка случается каждый раз, — лучше самый маленький.
2. **Прочитать** сообщение, вывод, неверное число.
3. **Предположить** одну конкретную причину: «пропускается первый элемент».
4. **Проверить** предположение: `print` промежуточного значения, `assert`, прогон вручную на маленьком входе, пошаговое выполнение.
5. **Исправить** и снова запустить программу и проверки, если они есть.

</Theorem>

## Разбор: тёплые дни

Программа считает дни недели с температурой выше нуля:

```python
def parse(text):
    return [int(t) for t in text.split(";")]

def warm_days(temps):
    count = 0
    for i in range(1, len(temps)):
        if temps[i] > 0:
            count += 1
    return count

week = "4;-2;0;7;3;-1;5"
print(warm_days(parse(week)))
```

```
3
```

Тёплых дней четыре — с температурой 4, 7, 3 и 5. **Воспроизвели**: ответ неверный каждый раз.

**Делим пополам.** Данные проходят два шага: `parse`, потом `warm_days`. Посмотрим, что приходит между ними, — добавим `print(parse(week))`:

```
[4, -2, 0, 7, 3, -1, 5]
```

Список правильный — значит, ищем в `warm_days`. В длинной программе так и ищут: `print` посередине, и дальше — в той половине, где данные уже неверны.

**Уменьшаем вход.** Ответ меньше ровно на один: один тёплый день теряется. Какой? Возьмём список из одного тёплого дня. Напомним: <Term id="assert">`assert`</Term> молчит, если условие истинно, а если ложно — выбрасывает `AssertionError` с текстом после запятой, например f-строкой:

```python
assert warm_days([4]) == 1, f"warm_days([4]) вернула {warm_days([4])}, а нужно 1"
```

```
AssertionError: warm_days([4]) вернула 0, а нужно 1
```

**Предполагаем и проверяем.** Единственный день не посчитан. Он здесь и первый, и последний — какой из них теряется? `warm_days([4, -1])` тоже возвращает 0, а `warm_days([-1, 4])` — 1. Предположение: «первый элемент не проверяется». Смотрим, откуда берутся индексы: `range(1, len(temps))` начинается с 1 и пропускает индекс 0 — ошибка на единицу. Надёжнее обойтись без индексов: `for t in temps:` и `if t > 0:`. Теперь программа печатает 4, а `assert` молчит. Проверку оставьте под функцией: если ошибка вернётся, эта проверка сразу о ней скажет.

<Page title="Утёнок, ассистент и отладчик" minutes={5}>

**Метод утёнка.** Объясните код вслух — хоть резиновому утёнку на столе (отсюда и название) — строку за строкой: на какое значение указывает каждое имя и почему. Вслух нельзя пропустить строку, которая «и так понятна».

**ИИ-ассистент.** Спрашивайте его о *причине*, а исправление, которое не можете проследить вручную, проверьте на том же маленьком входе.

**Отладчик** останавливает программу на нужной строке и показывает все имена, как пошаговое выполнение. С ним вы поработаете в теме «Редактор кода и отладчик» дисциплины «Компьютер и командная строка». А `print`, `assert` и деление пополам работают везде.
