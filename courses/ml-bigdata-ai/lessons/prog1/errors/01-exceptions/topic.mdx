## Программа, которая сдаётся

Программа считает чаевые: читает сумму счёта и печатает десятую часть. Гость вводит сумму словами:

```python
bill = int(input("Сумма счёта: "))
print("Чаевые 10%:", bill / 10)
```

Программа останавливается с traceback, последняя строка которого — `ValueError: invalid literal for int() with base 10: 'тысяча'`. Гость видит одно: программа сломалась. Хочется сказать «нужно число» и работать дальше.

Проверять текст заранее трудно (`int` примет `" 200 "`, но не `"1 500"`). Проще *попробовать*, а если не вышло — сделать другое.

## try и except

Вот та же программа с запасным планом. Предскажите вывод для ввода `тысяча` и пройдите по шагам:

<Trace>

```python
text = input("Сумма счёта: ")
try:
    bill = int(text)
    print("Чаевые 10%:", bill / 10)
except ValueError:
    print("Нужно целое число, например 1500")
print("Спасибо!")
```

```input
тысяча
```

</Trace>

В строке 3 возникает исключение `ValueError`. Строка 4 не выполняется: Python переходит к блоку `except ValueError`, а тот печатает подсказку; потом программа идёт к «Спасибо!». С вводом `1500` блок `except` пропускается.

<Theorem kind="definition" title="Обработка исключений: try и except"
  formal="Сначала выполняется блок try. Если в нём возникло исключение, остаток блока try пропускается; если тип исключения совпадает с указанным после except, выполняется блок except. Иначе исключение передаётся дальше — во внешний try или туда, откуда вызвали функцию; не нашлось подходящего except — программа останавливается."
  source="Python Tutorial, 8.3 «Handling Exceptions» (пересказ)">

<Term id="exception-handling">Обработка исключений</Term> — запасной план на случай ошибки. В блок `try` («попробуй») пишут код, где может возникнуть исключение. В блок `except ТипИсключения` («а если случилось») — что делать, если возникло исключение именно этого типа. Говорят «перехватить исключение» или «поймать».

</Theorem>

Python не возвращается в `try`: строки после упавшей так и не выполнятся. А `except ValueError` ловит `ValueError` и его разновидности, исключения других типов пропускает дальше.

</Page>

## Ловушка: ловить всё подряд

После `except` можно указать любой тип: `KeyError`, `ZeroDivisionError`… А можно не указывать тип вовсе — тогда `except` ловит все исключения подряд. Кажется, так надёжнее:

```python
text = input()
try:
    price = int(text)
    total = prise * 2
except:
    print("Введите число")
```

Для ввода `100` программа отвечает:

```
Введите число
```

Ввели число, а просят число. Причина — опечатка `prise`: без `try` вы бы сразу увидели `NameError`, а на компьютере ещё и подсказку `Did you mean: 'price'?`. А `except` без типа перехватил это исключение и выдал опечатку за неверный ввод.

`except` без типа ловит даже Ctrl+C, которым останавливают зависшую программу: цикл «спрашивать, пока не введут число» с таким `except` не прервать. А `Exception` — самый общий тип обычных исключений: `except Exception:` ловит почти всё, кроме Ctrl+C и немногих похожих случаев, и тоже прячет ошибки в коде.

<Callout kind="warning" title="Ловушка: широкий except и большой try">
После `except` — тип того исключения, которое ожидаете и знаете, как обработать; в `try` — только строки, где оно может возникнуть. Остальные ошибки пусть останавливают программу: так вы узнаете о них сразу.
</Callout>

## Спрашивать, пока не получится

После неверного ввода обычно спрашивают снова. Соединим `while True` с `break` и `try`; предскажите, сколько раз выведется подсказка:

```python

```

```input
5
```

`int("пять")` и `int("5.5")` выбрасывают исключение раньше `break` — подсказка печатается дважды.

## else и finally

У `try` есть ещё два необязательных блока. `else:` пишут после `except` с тем же отступом; он выполняется, если в `try` исключения не было. В нём пишут работу с удачным результатом. Почему не в сам `try`? Если эта работа сама выбросит `ValueError` по другой причине, внутри `try` его приняли бы за неверный ввод, а из `else` оно остановит программу с честным сообщением.

`finally` выполняется при *любом* выходе из `try`: обычном, через `return`, после пойманного исключения и даже если исключение никто не поймал. Этим он отличается от кода, поставленного после всей конструкции. Середину последнего сообщения мы опустили:

```python
def to_price(text):
    try:
        return int(text)
    except ValueError:
        print("не число:", text)
    finally:
        print("проверили:", text)

print(to_price("45"))
print(to_price("сорок"))
print(to_price(None))
```

```
проверили: 45
45
не число: сорок
проверили: сорок
None
проверили: None
Traceback (most recent call last):
  ...
TypeError: int() argument must be a string, a bytes-like object or a real number, not 'NoneType'
```

`finally` выполнился и перед `return` для `"45"`, и после пойманного исключения для `"сорок"` (функция вернула `None`), и для `None`, хотя `TypeError` пошёл дальше. Код после всей конструкции при `"45"` и `None` не выполнился бы. `finally` нужен для того, что должно случиться при любом исходе: увеличить счётчик попыток, напечатать «готово». Для файлов в разделе «Текст и файлы» будет своя короткая запись — `with`.

## Не только «эта функция»

Если в функции нет подходящего `except`, она прерывается, а исключение передаётся туда, откуда её вызвали. Там его снова пробуют поймать — и так дальше вверх.

```python
def to_number(text):
    return int(text)

def total(lines):
    s = 0
    for line in lines:
        s += to_number(line)
    return s

try:
    print(total(["100", "сто", "50"]))
except ValueError as e:
    print("Не посчитать:", e)
```

```
Не посчитать: invalid literal for int() with base 10: 'сто'
```

`except ValueError as e` привязывает имя `e` к пойманному исключению — это тоже значение.

`int("сто")` выбрасывает исключение в `to_number`, там `try` нет — она прерывается. В `total` тоже нет — прерывается и она, до `"50"` цикл не доходит. Ловит исключение основная программа; без её `try` остановилась бы *вся* программа.

Этот путь вверх и виден в traceback: по паре «файл — номер строки» на основную программу и на каждый прерванный вызов. Читать его научимся в теме «Чтение traceback и отладка».

Ловить стоит там, где *знают, что делать*: пропустить значение или остановить отчёт — решает не `to_number`, а тот, кто её вызвал.

## Когда ошибку замечаете вы

Функция `parse_age` переводит текст в возраст. `int("200")` сработает, но людям не бывает 200 лет. Что должна сделать функция?

- **Напечатать** «неверный возраст» и вернуть `None`? Ошибка всплывёт позже: `None + 1` — `TypeError` где-то в отчёте.
- **Вернуть** особое число, например `-1`? Его забудут проверить, и оно попадёт в средний возраст.
- **Выбросить исключение.** Его либо поймают, либо программа остановится с понятным сообщением.

<Theorem kind="rule" title="Инструкция raise"
  formal="Инструкция raise позволяет программисту принудительно выбросить указанное исключение. После raise пишут исключение, которое нужно выбросить."
  source="Python Tutorial, 8.4 «Raising Exceptions» (пересказ)">

<Term id="raise">`raise`</Term> — «выброси»: `raise ValueError("текст")`. Запись `ValueError("текст")` создаёт значение-исключение с этим текстом, а `raise` его выбрасывает. В документации встречаются «возбудить» и «вызвать исключение» — это то же, что «выбросить», а не вызов функции.

</Theorem>

```python
def parse_age(text):
    age = int(text)
    if age < 0 or age > 150:
        raise ValueError(f"возраст должен быть от 0 до 150, а не {age}")
    return age

for text in ["35", "двадцать", "200"]:
    try:
        print(parse_age(text))
    except ValueError as e:
        print("Ошибка:", e)
```

```
35
Ошибка: invalid literal for int() with base 10: 'двадцать'
Ошибка: возраст должен быть от 0 до 150, а не 200
```

Оба исключения ловит один `except ValueError`: первое выбросил `int`, второе — наша функция.

`raise` можно написать и внутри `except` — так чужое исключение с непонятным текстом заменяют своим, понятным:

```python
try:
    price = int(text)
except ValueError:
    raise ValueError(f"цена должна быть целым числом рублей, а не «{text}»")
```

Особое значение вместо исключения уместно, когда отсутствие результата — обычное дело. Так устроен `get` у словаря: нет ключа — вернёт значение по умолчанию. А когда пришло то, чего быть не должно, как `int("abc")` или возраст 200, — исключение.

## Тип, текст и описание исключения

- **Тип** — из знакомых: `ValueError` — значение нужного типа, но неподходящее; `TypeError` — значение не того типа. Свои классы исключений появятся в разделе «Классы и объекты» дисциплины «Объектно-ориентированное программирование».
- **Текст** — что ожидалось и что пришло: его увидят в последней строке traceback. Просто «ошибка» не поможет никому.
- **Строка документации.** Исключение — часть того, что функция обещает. Упомяните его в строке документации: «возраст вне 0..150 — ValueError». Проверять, что оно выбрасывается, научимся в теме «assert и свои проверки».
