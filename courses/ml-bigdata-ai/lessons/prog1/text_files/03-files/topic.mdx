## Файл — уже не строка в коде

До сих пор данные были прямо в программе или приходили через `input()`. В работе они лежат в файлах. Рядом с программой — файл `marks.txt` с оценками. Предскажите, что напечатает второй цикл, и пройдите по шагам:

<Trace files={{"marks.txt": "Аня 5\nБорис 3\n\nВера 4\n"}}>

```python
with open("marks.txt", encoding="utf-8") as f:
    text = f.read()
print(len(text), text.count("\n"))

with open("marks.txt", encoding="utf-8") as f:
    for line in f:
        print(line)
```

</Trace>

`open` открывает файл и возвращает файловый объект; `with … as f` привязывает его к имени `f` (зачем нужен `with` — на следующей странице). Дальше два способа чтения:

- `f.read()` — весь файл одной строкой (`str`) с переводами строк; список строк файла даёт `f.readlines()`.
- `for line in f:` — по одной строке файла за шаг. Так читают большие файлы: целиком в память они не загружаются.

<Theorem kind="definition" title="Файловый объект"
  formal="Файловый объект — объект, предоставляющий файловый интерфейс (методы read(), write() и другие) к нижележащему ресурсу, например к файлу на диске. Создаётся функцией open()."
  source="Документация Python, Glossary: file object; Python Tutorial, 7.2 «Reading and Writing Files» (пересказ)">

<Term id="file-object">Файловый объект</Term> — доступ программы к файлу на диске: через него читают и пишут. Каждое чтение продолжает с того места, где остановилось предыдущее: после `f.read()` второе `f.read()` вернёт пустую строку.

</Theorem>

## `\n` остаётся в конце строки файла

Вы уже различаете строку текста и строку-`str`. Строку текста из файла будем коротко называть **строкой файла**: `line` — это `str`, в котором одна строка файла.

Второй цикл напечатал оценки через пустую строку. Каждая строка файла, кроме, может быть, последней, заканчивается символом `\n`, и `for` его не убирает. `print` добавляет свой перевод строки — получается два. Поэтому строку файла почти всегда сначала чистят: `line.strip()`, а если пробелы по краям важны — `line.rstrip("\n")`.

## Почему with

Открытый файл нужно закрыть: система держит его занятым, а записанное может не дойти до диска, пока файл не закрыт. Ручной `f.close()` не выполнится, если перед ним возникнет исключение. `with open(...) as f:` закрывает файл сам при любом выходе из блока: блок закончился, сработал `return` или выброшено исключение. Это та короткая запись, которую мы обещали, когда разбирали `finally`. <Mark>Файлы открывают только через with.</Mark> Как `with` устроен изнутри, разберём в разделе «Функции как объекты» дисциплины «Инженерный Python».

После блока файл закрыт: `f.read()` за его пределами — `ValueError`. Всё нужное читают внутри блока, а результат привязывают к имени — как `text` выше.

## Режимы: r, w, a

Второй аргумент `open` — режим:

- `"r"` — чтение, режим по умолчанию. Нет файла — `FileNotFoundError`.
- `"w"` — запись. Если файла нет, он создаётся. **Если файл есть, его содержимое сразу стирается** — ещё до первой записи.
- `"a"` — дозапись (append): новое добавляется в конец, старое остаётся.

```python
with open("log.txt", "w", encoding="utf-8") as f:
    f.write("первая")
    f.write("вторая\n")
    print("третья", file=f)

with open("log.txt", encoding="utf-8") as f:
    print(f.read())
```

```
перваявторая
третья

```

`write` **перевод строки не добавляет** — «первая» и «вторая» слиплись. `print(..., file=f)` печатает в файл, как на экран, с переводом строки. Пустая строка в конце вывода — перевод строки от `print` после последнего `\n` файла.

<Callout kind="warning" title="Ловушка: w стирает файл">
Открыть журнал в режиме `"w"`, чтобы «дописать строку», — значит стереть весь журнал. Дописывают в режиме `"a"`.
</Callout>

<Callout kind="remember" title="Файлы в песочнице">
Каждый запуск в песочнице идёт в свежей папке с файлами задачи. После запуска она удаляется — созданные программой файлы на ваш диск не попадают. На своём компьютере файл останется в текущей папке.
</Callout>

## Таблица символов

Когда мы сравнивали строки, оказалось, что «ё» больше «я», а заглавные буквы меньше строчных. Откуда эти номера? Каждому символу Юникод — всемирная таблица символов — присваивает номер. Функция `ord` даёт номер символа, `chr` — символ по номеру:

```python
print(ord("A"), ord("Я"), ord("я"), ord("ё"))
print(chr(1103), chr(8381))
```

```
65 1071 1103 1105
я ₽
```

«ё» (1105) стоит в таблице не между «е» и «ж», а после «я» (1103); «Я» (1071) — раньше любой строчной. Вот почему `sorted` ставит «ёж» после «яблока», а «Яблоко» — перед «арбузом»: строки сравниваются по этим номерам.

<Term id="code-point">Кодовая точка</Term> — номер символа в таблице Юникода, целое число от 0 до 1 114 111. Строка в Python — последовательность кодовых точек.

## Байты на диске

Диск хранит не символы, а байты — числа от 0 до 255. Номер 1103 в один байт не помещается. Нужно правило перевода.

<Theorem kind="definition" title="Кодировка"
  formal="Правила, по которым строку Юникода превращают в последовательность байтов, называют кодировкой символов (character encoding). UTF-8 — кодировка, в которой символ занимает от 1 до 4 байтов; символы с номерами меньше 128 — по одному байту."
  source="Документация Python, Unicode HOWTO: Definitions, Encodings (пересказ)">

<Term id="encoding">Кодировка</Term> — договорённость о том, какими байтами записывается каждый символ. Прочитать файл правильно можно, только зная, в какой кодировке его записали. <Term id="utf-8">UTF-8</Term> (Unicode Transformation Format, 8-bit) — самая распространённая сегодня кодировка: латиница и цифры в ней — 1 байт на символ, кириллица — 2, знак рубля — 3.

</Theorem>

`len("привет")` — 6: `len` считает символы, а не байты. Байтов в UTF-8 — 12. Метод `encode` ниже — только для показа: в этом разделе работать с байтами не придётся.

```python
print(len("привет"), len("привет".encode("utf-8")))
print("привет".encode("utf-8").decode("cp1251"))
```

```
6 12
РїСЂРёРІРµС‚
```

Вторая строка — то самое «РїСЂРёРІРµС‚»: байты UTF-8 прочитали по чужой таблице — старой русской кодировке Windows `cp1251`, где почти каждый байт означает какой-то символ. Для «привет» ошибки нет, просто текст неверный. В обратном случае — файл записан в `cp1251`, читают как UTF-8 — на первом же неподходящем байте будет `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xef…`.

<Callout kind="warning" title="Ловушка: open без encoding">
Без `encoding` Python до версии 3.15 берёт кодировку системы: на Linux и macOS это UTF-8, а на Windows — часто `cp1251`. Программа, которая у вас читала файл верно, у коллеги выдаст кракозябры (так в обиходе называют нечитаемый текст) или `UnicodeDecodeError`. С версии 3.15 по умолчанию UTF-8, но программу запустят и на старом Python. Пишите `encoding="utf-8"` в каждом `open` с текстом.
</Callout>

Как устроены байты и почему кодировок так много, разберём в разделе «Как устроен компьютер» дисциплины «Компьютер и командная строка».

## Где Python ищет файл

`open("marks.txt")` — **относительный путь**: файл ищется в *текущей папке*. На своём компьютере программу запускают командой в терминале, находясь в какой-то папке, — она и становится текущей. Это не обязательно папка, где лежит сам `.py`: запустите программу из другой папки, и тот же `open` даст `FileNotFoundError`. Работу с терминалом разберём в разделе «Терминал Linux». **Абсолютный путь** начинается от корня диска: `C:\Users\anna\marks.txt` на Windows, `/home/anna/marks.txt` на Linux.

Путь Windows в обычной строке — ловушка: в `"C:\new\table.txt"` сочетание `\n` станет переводом строки, а `\t` — табуляцией. Выручает сырая строка, знакомая по регулярным выражениям (только она не может кончаться одиночной `\`), или прямая косая черта: Python понимает `"C:/new/table.txt"` и на Windows.

## pathlib — пути как значения

Запись `from pathlib import Path` берёт из модуля `pathlib` одно имя — дальше пишут `Path`, а не `pathlib.Path`. Подробнее об импорте — в разделе «Модули и мини-проект». `Path` — тип пути, который знает, из чего путь состоит. Части соединяют знаком `/`, и он сам поставит черту, принятую в системе:

```python
from pathlib import Path

p = Path("data") / "sales.csv"
print(p.name, p.stem, p.suffix, p.exists())
```

```
sales.csv sales .csv False
```

`name` (имя файла), `stem` (имя без расширения) и `suffix` (расширение с точкой) — **атрибуты** пути: значения, которые берут через точку без скобок. `exists()` — метод, его вызывают: есть ли такой файл или папка. Ещё два метода: `p.read_text(encoding="utf-8")` читает файл целиком, `p.write_text(text, encoding="utf-8")` записывает (как `"w"`: старое стирается). `open` принимает и `Path`, и строку.

## Файла может не быть

Отсутствующий файл — часто обычная ситуация: пользователь ещё ничего не сохранил. Тогда перехватывают именно `FileNotFoundError`:

```python
def read_marks(path):
    try:
        with open(path, encoding="utf-8") as f:
            return [line.strip() for line in f if line.strip()]
    except FileNotFoundError:
        return []

print(read_marks("нет_такого.txt"))
```

```
[]
```
