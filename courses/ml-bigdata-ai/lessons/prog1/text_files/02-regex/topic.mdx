## Где методов строк мало

Из сообщения нужно достать все числа: `"Заказ 15: 3 шт. по 120 руб., доставка 250 руб."`. `split()` даст куски вроде `'15:'` и `'руб.,'`, и каждый придётся чистить отдельно. Мы не знаем, где стоят числа, но знаем, *как они выглядят*: одна или несколько цифр подряд. Это и записывают шаблоном.

```python
import re

msg = "Заказ 15: 3 шт. по 120 руб., доставка 250 руб."
print(re.findall(r"\d+", msg))
print(re.findall(r"\d+ руб", msg))
```

```
['15', '3', '120', '250']
['120 руб', '250 руб']
```

Модуль `re` входит в стандартную библиотеку — набор модулей, которые устанавливаются вместе с Python, как уже знакомый `math`. Подробнее о ней — в разделе «Модули и мини-проект».

<Theorem kind="definition" title="Регулярное выражение"
  formal="Регулярное выражение задаёт множество строк, которые ему соответствуют. Функции модуля re проверяют, соответствует ли строка выражению, и находят в строке такие части."
  source="Документация Python, модуль re, вступление (пересказ); Regular Expression HOWTO">

<Term id="regex">Регулярное выражение</Term> (англ. regular expression, в речи — «регулярка», regex) — шаблон, который описывает *форму* текста: `\d` — «цифра», `+` — «одна или больше». `re.findall(шаблон, текст)` возвращает список всех непересекающихся кусков, которые подходят под шаблон.

</Theorem>

Обычные символы в шаблоне означают сами себя: за числами 15 и 3 «руб» не идёт, поэтому во второй ответ они не попали.

## Буква r перед кавычками

Все шаблоны записаны как `r"…"`. Без `r` обратная косая черта внутри строки начинает особые сочетания, одно из них вы знаете — `\n`. Иногда это ломает шаблон молча. `\b` в шаблоне значит «граница слова», а в обычной строке — служебный символ «шаг назад», и до модуля `re` доходит уже он:

```python
import re

text = "кот и котлета"
print(re.findall("\bкот\b", text))
print(re.findall(r"\bкот\b", text))
```

```
[]
['кот']
```

<Term id="raw-string">Сырая строка</Term> (англ. raw string) — строка с буквой `r` перед кавычками: в ней обратная косая черта остаётся обычным символом. `len("\b")` — 1, а `len(r"\b")` — 2: черта и буква. <Mark>Шаблоны регулярных выражений всегда пишут сырыми строками.</Mark> Для `"\d"` без `r` Python 3.12 хотя бы предупредит: `SyntaxWarning: invalid escape sequence '\d'`, а для `"\b"` — нет: это допустимое сочетание.

</Page>

## Символы и классы

<div className="table-scroll">

| Запись | Что подходит | Пример |
|---|---|---|
| `\d` | одна цифра | `\d\d` — `"07"` |
| `\w` | буква (и кириллица тоже), цифра или `_` | `\w+` — `"мир_2024"` |
| `\s` | пробельный символ | `\s+` — `"  \t"` |
| `\D`, `\W`, `\S` | обратное: не цифра, не `\w`, не пробельный | `\D` — `"-"` |
| `.` | любой символ, кроме перевода строки | `a.c` — `"abc"`, `"a.c"` |
| `[абв]`, `[0-9]` | один символ из набора или диапазона | `[А-Яа-яЁё]` — русская буква |
| `[^…]` | один символ *не* из набора | `[^»]` — всё, кроме `»` |
| `\.`, `\+`, `\(` | сам символ, а не его особый смысл | `\d+\.\d+` — `"89.90"` |

</div>

Точка — не «вообще любой символ»: перевод строки она не захватывает. Саму точку экранируют: `\.`. В диапазоне `[А-Яа-я]` нет буквы «ё»: в таблице Юникода она стоит отдельно, поэтому её добавляют явно.

## Сколько раз: квантификаторы

<Term id="quantifier">Квантификатор</Term> ставят сразу после символа или класса; он говорит, сколько раз тот может повториться:

- `+` — один или больше: `\d+`;
- `*` — ноль или больше: `\d*` подходит и к пустому месту, поэтому если нужен хотя бы один символ — `+`;
- `?` — ноль или один, то есть «необязательно»: под `\d+ ?руб` подходят и `"120руб"`, и `"250 руб"`;
- `{n}` — ровно n раз, `{n,m}` — от n до m: `\d{6}` — шесть цифр.

## Начало и конец

`^` — начало строки, `$` — конец. Сами они символов не захватывают, а только указывают место: под `^\d+$` подходит `"123"`, но не `"123 "` — после цифр стоит пробел, а не конец.

## search и Match

`re.search(шаблон, текст)` ищет *первый* кусок, который подходит под шаблон. Если нашёлся — возвращает объект-совпадение (Match), иначе — `None`. Найденный текст отдаёт метод `group()`:

```python
import re

m = re.search(r"\d+", "Заказ 15: 3 шт.")
print(m.group())
print(re.search(r"\d+", "без цифр"))
```

```
15
None
```

Поэтому результат `search` сначала проверяют: `if m:` — совпадение истинно, `None` ложен. Вызвать `.group()` у `None` — `AttributeError`.

Название `re.match` обманывает: он ищет совпадение **только в начале** строки — `re.match(r"\d+", "Заказ 15")` вернёт `None`. В курсе ищем через `search`, проверяем через `fullmatch`.

## Проверка формы — fullmatch

Проверим почтовый индекс: ровно шесть цифр. Предскажите столбцы:

```python
import re

for s in ["123456", "1234567", "индекс 123456"]:
    print(s, bool(re.search(r"\d{6}", s)), bool(re.fullmatch(r"\d{6}", s)))
```

```
123456 True True
1234567 True False
индекс 123456 True False
```

`search` нашёл шесть цифр *внутри* семи — для проверки это ошибка.

<Theorem kind="rule" title="Проверка формы — fullmatch"
  formal="re.fullmatch(pattern, string) возвращает объект-совпадение, только если вся строка целиком соответствует шаблону; иначе — None. re.search находит первое подходящее место в любой части строки."
  source="Документация Python, модуль re: re.fullmatch, re.search (пересказ)">

Чтобы проверить, что *вся* строка имеет нужную форму, — `fullmatch`. `search` отвечает на другой вопрос: «есть ли где-то внутри». Почти то же даёт `search` с `^…$`, но `$` подходит и перед переводом строки в самом конце: `"123456\n"` пройдёт такую проверку. А строки файла как раз оканчиваются на `\n`. Поэтому для проверок — `fullmatch`.

</Theorem>

## Замена — sub

`re.sub(шаблон, замена, текст)` заменяет все совпадения. Номер телефона пишут как угодно; оставим только цифры — заменим каждую «не цифру» `\D` пустой строкой:

```python
import re

for phone in ["+7 (912) 345-67-89", "8 912 345 67 89"]:
    digits = re.sub(r"\D", "", phone)
    print(digits, "+7" + digits[1:])
```

```
79123456789 +79123456789
89123456789 +79123456789
```

## Скобки в шаблоне

Часто нужно не всё совпадение, а его части: год, месяц, день. Части шаблона заключают в круглые скобки:

```python
import re

text = "Отгрузка 2024-05-17, оплата 2024-05-20"
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", text)
print(m.group(), m.group(1), m.groups())
print(re.findall(r"(\d{4})-(\d{2})-(\d{2})", text))
print(re.sub(r"(\d{4})-(\d{2})-(\d{2})", r"\3.\2.\1", text))
```

```
2024-05-17 2024 ('2024', '05', '17')
[('2024', '05', '17'), ('2024', '05', '20')]
Отгрузка 17.05.2024, оплата 20.05.2024
```

<Term id="regex-group">Группа</Term> — часть шаблона в круглых скобках. Группы нумеруются с 1 слева направо по открывающим скобкам; `group()` без аргумента — всё совпадение.

- `m.group(1)` — текст первой группы, `m.groups()` — кортеж всех групп.
- `findall` с группами возвращает уже не список совпадений, а список **кортежей групп**: по кортежу на совпадение. С одной группой — список строк этой группы.
- В строке замены `sub` запись `\1` значит «текст первой группы». Строку замены тоже пишут сырой: в обычной `"\1"` — символ с номером 1 в таблице Юникода.

Группы извлекают текст, но числа остаются строками: `int(m.group(1))` — уже число.

## Квантификатор берёт как можно больше

Достанем ответы в кавычках-ёлочках. Предскажите, что вернёт первый вызов:

```python
import re

t = "Ответы: «да» и «нет»"
print(re.findall(r"«.+»", t))
print(re.findall(r"«.+?»", t))
print(re.findall(r"«[^»]+»", t))
```

```
['«да» и «нет»']
['«да»', '«нет»']
['«да»', '«нет»']
```

`+` и `*` **жадные**: захватывают столько символов, сколько можно, лишь бы совпадение ещё получилось. `.+` дошёл до последней `»` в строке. Знак `?` после квантификатора делает его ленивым — «как можно меньше»: `.+?` останавливается на первой `»`. Третий вариант — «любые символы, кроме закрывающей кавычки» — часто понятнее.

Третьим аргументом можно передать настройку `re.I` — тогда заглавные и строчные буквы считаются одинаковыми: `re.findall(r"кот", "Кот и кот", re.I)` даёт `['Кот', 'кот']`.

<Callout kind="warning" title="Ловушка: регулярка там, где хватит метода">
Регулярку трудно читать даже автору через неделю. Если хватает `split`, `startswith`, `in`, `strip`, — обходитесь ими; регулярку пишите короткой, с комментарием-примером: `# дата вида 2024-05-17`. Страницы сайтов и форматы данных вроде CSV и JSON разбирают не регулярками, а готовыми модулями — об этом тема «CSV и JSON на реальных данных». Идеальной регулярки для email тоже нет: правила записи адреса слишком сложны для короткого шаблона.
</Callout>
