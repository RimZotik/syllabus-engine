## split с аргументом и без

С методом `split` вы работали много раз: `"89 45 320".split()` даёт `['89', '45', '320']`. А в записи `"хлеб;45"` из прошлого раздела мы писали `split(";")`, не объясняя разницы. Она больше, чем кажется. Предскажите четыре строки вывода:

```python
print("хлеб  молоко\tсыр\n".split())
print("хлеб  молоко".split(" "))
print("хлеб;45;;2;".split(";"))
print("".split(), "".split(";"))
```

```
['хлеб', 'молоко', 'сыр']
['хлеб', '', 'молоко']
['хлеб', '45', '', '2', '']
[] ['']
```

<Theorem kind="rule" title="split() и split(sep)"
  formal="str.split(sep=None, maxsplit=-1): если sep не задан, разделителем считается любая последовательность пробельных символов, пустые строки в результат не попадают, а пробельные символы в начале и в конце не дают пустых строк. Если sep задан, соседние разделители не склеиваются и дают пустые строки."
  source="Документация Python, Built-in Types: str.split (пересказ)">

<Term id="whitespace">Пробельные символы</Term> — пробел, табуляция `\t`, перевод строки `\n`, возврат каретки `\r` и несколько редких, например неразрывный пробел. Без аргумента `split()` режет по любой их цепочке и выбрасывает пустые куски: сколько бы пробелов ни стояло между словами, получатся только слова. С аргументом `split(";")` режет *ровно* по каждому `;`: два разделителя подряд дают пустую строку между ними, разделитель в конце — пустую строку после него.

</Theorem>

Поэтому `split(" ")` — не то же самое, что `split()`: двойной пробел даст пустое «слово». Для слов через пробелы — `split()` без аргумента. Для данных с разделителем (`;`, `,`, `|`) — `split(sep)`, и пустая строка в результате честно скажет «здесь значение пропущено».

Второй аргумент, `maxsplit`, ограничивает число разрезов — когда последняя часть сама может содержать разделитель: `"10:02 INFO вход user=anna".split(maxsplit=2)` даёт `['10:02', 'INFO', 'вход user=anna']`.

`join` — обратная операция: `";".join("a;;b".split(";"))` снова даёт `"a;;b"`. Элементы должны быть строками, числа сначала превращают в строки через `str`.

<Callout kind="warning" title="Много кусков склеивают через join, а не через +=">
Строки неизменяемы: `s += "кусок"` создаёт новую строку и копирует в неё всё накопленное. Документация Python предупреждает: если собирать строку повторным склеиванием, время растёт квадратично от общей длины — вдвое больше кусков, примерно вчетверо больше копирования. CPython иногда ускоряет `+=`, но полагаться на это документация не советует. Куски собирают в список, а в конце один раз вызывают `"".join(parts)`. Как оценивают время работы программы, разберём в дисциплине «Первые алгоритмы».
</Callout>

## strip убирает набор символов

`strip()` без аргумента убирает пробельные символы по краям. Ему можно передать, *какие* символы убирать: `"  --Итого--  ".strip(" -")` даёт `"Итого"`. Кажется, так же можно отрезать окончание имени файла. Предскажите результат:

```python
print("test.txt".strip(".txt"))
print("report.txt".strip(".txt"))
print("report.txt".removesuffix(".txt"))
```

```
es
repor
report
```

Аргумент `strip` — не кусок текста, а **набор символов**: здесь `.`, `t` и `x`. С каждого края `strip` отрезает символы, пока они входят в набор. У `test` слева ушло `t`, справа — `.txt` и ещё одно `t`. У `report` справа ушли `.txt` и последняя буква слова.

<Callout kind="warning" title={"Ловушка: strip(\".txt\") не убирает «.txt»"}>
Чтобы убрать конкретный кусок с края, есть `removesuffix(".txt")` (с конца) и `removeprefix("IMG_")` (с начала). Они убирают кусок ровно один раз и только если строка им действительно заканчивается или начинается. `lstrip` и `rstrip` работают как `strip`, но только с левого или с правого края.
</Callout>

## Найти и посчитать

```python
s = "мама мыла раму"
print(s.find("мы"), s.find("папа"))
print(s.count("ма"), s.count("а"))
print("IMG_001.jpg".startswith("IMG_"))
print("отчёт.PDF".lower().endswith((".pdf", ".doc")))
```

```
5 -1
2 4
True
True
```

- `find(sub)` возвращает индекс начала первого вхождения, а если вхождения нет — `-1`. Но `-1` — допустимый индекс: `s[s.find("папа")]` молча даст последний символ. Поэтому результат `find` сначала сравнивают с `-1`; для ответа «есть или нет» хватит `in`.
- `count(sub)` считает вхождения, которые не перекрываются: в «мама» «ма» встречается дважды, в «раму» — ни разу.
- `startswith` и `endswith` проверяют начало и конец строки. Можно передать кортеж вариантов — `True`, если подошёл любой.

Есть ещё `index(sub)` — как `find`, но при отсутствии вхождения выбрасывает `ValueError`. Выбор — как между `get` и квадратными скобками у словаря.

## Ширина и выравнивание

Формат `:.2f` вы уже знаете: после двоеточия в f-строке задают, *как* показать значение. Возможностей у этой записи больше. Каждое значение в выводе обрамлено квадратными скобками, чтобы были видны пробелы. Предскажите, где они окажутся:

```python
print(f"[{45:>6}]", f"[{45:<6}]", f"[{'Итого':^11}]")
print(f"[{12.5:>8.2f}]", f"[{7:03}]", f"[{0.256:.1%}]")
print(f"{1234567.891:,.2f}")
```

```
[    45] [45    ] [   Итого   ]
[   12.50] [007] [25.6%]
1,234,567.89
```

Строку внутри f-строки пишут в кавычках другого вида — `'Итого'` в одинарных: так читается проще и работает в любой версии Python.

<Theorem kind="definition" title="Спецификация формата"
  formal="Спецификация формата определяет, как представить отдельное значение в поле замены f-строки или str.format: [[заполнитель]выравнивание][0][ширина][,][.точность][тип]. Каждая часть необязательна."
  source="Документация Python, Format Specification Mini-Language (пересказ, сокращено)">

<Term id="format-spec">Спецификация формата</Term> — всё, что стоит после двоеточия внутри фигурных скобок. Части идут строго в таком порядке:

- **выравнивание:** `<` — влево, `>` — вправо, `^` — по центру; перед ним можно поставить символ-заполнитель: `{'кот':*^7}` даёт `**кот**`;
- **`0`** перед шириной дополняет число нулями слева, как в `03`;
- **ширина** — сколько символов значение займёт как минимум; длинное значение не обрезается;
- **`,`** — разделять тысячи запятой;
- **`.точность`** — знаков после точки;
- **тип:** `f` — дробное с фиксированной точкой, `%` — умножить на 100 и добавить знак процента, `d` — целое (к дробному не применяется).

</Theorem>

Без знака выравнивания числа прижимаются вправо, а строки — влево: `f"[{42:5}]"` даёт `[   42]`, а `f"[{'42':5}]"` — `[42   ]`.

В России тысячи отделяют пробелом, а дробную часть — запятой. Отдельного формата для этого нет: сначала форматируют, потом заменяют знаки. `f"{1234567.5:,.2f}".replace(",", " ").replace(".", ",")` даёт `1 234 567,50`. Формат, как и раньше, меняет только вывод: само число не округляется.

## Чек ровными столбцами

```python
items = [("хлеб", 45, 2), ("сыр", 320.5, 1), ("молоко", 89.9, 3)]
total = 0
for name, price, count in items:
    cost = price * count
    total += cost
    print(f"{name:<8}{count:>3} x {price:>7.2f} = {cost:>8.2f}")
print(f"{'Итого':<8}{total:>24,.2f}")
```

```
хлеб      2 x   45.00 =    90.00
сыр       1 x  320.50 =   320.50
молоко    3 x   89.90 =   269.70
Итого                     680.20
```

Ширины подобраны так, чтобы итог встал ровно под столбцом стоимостей: строка «Итого» занимает столько же символов, сколько строка товара.

## Сколько ошибок у каждого пользователя

Журнал сервера (англ. log, в речи — «лог») — текст, где каждая строка описывает одно событие. Различаем: **строка текста** (line) — одна запись до перевода строки, а **строка** как тип `str` — любое текстовое значение, хоть весь журнал целиком.

Строку в тройных кавычках `"""…"""` можно записать на нескольких строках кода: переводы строк войдут в неё как `\n`. Метод `splitlines()` делит текст по переводам строк, а сами переводы отбрасывает. Предскажите отчёт (порядок ключей — порядок первого появления) и пройдите по шагам:

<Trace>

```python
log = """2024-05-17 10:02 INFO вход anna
2024-05-17 10:05 ERROR оплата boris

2024-05-17 10:07 ERROR оплата anna
2024-05-17 10:12 ERROR склад boris
"""
errors = {}
for line in log.splitlines():
    if not line.strip():
        continue
    date, time, level, action, user = line.split()
    if level == "ERROR":
        errors[user] = errors.get(user, 0) + 1
for user, n in errors.items():
    print(f"{user:<8}{n:>3}")
```

</Trace>

```
boris     2
anna      1
```

- **Пустая строка текста** в журнале — обычное дело. Для неё `line.strip()` даёт пустую строку, а пустая строка ложна — `continue` её пропускает. Без проверки упала бы распаковка: `split()` от пустой строки даёт пустой список, а имён пять.
- **Распаковка проверяет формат.** Не пять частей — `ValueError`, и сломанная строка текста не пройдёт тихо. Как обрабатывать неаккуратные данные, не останавливая программу, — в теме о CSV и JSON.
