## Почему не split(",")

Выгрузка продаж `sales.csv`: в первой строке файла — названия столбцов, дальше — по записи на строку, значения через запятую. Кажется, хватит `line.split(",")`. Но в названии магазина тоже есть запятая: `'Казань,"Ромашка, ИП",1200'.split(",")` даёт четыре куска вместо трёх — `'"Ромашка'` и `' ИП"'`. Кавычки в CSV как раз и говорят «эта запятая — часть значения», но `split` о них не знает.

<Theorem kind="definition" title="CSV"
  formal="Каждая запись расположена на отдельной строке. Первая строка может быть заголовком с именами полей. Поля разделяются запятыми. Поле, которое содержит запятую, двойную кавычку или перевод строки, заключается в двойные кавычки; кавычка внутри такого поля удваивается."
  source="RFC 4180 «Common Format and MIME Type for Comma-Separated Values (CSV) Files», раздел 2 (пересказ)">

<Term id="csv">CSV</Term> (Comma-Separated Values — «значения, разделённые запятыми») — таблица, записанная обычным текстом: строка файла — запись, поля — через разделитель. В CSV выгружают данные Excel, базы данных, банки и интернет-магазины. Простота обманчива: кавычки, переводы строк внутри поля и разные разделители правильно разбирает только модуль, который знает все эти правила.

</Theorem>

## Модуль csv

Такой модуль есть в стандартной библиотеке — `csv`. Пройдите по шагам и посмотрите, чему равно `row` на каждом шаге:

<Trace files={{"sales.csv": "город,магазин,сумма\nКазань,\"Ромашка, ИП\",1200\nОмск,Лето,850\n"}}>

```python
import csv

with open("sales.csv", encoding="utf-8", newline="") as f:
    for row in csv.DictReader(f):
        print(row["магазин"], row["сумма"])
```

</Trace>

- `csv.DictReader` читает первую строку файла как заголовок и выдаёт каждую запись словарём: ключи — названия столбцов. Это та же «таблица как список словарей», только из файла. (`csv.reader` выдаёт записи списками.)
- `newline=""` в `open` — правило модуля, его просто запоминают: для csv файл открывают с `newline=""`. Переводы строк тогда разбирает сам `csv`.

<Mark>В CSV всё — строки.</Mark> `row["сумма"]` — это `'1200'`, а не число; `row["сумма"] * 2` даст `'12001200'`. Числовые поля переводят в числа сами — через `int` или `float` — и решают, что делать, если перевести не удалось.

## Выгрузка из реальной жизни

Выгрузку `raw.csv` собирали руками в разных городах — в ней типичные проблемы:

```
дата;город;сумма
2024-05-17; Казань ;1 200,50
2024-05-17;Омск;
2024-05-18;казань;980
2024-05-18;Омск;сто
```

- **Разделитель `;`.** Excel с русскими настройками сохраняет CSV через точку с запятой: запятая занята под дробную часть. Модулю это сообщают: `delimiter=";"`.
- **Кодировка.** Файл из Excel бывает в `cp1251` или в UTF-8 с невидимой меткой в начале (BOM). С `encoding="utf-8"` метка прилипнет к первому заголовку — `'\ufeffдата'`, и `row["дата"]` даст `KeyError`; помогает `encoding="utf-8-sig"`.
- **Лишние пробелы** вокруг « Казань » и **разный регистр** («казань»): для программы это три разных города.
- **Число по-русски:** запятая вместо точки, а между тысячами — неразрывный пробел (так его ставят Excel и бухгалтерские программы). На вид он как обычный, но `replace(" ", "")` его не уберёт.
- **Пропуск** (пустая сумма) и **мусор** («сто»).

Задача: сумма продаж по городам. Предскажите итог и номера пропущенных строк файла, потом пройдите по шагам:

<Trace files={{"raw.csv": "дата;город;сумма\n2024-05-17; Казань ;1\u00a0200,50\n2024-05-17;Омск;\n2024-05-18;казань;980\n2024-05-18;Омск;сто\n"}}>

```python
import csv

def to_amount(text):
    return float("".join(text.split()).replace(",", "."))

totals = {}
skipped = []
with open("raw.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f, delimiter=";")
    for n, row in enumerate(reader, start=2):
        city = row["город"].strip().lower()
        try:
            amount = to_amount(row["сумма"])
        except ValueError:
            skipped.append(n)
            continue
        totals[city] = totals.get(city, 0) + amount
print(totals)
print("пропущены строки файла:", skipped)
```

</Trace>

```
{'казань': 2180.5}
пропущены строки файла: [3, 5]
```

- **Город приводят к одному виду:** `strip()` убирает пробелы, `lower()` — разницу в регистре. Без этого «Казань», « Казань » и «казань» стали бы тремя ключами.
- **Текст в число переводит отдельная функция.** `"".join(text.split())` убирает любые пробельные символы, в том числе неразрывный пробел: `split()` без аргумента режет и по нему. Пустую строку и «сто» `float` не переводит — `ValueError`. Функцию легко проверить своими `assert` на граничных случаях.
- **Ни одна строка не теряется молча.** `enumerate(..., start=2)` даёт номер строки файла (первая — заголовок), и номера пропущенных записываются. Отчёт, из которого тихо выпала часть данных, хуже упавшей программы: ему поверят.

У Омска обе записи пропущены — его нет в итогах. Сказать «у Омска 0» было бы неправдой: продажи были, их не удалось прочитать.

<Callout kind="warning" title="Ловушка: пустое — не ноль">
Пропуск значит «неизвестно», а не «ноль». Заменить пустую сумму нулём — значит занизить итог и среднее. Пропуски считают и сообщают о них; заполнять ли их и чем — решение о данных, а не о коде. Стратегии работы с пропусками — в разделе «Очистка» дисциплины «Сбор и подготовка данных».
</Callout>

Если полей в строке файла меньше, чем в заголовке, `DictReader` подставит в недостающие `None`, а лишние соберёт списком под ключом `None`; такие строки проверяют до разбора полей.

## Записать CSV

Записывают так же, как читают: список словарей → файл.

```python
import csv

rows = [{"город": "Казань", "сумма": 2180.5}, {"город": "Тула", "сумма": 640}]
with open("report.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["город", "сумма"])
    writer.writeheader()
    writer.writerows(rows)
```

В файле окажутся три строки: `город,сумма`, `Казань,2180.5`, `Тула,640`. `fieldnames` задаёт порядок столбцов, `writeheader()` пишет заголовок. Числа модуль сам превращает в строки, а поле с запятой или кавычкой сам берёт в кавычки.

## Таблицы мало

У заказа есть покупатель с именем и городом и список товаров, у каждого — цена и количество. В плоскую таблицу это не ложится — для таких данных есть JSON.

<Theorem kind="definition" title="JSON"
  formal="JSON — текстовый, не зависящий от языка формат обмена данными. Он представляет четыре простых типа — строки, числа, логические значения и null — и два составных: объект (неупорядоченный набор пар «имя: значение», где имя — строка) и массив (упорядоченная последовательность значений)."
  source="RFC 8259 «The JavaScript Object Notation (JSON) Data Interchange Format», раздел 1 (пересказ); ECMA-404">

<Term id="json">JSON</Term> (JavaScript Object Notation — «запись объектов JavaScript») — текст, похожий на словари и списки Python. В нём обмениваются данными программы на любых языках: отвечают сайты, хранят настройки.

</Theorem>

JSON похож на Python, но не совпадает с ним:

<div className="table-scroll">

| JSON | Python |
|---|---|
| объект `{"a": 1}` | `dict` |
| массив `[1, 2]` | `list` |
| строка `"чай"` — только двойные кавычки | `str` |
| число `17`, `300.5` | `int`, `float` |
| `true`, `false` | `True`, `False` |
| `null` | `None` |

</div>

Модуль `json` переводит в обе стороны: `json.dumps(значение)` — значение Python → строка JSON, `json.loads(строка)` — обратно.

```python
import json

order = {"id": 17, "paid": True, "coupon": None, "items": [{"name": "чай", "qty": 2}]}
print(json.dumps(order))
print(json.dumps(order, ensure_ascii=False))
print(json.loads(json.dumps(order)) == order)
```

```
{"id": 17, "paid": true, "coupon": null, "items": [{"name": "\u0447\u0430\u0439", "qty": 2}]}
{"id": 17, "paid": true, "coupon": null, "items": [{"name": "чай", "qty": 2}]}
True
```

<Term id="serialization">Сериализация</Term> — перевод значения в текст или байты, чтобы сохранить его в файл или передать другой программе; обратный перевод — десериализация. `dumps` — сериализация в JSON. По умолчанию кириллица записывается номерами символов вида `\u0447` — это верный JSON, но человеку не прочитать. `ensure_ascii=False` оставляет буквы как есть.

Для файлов — `json.dump(значение, f)` и `json.load(f)`. Самая частая запись:

```python
import json

with open("order.json", "w", encoding="utf-8") as f:
    json.dump({"id": 17, "name": "чай"}, f, ensure_ascii=False, indent=2)
```

`indent=2` расставляет переводы строк и отступы, чтобы файл читался глазами.

По дороге кое-что меняется. Ключи объекта JSON — только строки: `json.loads(json.dumps({1: "a"}))` даёт `{'1': 'a'}`, и `d[1]` после чтения — `KeyError`. Кортеж вернётся списком, а множество `json.dumps` не примет вовсе — `TypeError`.

</Page>

## Добраться до значения

Заказы из интернет-магазина, файл `orders.json`. Предскажите, что напечатает программа для заказа 2, и пройдите по шагам:

<Trace files={{"orders.json": "[\n  {\"id\": 1, \"customer\": {\"name\": \"Аня\", \"city\": \"Казань\"},\n   \"items\": [{\"name\": \"чай\", \"price\": 150, \"qty\": 2}, {\"name\": \"сыр\", \"price\": 320, \"qty\": 1}]},\n  {\"id\": 2, \"customer\": {\"name\": \"Борис\"}, \"items\": []},\n  {\"id\": 3, \"customer\": {\"name\": \"Аня\", \"city\": \"Казань\"},\n   \"items\": [{\"name\": \"хлеб\", \"price\": 45, \"qty\": 3}], \"paid\": false}\n]\n"}}>

```python
import json

with open("orders.json", encoding="utf-8") as f:
    orders = json.load(f)

spent = {}
for order in orders:
    name = order["customer"]["name"]
    city = order["customer"].get("city", "не указан")
    total = sum(item["price"] * item["qty"] for item in order["items"])
    spent[name] = spent.get(name, 0) + total
    print(order["id"], name, city, total, order.get("paid", True))
print(json.dumps(spent, ensure_ascii=False))
```

</Trace>

Для заказа 2 программа печатает `2 Борис не указан 0 True`, а в конце — `{"Аня": 755, "Борис": 0}`.

- Путь к значению читают слева направо: `order["customer"]["name"]` — у заказа взять покупателя, у покупателя — имя. Каждая пара скобок — шаг вглубь.
- **Обязательное поле** берут квадратными скобками: нет имени — `KeyError` сразу. **Необязательное** — через `get` со значением по умолчанию, как `city` и `paid`.
- Пустой список товаров — не ошибка: `sum` от него даёт 0, и этот 0 честный.

## Битый JSON

JSON строже записи словаря в Python: одинарные кавычки `{'a': 1}`, запятая после последней пары `{"a": 1,}`, `True` вместо `true` — и `json.loads` выбросит `json.JSONDecodeError` (разновидность `ValueError`). Текст исключения называет место: `line 1 column 2 (char 1)`. Битый JSON не чинят «на глаз» — сообщают источнику данных.

В настройках проектов встретится ещё YAML — та же вложенность, что у JSON, но через отступы, без скобок и почти без кавычек: заказ 2 там записан строками `id: 2`, `customer:` и под ней с отступом `name: Борис`. Модуля для YAML в стандартной библиотеке нет.
