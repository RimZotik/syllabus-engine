## Куда уходят деньги

Вы записываете расходы в таблицу — то с телефона, то с компьютера. Получился CSV-файл `expenses.csv`, и он неаккуратный, как почти все настоящие данные:

```
дата,категория,сумма
2024-05-03, Продукты ,"1 250,50"
2024-05-03,Транспорт,60
2024-05-17,продукты,890
2024-06-01,Кафе,
2024-06-02,транспорт,120
06.06.2024,Кафе,450
2024-06-09,кафе,380
```

Пробелы вокруг категории, разный регистр, сумма с пробелом и запятой, пустая сумма, дата не в ISO 8601. Нужна программа, которая читает такой файл и пишет отчёт `report.json` с такими данными (отступы в файле будут шире):

```
{
  "всего": 2700.5,
  "по категориям": {"продукты": 2140.5, "транспорт": 180.0, "кафе": 380.0},
  "по месяцам": {"2024-05": 2200.5, "2024-06": 500.0},
  "пропущено": [
    {"строка": 5, "причина": "пустая сумма"},
    {"строка": 7, "причина": "Invalid isoformat string: '06.06.2024'"}
  ]
}
```

Строки, которые не удалось разобрать, программа не теряет молча и не падает на них: она их пропускает, а в отчёт записывает номер строки и причину. Номера — как в редакторе: заголовок — строка 1.

## Что должно получиться

- **Три модуля:** разбор строк, подсчёт сводок, основная программа.
- **Функции, каждая — одно дело,** со строками документации; печать и файлы — только в основной программе.
- **Проверки** `assert` для каждой функции — обычные, граничные и «плохие» случаи.
- **README** — описание проекта на десять строк.

Это репетиция проекта Курса I «Первый настоящий репозиторий»: там программа тоже читает данные, отвечает на вопросы и живёт в нескольких файлах, только уже на вашем компьютере и под контролем Git — его изучите в дисциплине «Git и GitHub».

## От условия к функциям

Помните декомпозицию: делим задачу, пока для каждой части не станет ясно, как её написать. Пройдём по условию и выпишем действия:

<div className="table-scroll">

| Действие | Функция | Получает → возвращает |
|---|---|---|
| сумма из текста | `parse_amount(text)` | `"1 250,50"` → `1250.5`; пусто или не число — `ValueError` |
| категория без мусора | `clean_category(text)` | `" Продукты "` → `"продукты"` |
| запись из строки таблицы | `parse_row(row)` | словарь из `csv.DictReader` → словарь с ключами `date`, `category`, `amount`; плохая строка — `ValueError` |
| прочитать файл | `load(path)` | путь → (записи, пропущенные строки) |
| суммы по категориям | `by_category(records)` | записи → `{категория: сумма}` |
| суммы по месяцам | `by_month(records)` | записи → `{"ГГГГ-ММ": сумма}` |
| собрать и записать отчёт | `main()` | ничего не возвращает: пишет файл и печатает итог |

</div>

Дату разбирает готовая `date.fromisoformat`: на неверной дате она сама выбросит `ValueError`, как `parse_amount` на пустой сумме. Если в строке не хватает полей, `csv.DictReader` вместо них даёт `None`, и `parse_row` тоже выбрасывает `ValueError` («не хватает полей»). Поэтому `load` поймает все плохие строки одним `except ValueError`.

## От функций к модулям

Функции группируют по тому, что они **знают**:

- `clean.py` — знает формат таблицы: названия столбцов, запятую в суммах. `parse_amount`, `clean_category`, `parse_row`.
- `summary.py` — знает только записи-словари, про CSV не знает ничего. `by_category`, `by_month`. Завтра записи придут из базы данных — этот модуль не изменится.
- `main.py` — знает про файлы: читает `expenses.csv`, пишет `report.json`, печатает итог. `load`, `main`.

```
main.py ──► clean.py ──► datetime
   │
   └──────► summary.py ──► collections
```

Стрелка — «импортирует». <Mark>Модули делят по тому, что они знают; импорты идут в одну сторону.</Mark> `clean` и `summary` не импортируют `main` и друг друга, поэтому циклическому импорту неоткуда взяться. В `clean` и `summary` — только чистые функции, без `print` и без файлов: их легко проверить.

## Сначала требования

Проверки пишут по условию, до кода, — для каждой функции модулей `clean` и `summary`. Их выносят в отдельный файл `checks.py`: он импортирует модули и проверяет их, а в самих модулях проверок нет.

```python
import clean

# обычные
assert clean.parse_amount("60") == 60
assert clean.clean_category("Кафе") == "кафе"
# граничные — как в настоящей таблице
assert clean.parse_amount("1 250,50") == 1250.5
assert clean.clean_category(" Продукты ") == "продукты"
# «плохие»
raised = False
try:
    clean.parse_amount("")
except ValueError:
    raised = True
assert raised, "пустая сумма должна давать ValueError"
```

Ещё «плохие» случаи: строка без суммы (`None` вместо текста) и текст `"nan"` — `float("nan")` даёт особое значение «не число» без всякой ошибки, и оно испортит все суммы. Для `summary` придумайте записи, ответ для которых считается в уме, — две-три записи с круглыми суммами. Граничные случаи: пустой список записей (`by_category([]) == {}`), одна категория в двух месяцах, два месяца разных лет — `2023-12` и `2024-12` не должны слиться.

## Деньги во float

Сравнивать дробные суммы через `==` можно, пока они точно представимы: 1250.5, 150.0. Для сумм вроде 0.1 + 0.2 нужен `math.isclose` или округление — помните, почему 0.1 + 0.2 не равно 0.3. В отчёт суммы пишут округлёнными до копеек: `round(x, 2)`. В настоящем учёте деньги хранят в копейках целым числом или в типе `Decimal`: `float` копит погрешность.

## Одна функция целиком

`parse_amount` — функция из одной мысли: убрать пробелы, запятую заменить точкой, перевести в `float`. В таблицах из банка встречается неразрывный пробел — в Python его записывают `"\xa0"`:

```python
def parse_amount(text):
    """'1 250,50' → 1250.5; пустой текст или не число — ValueError."""
    cleaned = text.replace(" ", "").replace("\xa0", "").replace(",", ".")
    if not cleaned:
        raise ValueError("пустая сумма")
    return float(cleaned)
```

`float("")` выбросил бы `ValueError` и сам, но с текстом `could not convert string to float: ''`. Своё сообщение «пустая сумма» попадёт в отчёт и будет понятно человеку.

## Основная программа

`load` открывает файл с `encoding="utf-8-sig"` и `newline=""`. `utf-8-sig` — UTF-8, который понимает невидимую метку в начале файла: её ставит Excel, сохраняя «CSV UTF-8». С простым `utf-8` метка попадёт в название первого столбца, и `row["дата"]` уронит программу с `KeyError`. Строки `load` читает через `csv.DictReader`, нумерует, как в разборе CSV, `enumerate(…, start=2)`, и каждую отдаёт `clean.parse_row` внутри `try`: `ValueError` значит «пропустить строку и записать причину». `try` охватывает только разбор одной строки — ошибки в остальном коде не прячутся.

`main` собирает отчёт словарём с суммами, округлёнными через `round(…, 2)`, записывает его через `json.dump` с `ensure_ascii=False` — чтобы кириллица осталась кириллицей — и печатает одну итоговую строку. Вызов `main()` — под `if __name__ == "__main__":`, поэтому `checks.py` и платформа могут импортировать `main.py`, не запуская программу.

Запуск `main.py` на таблице выше печатает `записей: 5 пропущено: 2`. В песочнице `report.json` исчезнет вместе с папкой задачи после запуска (проверка успеет его прочитать), а на вашем компьютере останется рядом с программой.

## Traceback через два модуля

Пока `load` не дописана, вы пробуете `parse_amount` из отдельного файла `boom.py` и передаёте ей сумму словами. На компьютере:

```python
import clean

print(clean.parse_amount("сто"))
```

```
Traceback (most recent call last):
  File "C:\work\boom.py", line 3, in <module>
    print(clean.parse_amount("сто"))
          ^^^^^^^^^^^^^^^^^^^^^^^^^
  File "C:\work\clean.py", line 10, in parse_amount
    return float(cleaned)
           ^^^^^^^^^^^^^^
ValueError: could not convert string to float: 'сто'
```

Две пары строк — два файла, и оба ваши. Нижняя пара — место, где ошибку заметили: `float` в `clean.py`. Верхняя — откуда пришло «сто». Где же ошибка? По условию `parse_amount` для «не числа» выбрасывает `ValueError`, так что функция права, а `load` такие строки поймает и пропустит.

## Описание проекта

README — первый файл, который читают в чужом проекте. Для мини-проекта хватит десяти строк:

```
# Учёт расходов

Читает expenses.csv (дата, категория, сумма) и пишет report.json:
итог, суммы по категориям и месяцам, пропущенные строки с причиной.

Запуск из папки проекта: python main.py
Проверки: python checks.py

Модули: clean.py — разбор строк таблицы; summary.py — сводки;
main.py — файлы и отчёт.
Нужен только Python 3.12+, сторонних пакетов нет.
```

## Перед сдачей

- Каждая функция модулей `clean` и `summary` — со строкой документации и проверками в `checks.py`, включая граничные и «плохие» случаи.
- В `clean.py` и `summary.py` нет `print`, `input` и работы с файлами.
- При `import main` программа ничего не печатает и не ждёт ввода.
- CSV открывается с `encoding="utf-8-sig"`, JSON пишется с `encoding="utf-8"` и `ensure_ascii=False`; суммы в отчёте округлены.
- `except` ловит конкретный тип и охватывает только разбор строки.
- Вы можете пройти любую строку своего кода вручную. Код от ассистента берите, только если он прошёл ваши проверки, написанные по условию.
