## Функции нужны в двух программах

Расчёт чека из программы магазина понадобился программе кассы. Скопируете функции — каждую найденную ошибку придётся исправлять в двух местах. Вы уже подключали `statistics` и `copy` — это обычные файлы с кодом на Python, написанные другими людьми. Свой модуль устроен так же.

<Theorem kind="definition" title="Модуль"
  formal="Модуль — файл, содержащий определения и инструкции Python. Имя файла — это имя модуля с добавленным суффиксом .py."
  source="Python Tutorial, 6 «Modules» (пересказ)">

<Term id="module">Модуль</Term> получается из файла `.py`: функции и значения этого файла подключают к другой программе через `import`. Файл `shop.py` даёт модуль `shop` — в `import` пишут имя без `.py`.

</Theorem>

В документации модулем называют и сам файл. Точнее различать: файл хранится на диске, модуль — значение с именами внутри, которое появляется в программе по `import`.

</Page>

## Два файла

Файл `shop.py` — цены и расчёт чека. Первая строка печатает, чтобы было видно, когда файл выполняется:

```python
print("выполняю shop.py")
PRICES = {"молоко": 89, "хлеб": 45, "сыр": 320}

def total(items):
    return sum(PRICES[name] for name in items)
```

Программа рядом с ним импортирует `shop` дважды. Предскажите вывод, потом пройдите по шагам:

<Trace files={{"shop.py": "print(\"выполняю shop.py\")\nPRICES = {\"молоко\": 89, \"хлеб\": 45, \"сыр\": 320}\n\ndef total(items):\n    return sum(PRICES[name] for name in items)\n"}}>

```python
import shop
import shop

print(shop.total(["хлеб", "сыр"]))
print(shop.PRICES["молоко"])
```

</Trace>

Строка «выполняю shop.py» печатается один раз, хотя `import` два, а потом — 365 и 89:

1. **Первый `import shop`.** Python заводит пустой модуль `shop`, запоминает его и выполняет `shop.py` сверху вниз: печатает строку, а каждое имя, которое заводит файл (`PRICES`, `total`), попадает в этот модуль. В конце имя `shop` в вашей программе связывается с модулем.
2. **Второй `import shop`.** Модуль уже запомнен: файл не выполняется снова, имя `shop` связывается с тем же модулем.

Поэтому в модуле обычно нет `print` вне функций — иначе каждая импортирующая программа напечатает чужой текст. А исправив `shop.py`, программу перезапускают: повторный `import` в запущенной возьмёт старый модуль.

## У каждого модуля свои имена

Глобальные имена у каждого модуля свои: `total = 0` в основной программе не тронет `shop.total`. Набор имён, каждое из которых связано со своим значением, называют <Term id="namespace">пространством имён</Term> (англ. namespace). У каждого модуля своё пространство глобальных имён, у каждого вызова функции — своё пространство локальных. `shop.total` читается как «имя `total` из пространства имён модуля `shop`».

А `PRICES` функция `total` ищет среди глобальных имён того модуля, где её определили, — `shop`, а не того, откуда её вызвали.

## import, from … import, as

```python
import shop
from shop import total, PRICES
import statistics as st
```

Файл выполняется один раз при любой записи; различаются имена в вашей программе. `import shop` даёт одно имя `shop`, и в каждом вызове видно, откуда функция. `from shop import ...` даёт имена `total` и `PRICES` прямо в программе — короче, но откуда они, видно только в начале файла. `as` даёт модулю короткое имя: `st.mean(...)`; NumPy, которую откроем в дисциплине «Векторы и матрицы», принято подключать как `np`.

## Импорт не копирует

`from shop import PRICES` не создаёт копию словаря. Это присваивание имени, как `a = b`: имя `PRICES` в вашей программе указывает на тот же словарь, что `shop.PRICES`. Ловушки псевдонимов здесь те же, что и со списками:

```python
from shop import total, PRICES

PRICES["чай"] = 150
print(total(["чай", "хлеб"]))

import shop
print(shop.PRICES is PRICES, len(shop.PRICES))
```

```
выполняю shop.py
195
True 4
```

Чай добавили «у себя», а `total` его нашла: словарь один на двоих.

## Ловушка: from … import *

Звёздочка импортирует все имена модуля сразу. Беда начинается, когда одно из них совпадает с вашим или встроенным. Встроенная функция `pow(a, b)` — то же, что `a ** b`:

```python
print(pow(2, 10))
from math import *
print(pow(2, 10))
```

```
1024
1024.0
```

У `math` своя `pow`, она всегда возвращает `float`. Звёздочка молча перепривязала имя `pow` — как `sum = 0`, только этой строки в коде не видно. <Mark>Перечисляйте нужные имена явно или пишите `import модуль`: тогда видно, откуда каждое имя.</Mark>

</Page>

## Программа и библиотека

Файл `temperature.py` переводит градусы. Его хочется и запускать, и подключать к прогнозу погоды:

```python
def to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32

print("__name__ =", __name__)

if __name__ == "__main__":
    print(to_fahrenheit(100))
```

Запустим сам файл:

```
__name__ = __main__
212.0
```

А теперь файл `weather.py` рядом с ним:

```python
import temperature

print(temperature.to_fahrenheit(-40))
```

```
__name__ = temperature
-40.0
```

`__name__` (читается «дандер нейм»: двойное подчёркивание с обеих сторон) Python заводит в каждом модуле сам. У запущенного файла это строка `"__main__"` («главный»), у импортированного — имя модуля, здесь `"temperature"`. Поэтому `212.0` напечаталось только при запуске.

<Theorem kind="rule" title={'if __name__ == "__main__"'}
  formal={'Когда модуль запускают как программу (python temperature.py), его код выполняется так же, как при импорте, но __name__ равно "__main__". Код под условием if __name__ == "__main__" выполнится только при запуске файла как скрипта и не выполнится при импорте.'}
  source="Python Tutorial, 6.1.1 «Executing modules as scripts» (пересказ)">

Файл, который запускают как программу, называют <Term id="script">скриптом</Term>. Под `if __name__ == "__main__":` пишут то, что нужно только при запуске: чтение ввода, печать, вызов главной функции. Функции и настройки — выше, без условия: они нужны в обеих ролях.

</Theorem>

## Сначала — рядом с программой

Упрощённо: по `import shop` Python ищет `shop.py` сначала в папке запущенного файла, потом в стандартной библиотеке — модулях, которые идут вместе с Python, — потом среди установленных пакетов (о них — в теме «Сторонние пакеты и окружение»). Не нашёл — `ModuleNotFoundError: No module named 'shop'`. Заметьте: модуль ищется рядом с запущенным файлом, а `open("data.csv")` — в текущей папке; поэтому проект запускают из его папки.

## Ловушка: свой random.py

Новичок осваивает модуль `random` и называет файл с опытами `random.py`. Рядом — программа `dice.py`:

```python
import random

print(random.randint(1, 6))
```

```
Traceback (most recent call last):
  File "C:\work\dice.py", line 3, in <module>
    print(random.randint(1, 6))
          ^^^^^^^^^^^^^^
AttributeError: module 'random' has no attribute 'randint'
```

`AttributeError` — «в значении нет такого атрибута», то есть имени после точки. Python первым нашёл в папке программы `random.py` с опытами, где `randint` нет, — как `sum = 0`, только для модулей. В песочнице курса часть стандартных модулей подключена заранее, и там ловушка может не проявиться.

<Callout kind="warning" title="Ловушка: имя файла как у модуля">
Не называйте свои файлы `random.py`, `csv.py`, `json.py`, `statistics.py` и другими именами стандартных модулей (немногие, встроенные в сам Python, как `sys`, так не перекрыть). Странный `AttributeError` у знакомого модуля — ищите в папке программы файл с тем же именем.
</Callout>

## Ловушка: модули импортируют друг друга

Программа `main.py` начинается с `import report`. Файл `report.py` начинается с `from prices import PRICES`, затем заводит `TITLE = "Отчёт по ценам"`. А `prices.py` начинается с `from report import TITLE`. Запуск `main.py`:

```
Traceback (most recent call last):
  File "C:\work\main.py", line 1, in <module>
    import report
  File "C:\work\report.py", line 1, in <module>
    from prices import PRICES
  File "C:\work\prices.py", line 1, in <module>
    from report import TITLE
ImportError: cannot import name 'TITLE' from partially initialized module 'report' (most likely due to a circular import) (C:\work\report.py)
```

Python завёл и запомнил модуль `report`, но на первой строке `report.py` ушёл выполнять `prices.py`. Тот просит `TITLE` у уже запомненного `report`, а до строки `TITLE = …` выполнение не дошло: модуль загружен наполовину (partially initialized). Это **циклический импорт** — зависимость по кругу. `PRICES` и `TITLE` переносят в третий модуль, например `common.py`: `report` и `prices` импортируют его, а он — никого.
