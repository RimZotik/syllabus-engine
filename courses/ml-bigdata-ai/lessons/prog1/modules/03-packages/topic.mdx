## Чужой код, которым делятся

Страницы сайтов чаще всего скачивают через `requests`, таблицы обрабатывают в `pandas`, модели обучают в `scikit-learn`. С Python они не ставятся: это **сторонние** пакеты, их пишут и выкладывают другие люди.

<Theorem kind="definition" title="Пакет (дистрибутив)"
  formal="Пакет дистрибутива (distribution package) — архив с номером версии, который содержит Python-модули, пакеты импорта и другие файлы и служит для распространения выпуска. Его скачивает и устанавливает пользователь. В разговоре его обычно называют просто «пакет»."
  source="Python Packaging User Guide, Glossary — «Distribution Package» (пересказ)">

<Term id="package">Пакет</Term> — чужой код, упакованный для установки: модули, номер версии и список того, что нужно ему самому. Установили пакет — и его модули подключаются через `import`, как стандартные.

</Theorem>

Различим три слова: **файл** хранится на диске, **модуль** получается из файла по `import`, **пакет** устанавливают, и внутри него обычно много модулей — у `requests` их десятки, а подключают его одной строкой `import requests`.

Какое имя писать в `import`, сказано в README — описании пакета на его странице. Оно не всегда совпадает с именем для установки: устанавливают `scikit-learn`, а пишут `import sklearn`.

<Term id="pypi">PyPI</Term> (Python Package Index — «каталог пакетов Python», читается «пай-пи-ай») — общий сайт pypi.org, куда авторы выкладывают пакеты, а все остальные их скачивают. Выложить пакет может любой зарегистрированный: проверки содержимого перед публикацией нет.

## Установка

Устанавливает пакеты программа <Term id="pip">pip</Term> (читается «пип») — она идёт вместе с Python. Команду набирают не в Python, а в терминале — окне, где программы запускают текстовыми командами:

```
python -m pip install requests==2.32.3
```

`python -m pip` — запустить модуль `pip` как скрипт: флаг `-m` (от module) велит Python найти модуль по имени и выполнить его с `__name__`, равным `"__main__"`. Дальше — команда `install` и что поставить: пакет `requests` версии ровно `2.32.3`. Вывод на компьютере (сокращён):

```
Collecting requests==2.32.3
Collecting charset-normalizer<4,>=2 (from requests==2.32.3)
...
Installing collected packages: urllib3, idna, charset-normalizer, certifi, requests
Successfully installed certifi-2026.11.20 charset-normalizer-3.5.2 idna-3.20 requests-2.32.3 urllib3-2.8.0
```

Просили один пакет, а установилось пять. `requests` сам пользуется чужим кодом, и pip ставит этот код тоже. Это <Term id="dependency">зависимости</Term>: пакеты, без которых этот пакет не работает. У зависимостей бывают свои зависимости, и проект тянет за собой целое дерево. Рядом с каждой — какие версии нужны `requests`:

```
ваш проект
└── requests 2.32.3
    ├── charset-normalizer   <4,>=2
    ├── idna                 <4,>=2.5
    ├── urllib3              <3,>=1.21.1
    └── certifi              >=2017.4.17
```

## Установили, а import не находит

Пакеты устанавливаются в папку того Python, который запустил pip. Если на компьютере два Python, а программу запускают не тем, в который ставили пакет, `import requests` упадёт с `ModuleNotFoundError: No module named 'requests'`: Python не нашёл модуль ни рядом с программой, ни в стандартной библиотеке, ни среди пакетов *своей* папки. Поэтому пишут `python -m pip`, а не просто `pip`: слово `pip` может принадлежать другому Python, а так пакет точно попадёт к тому, что запускается словом `python`.

## Что значат три числа

Каждый выпуск пакета получает номер версии. Многие пакеты нумеруют выпуски по правилам **семантического версионирования** (semver.org), `MAJOR.MINOR.PATCH` — основная, дополнительная, исправление. PATCH растёт (2.32.3 → 2.32.4), когда исправлены ошибки; MINOR (→ 2.33.0) — когда добавлены возможности, а старое не тронуто; MAJOR (→ 3.0.0) — когда изменения несовместимы и ваш код может сломаться. Это договорённость, а не закон: автор может её нарушить.

## Как читать ограничения

Теперь ограничения из дерева можно прочитать (правила их записи — в PEP 440):

- `requests==2.32.3` — ровно эта версия;
- `certifi>=2017.4.17` — эта или новее;
- `charset-normalizer<4,>=2` — от 2 включительно до 4, без самой 4. Запятая значит «и»: оба условия сразу. С будущей несовместимой версией 4 авторы `requests` работу не обещают.

Версии сравниваются по частям, как числа, а не как строки: `2.10` новее `2.9`, потому что 10 > 9.

## Чтобы проект запустился у другого

У коллеги не установлен `requests`, а `urllib3` — другой версии. Поэтому список того, что нужно проекту, записывают в **файл зависимостей**. Самый простой — `requirements.txt`, по пакету с версией на строку:

```
certifi==2026.11.20
charset-normalizer==3.5.2
idna==3.20
requests==2.32.3
urllib3==2.8.0
```

Так его записывает `python -m pip freeze > requirements.txt`: все установленные пакеты с точными версиями, по алфавиту. Знак `>` направляет вывод команды в файл; такие перенаправления разберём в разделе «Терминал Linux». Установить всё по списку — `python -m pip install -r requirements.txt`. Точные версии — главное условие, чтобы через год проект поставился таким же; ещё нужна та же версия Python — её указывают в README.

## Два проекта — две версии

Один проект написан под `pandas` 1.5, другой — под 2.2. В общей папке Python версия может быть только одна: поставили 2.2 для нового проекта — старый сломался. А `pip freeze` выдаст пакеты всех проектов вперемешку.

<Theorem kind="definition" title="Виртуальное окружение"
  formal="Виртуальное окружение — самодостаточное дерево каталогов, которое содержит установку Python определённой версии и набор дополнительных пакетов. Разные приложения могут использовать разные виртуальные окружения; пакеты, установленные в одно окружение, не влияют на другие."
  source="Python Tutorial, 12.1 «Introduction» в главе «Virtual Environments and Packages» (пересказ)">

<Term id="virtual-environment">Виртуальное окружение</Term> (англ. virtual environment, коротко — venv) — отдельная папка проекта со своими пакетами. Python в ней не новый: окружение ссылается на уже установленный Python и опирается на него. У каждого проекта своё окружение: в одном `pandas` 1.5, в другом 2.2, и они друг другу не мешают.

</Theorem>

Окружение привязано к вашему компьютеру: его папку не передают другим и не отправляют в Git — передают `requirements.txt`. Команды в PowerShell на Windows:

```
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Первая создаёт окружение в папке `.venv` — снова модуль, запущенный как скрипт. Вторая включает его (в cmd — `.venv\Scripts\activate.bat`, на Linux — `source .venv/bin/activate`): теперь слово `python` в этом окне терминала означает Python окружения, и pip ставит пакеты туда. Третья ставит зависимости проекта. Создавать окружения — через `venv` и через отдельно устанавливаемую программу `uv` — будете в разделе «Скрипты и окружение разработчика», а файл описания проекта `pyproject.toml` появится в разделе «Качество и упаковка» дисциплины «Инженерный Python».

## Установка — это доверие

Пакет — чужой код, и он выполняется на вашем компьютере: импорт выполняет файл модуля, а установка иногда запускает код автора ещё раньше. Злоумышленник может выложить на PyPI пакет с именем-опечаткой: `reqeusts` вместо `requests`. Ошибётесь в одной букве — установите его код, а он получит доступ ко всем вашим файлам и ключам. В 2017 году на PyPI так нашли десяток пакетов, например `urlib3` вместо `urllib3`.

<Mark>Пишите `python -m pip`, фиксируйте версии, сверяйте имя пакета с документацией.</Mark> Перед установкой незнакомого пакета:

- **Сверьте имя** по документации или README, а не по памяти и не по совету из чата. Ассистент тоже ошибается и иногда называет пакеты, которых нет, — а такое имя может занять злоумышленник.
- **Посмотрите страницу на pypi.org:** даты выпусков, ссылка на исходный код. Пакет, выложенный неделю назад, с именем «почти как у известного», — повод остановиться.
- **Указывайте версии** в файле зависимостей: новая версия не придёт сама, без вашего решения.

Подробнее о рисках чужих зависимостей — в разделе «Безопасность приложений» дисциплины «Безопасность и этика ИИ».

## Как пакетом пользоваться

Начинают с README: почти всегда там есть короткий пример. Для `requests` он может выглядеть так:

```python
>>> import requests
>>> r = requests.get("https://example.com")
>>> r.status_code
200
```

Так записывают сеанс в интерактивном Python: после `>>>` — что ввели, ниже — что Python ответил. Видно, как импортировать, что вызвать (`requests.get` скачивает страницу) и что у результата есть `status_code` — код ответа сайта; 200 значит «всё в порядке».
