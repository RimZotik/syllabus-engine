## Сначала поищите готовое

Вместе с Python устанавливается больше двухсот модулей. Про Python говорят: «батарейки в комплекте» (англ. batteries included) — для частых задач всё уже есть.

<Term id="standard-library">Стандартная библиотека</Term> — модули, которые поставляются вместе с Python и доступны через `import` без установки. Так её описывает сама документация Python (раздел «The Python Standard Library»). Что-то из неё вы уже знаете, остальное — карта на будущее:

## Как читать документацию

Документация — на docs.python.org, раздел «Library Reference». Запись о функции начинается с её заголовка — имени и параметров:

```
random.randint(a, b)
    Return a random integer N such that a <= N <= b.
```

Читают её по частям: имя с модулем, параметры в скобках, текст — что возвращает. Деталь `a <= N <= b` значит: **обе** границы входят, в отличие от `range(a, b)`. Под описанием часто есть примеры — их стоит запустить. Короткую справку в песочнице покажет `help(random.randint)`.

## Тот же подсчёт, готовый

Частоты слов вы считали так: `counts[w] = counts.get(w, 0) + 1` в цикле. Модуль `collections` — «коллекции» — даёт для этого `Counter`:

```python
from collections import Counter

words = "мама мыла раму мама".split()
counts = Counter(words)
print(counts)
print(counts["мама"], counts["папа"])
print(counts.most_common(2))
```

```
Counter({'мама': 2, 'мыла': 1, 'раму': 1})
2 0
[('мама', 2), ('мыла', 1)]
```

`Counter` — разновидность словаря: ключи — то, что считали (здесь слова), значения — сколько раз каждое встретилось. `items()`, `in`, перебор работают как у словаря. Отличия такие:

- **Отсутствующий ключ — ноль, а не `KeyError`.** `counts["папа"]` даёт `0`, и пару при этом не создаёт.
- **`most_common(n)`** — список из `n` пар (элемент, сколько раз), от частых к редким. Это сортировка по количеству, которую вы писали с `key`. Пары с равным количеством идут в том порядке, в каком элементы впервые встретились: «мыла» раньше «раму».
- **`counts.update(список)`** прибавляет к счётчикам, а не заменяет значения, как `update` у словаря.

## Пустой список появляется сам

Группировку учеников по группам вы писали с проверкой «если группы ещё нет, завести пустой список». `defaultdict` («словарь со значением по умолчанию») заводит его сам:

```python
from collections import defaultdict

students = [{"name": "Аня", "group": "9А"}, {"name": "Борис", "group": "9Б"}, {"name": "Вера", "group": "9А"}]
by_group = defaultdict(list)
for s in students:
    by_group[s["group"]].append(s["name"])
print(dict(by_group))
```

```
{'9А': ['Аня', 'Вера'], '9Б': ['Борис']}
```

В скобках `defaultdict(list)` — функция `list` без вызова, как `key=len` в сортировке: её вызовут, когда понадобится значение для нового ключа. `list()` даёт пустой список, `int()` — ноль, поэтому для сумм пишут `defaultdict(int)`. Для печати переводят в обычный словарь, `dict(by_group)`, иначе `print` покажет `defaultdict(<class 'list'>, {...})`.

<Callout kind="warning" title="Ловушка: чтение тоже создаёт ключ">
Обращение `by_group["10А"]` к отсутствующему ключу не падает: оно создаёт пару `"10А": []` и возвращает пустой список. После такой «проверки» в словаре появляется лишняя группа. Есть ли ключ, проверяют через `in`: `"10А" in by_group` пары не создаёт. У `Counter` такого нет — там чтение пару не создаёт.
</Callout>

## Функции модуля random

`random.randint(1, 6)` — целое от 1 до 6 включительно, `random.choice(names)` — случайный элемент списка, `random.sample(names, 2)` — два элемента без повторного выбора одного и того же, `random.random()` — дробное от 0 до 1, без 1. `random.shuffle(names)` перемешивает сам список и, как `list.sort()`, возвращает `None`: `names = random.shuffle(names)` теряет список. Вывод при каждом запуске свой.

## Откуда берётся случайность

Монетки в компьютере нет: `random` вычисляет следующее число из внутреннего состояния, а состояние после этого меняется.

<Theorem kind="definition" title="Псевдослучайные числа и seed"
  formal="Модуль random реализует генераторы псевдослучайных чисел. Основной генератор — вихрь Мерсенна; он полностью детерминирован. Функция random.seed(a) инициализирует внутреннее состояние генератора: одинаковое значение seed даёт одинаковую последовательность чисел."
  source="Python docs, модуль random — «random — Generate pseudo-random numbers» (пересказ)">

<Term id="pseudo-random">Псевдослучайные числа</Term> только похожи на случайные: их вычисляет формула, и при одинаковом начале получается одна и та же последовательность. <Term id="random-seed">Seed</Term> (англ. «семя», в работе так и говорят — «сид») — число, которое задаёт это начало: `random.seed(42)`. Без `seed` Python выбирает начало сам, по системным данным, и запуски различаются.

</Theorem>

```python
import random

random.seed(42)
print(random.randint(1, 6), random.randint(1, 6), random.randint(1, 6))
random.seed(42)
print(random.randint(1, 6), random.randint(1, 6), random.randint(1, 6))
```

```
6 1 1
6 1 1
```

<Mark>Без seed запуски различаются; с одинаковым seed — одна и та же последовательность.</Mark> Та же тройка выйдет при каждом запуске с той же версией Python; в другой версии числа `randint` могут отличаться — документация обещает неизменность только для `random()`.

## Зачем повторять случайность

С `seed` проверка со «случайным» ответом проходит каждый раз, а ошибка на случайном наборе данных повторяется и её можно поймать. Так же фиксируют случайное деление данных на обучающую и отложенную выборки, чтобы коллега получил то же разбиение. Но `random.seed` управляет только модулем `random`: у NumPy свой генератор и свой seed — его разберём в разделе «NumPy изнутри» дисциплины «Инструменты анализа данных».

Для паролей `random` не годится: по нескольким сотням выданных чисел восстанавливается состояние, а с ним все следующие числа. Для секретов есть модуль `secrets`.

## Настройки — не в коде

Программа обращается к сервису по секретному ключу доступа. Запишете ключ в код, `SHOP_KEY = "a8f3..."`, — он уйдёт ко всем, кому вы покажете код. А настройки ещё и различаются: у вас проверочный сервис, на сервере — настоящий. Хочется, чтобы код был один, а настройки задавались снаружи.

<Theorem kind="definition" title="Переменная окружения"
  formal="Каждая запущенная программа (процесс) получает от операционной системы окружение — набор переменных окружения: пар «имя = значение», где и имя, и значение — строки. В Python окружение доступно как os.environ — объект, похожий на словарь, со строковыми ключами и значениями."
  source="Python docs, модуль os — «os.environ»; IEEE Std 1003.1 (POSIX), гл. 8 «Environment Variables» (пересказ)">

<Term id="environment-variable">Переменная окружения</Term> — именованная строка, которую программа получает от системы при запуске, вместе с другими. Её задают до запуска, в терминале или в настройках сервера, а программа только читает. Так передают ключи доступа, адреса сервисов, режимы работы.

</Theorem>

```python
import os

os.environ["SHOP_DISCOUNT"] = "5"   # для примера; обычно задают снаружи, до запуска
discount = int(os.environ.get("SHOP_DISCOUNT", "0"))
key = os.environ.get("SHOP_KEY")
print(discount, key)
```

```
5 None
```

- `os.environ.get(имя, по_умолчанию)` — как `get` у словаря. Обязательную переменную читают через `[]`: нет её — программа сразу упадёт с `KeyError: 'SHOP_KEY'`, и причина понятна.
- **Значения — всегда строки.** Как и в CSV, `"5"` — ещё не 5: переводят через `int(...)`.
- Присваивание `os.environ[...]` действует только внутри этой программы и запущенных из неё, в систему оно не попадает.

В песочнице окружение снаружи не задать, поэтому в задачах переменную присваивают в самой программе. Как задавать переменные окружения в терминале, разберём в разделе «Терминал Linux» дисциплины «Компьютер и командная строка».
