## Повторы мешают считать

В библиотеке записывают каждого, кто пришёл, а некоторые приходят по нескольку раз за день. Сколько было *разных* читателей? Можно собрать их шаблоном накопителя с проверкой `not in`, но задача «оставить только разные» встречается так часто, что для неё в Python есть отдельный тип:

```python
guests = ["Аня", "Борис", "Аня", "Вера", "Борис", "Аня"]
print(len(guests), len(set(guests)))
```

```
6 3
```

Функция `set(...)` строит множество из любого набора значений, который можно перебрать в `for`, — списка, кортежа, строки — и отбрасывает повторы.

<Theorem kind="definition" title="Множество"
  formal="Множество (тип set) — неупорядоченная коллекция различных хешируемых значений. Типичные применения — проверка принадлежности, удаление повторов из последовательности и математические операции: пересечение, объединение, разность и симметрическая разность."
  source="Python Standard Library, «Built-in Types», раздел «Set Types — set, frozenset»; Python Tutorial, 5.4 «Sets» (пересказ)">

<Term id="set">Множество</Term> (тип `set`) — набор значений без повторов и без порядка. «Дважды» или «на третьем месте» не бывает. Что значит «хешируемых», разберём в этой теме чуть позже; пока достаточно знать, что числа, строки и кортежи из них могут быть элементами множества, а списки — нет.

</Theorem>

Множество записывают в фигурных скобках: `{3, 1, 2}`. Повторы в такой записи тоже отбрасываются.

<Callout kind="warning" title="Ловушка: {} — не пустое множество">
Пустые фигурные скобки `{}` — это пустой **словарь**. Пустое множество пишут так: `set()`, и так же Python его выводит.
</Callout>

## В каком порядке выведется?

```python
print(set(["Аня", "Борис", "Аня", "Вера"]))
```

```
{'Борис', 'Вера', 'Аня'}
```

Порядок не тот, в каком значения записали, а при следующем запуске он может стать другим. Это не ошибка: множество порядка не хранит. У словаря порядок добавления сохраняется, у множества — нет.

Раз порядка нет, нет и индексов: `s[0]` даёт `TypeError: 'set' object is not subscriptable` — «множество не поддерживает обращение по индексу». Срезов тоже нет. Зато работает всё, для чего порядок не нужен: `len(s)`, `x in s`, `sum`, `min`, `max`, цикл `for x in s` — в неизвестном заранее порядке.

Нужен порядок — сделайте список: `sorted(s)` вернёт элементы по возрастанию, при каждом запуске одинаково. Так результат выводят и проверяют.

Множества равны, если в них одни и те же элементы: `{1, 2} == {2, 1}` даёт `True`. А `[1, 2] == [2, 1]` — `False`: у списка порядок — часть значения.

## Добавить и убрать

Множество можно менять. Учёт выданных промокодов:

```python
codes = {"A17", "B05"}
codes.add("C33")
codes.add("A17")
codes.remove("B05")
codes.discard("Z99")
print(sorted(codes))
```

```
['A17', 'C33']
```

- `add(x)` добавляет элемент; если он уже есть, ничего не происходит.
- `remove(x)` убирает элемент; если его нет — `KeyError`, та же ошибка, что у словаря без такого ключа.
- `discard(x)` убирает молча, даже если элемента нет.

Как и методы, меняющие список, все три возвращают `None`.

## Список не может быть элементом

ИИ-ассистент предложил хранить пройденный маршрут списком из двух городов:

```python
visited = set()
visited.add(["Казань", "Самара"])
```

```
Traceback (most recent call last):
  File "C:\work\trip.py", line 2, in <module>
    visited.add(["Казань", "Самара"])
TypeError: unhashable type: 'list'
```

Снизу вверх: «нехешируемый тип: list», строка кода 2. Эта ошибка знакома вам по ключам словаря: словарь находит пару по числу, вычисленному из ключа, и множество хранит элементы так же. Теперь подробнее.

Представьте камеру хранения, где номер ячейки не выдают по порядку, а вычисляют по самой вещи. Пришли за той же вещью — посчитали номер ещё раз и сразу открыли нужную ячейку, не перебирая остальные. Но если вещь за это время изменилась, номер выйдет другой, и откроется не та ячейка.

Множество устроено так же. По каждому значению Python вычисляет число — <Term id="hash">хеш</Term> — и по нему решает, в каком месте хранить значение. У равных значений хеш одинаковый: `hash("сыр") == hash("сыр")` даёт `True`. Если изменить элемент на месте, изменится его хеш, и множество будет искать элемент не там.

Поэтому элементами множества бывают только <Term id="hashable">хешируемые</Term> значения — те, хеш которых не меняется, пока значение существует. Среди встроенных типов это неизменяемые: числа, строки и кортежи из неизменяемых значений. Список, словарь и само множество изменяемы — они нехешируемы. Не подойдёт и кортеж `("Аня", [5, 4])`: список внутри кортежа меняется. Ключи словаря подчиняются тому же правилу.

Маршрут — запись из двух полей, то есть кортеж: `visited.add(("Казань", "Самара"))` работает.

## Перебор против хеша

Сайт запрещает самые простые пароли, а их в списках утечек — миллионы. `password in banned` для **списка** — это цикл поиска, который вы писали сами: если пароля нет, Python сравнит его со всеми элементами. В списке из миллиона паролей — миллион сравнений. Для **множества** Python вычисляет хеш пароля и сразу смотрит в то место, где такой пароль хранился бы. В среднем сравнений несколько, сколько бы элементов ни было.

<Mark>Если по одним и тем же данным много раз спрашивают «есть ли?», их один раз превращают в множество.</Mark> Построить множество — один проход по списку, зато потом каждая проверка почти мгновенна. ## Кто ходит в оба кружка

```python
chess = {"Аня", "Борис", "Вера", "Глеб"}
football = {"Борис", "Глеб", "Дима"}
print(sorted(chess & football))
print(sorted(chess | football))
print(sorted(chess - football))
print(sorted(chess ^ football))
```

```
['Борис', 'Глеб']
['Аня', 'Борис', 'Вера', 'Глеб', 'Дима']
['Аня', 'Вера']
['Аня', 'Вера', 'Дима']
```

<Theorem kind="rule" title="Операции над множествами"
  formal="a | b — объединение; a & b — пересечение; a - b — разность: элементы a, которых нет в b; a ^ b — симметрическая разность: элементы ровно одного из множеств; a <= b — проверка, что каждый элемент a есть в b. Операции, кроме <=, возвращают новое множество."
  source="Python Standard Library, «Built-in Types», раздел «Set Types — set, frozenset»; Python Tutorial, 5.4 «Sets» (пересказ)">

- `a & b` — **пересечение**: кто ходит в оба кружка;
- `a | b` — **объединение**: кто ходит хотя бы в один;
- `a - b` — **разность**: кто ходит в шахматы, но не в футбол;
- `a ^ b` — **симметрическая разность**: кто ходит ровно в один; `^` здесь не степень (степень — `**`);
- `a <= b` — **проверка подмножества**: `True`, если всё из `a` есть и в `b`. Например, `need <= have` — хватит ли продуктов на блины.

</Theorem>

Разность зависит от порядка: `football - chess` — это Дима. Исходные множества операции не меняют. Строгие определения множеств и операций над ними — в дисциплине «Язык математики», в разделе «Логика и множества».

## ИИ написал — найдите ошибку

Очередь к врачу: повторные записи убрать, порядок сохранить. ИИ-ассистент написал:

```python
def unique_in_order(queue):
    return list(set(queue))

print(unique_in_order(["Вера", "Аня", "Вера", "Борис", "Аня"]))
```

```
['Борис', 'Аня', 'Вера']
```

Порядок очереди не сохранился: `set` выбросил повторы вместе с порядком. У вас вывод может быть другим — иногда он даже совпадёт с верным, и ошибка спрячется до следующего запуска. В этом и беда.

Исправим: порядок хранит список, а «уже было?» быстро проверяет множество. Предскажите, на что будут указывать `seen` и `result` после третьей итерации, потом пройдите по шагам:

<Trace>

```python
def unique_in_order(queue):
    seen = set()
    result = []
    for name in queue:
        if name not in seen:
            seen.add(name)
            result.append(name)
    return result

print(unique_in_order(["Вера", "Аня", "Вера", "Борис", "Аня"]))
```

</Trace>

Элементы множества в блоке справа показаны по алфавиту — только для удобства.
