  explain="backup = marks не копирует список, а привязывает к нему второе имя. append меняет этот единственный список, и через backup видно то же изменение."

Пройдите программу по шагам. У каждого списка в блоке справа есть номер: по нему видно, одно это значение или разные. Следите — у обоих имён номер будет один.

<Trace>

```python
marks = [5, 4, 3]
backup = marks
marks.append(2)
print(backup)
```

Правая часть в `backup = marks` — уже существующий список, поэтому нового не появляется: к старому привязывается второе имя.

Когда на одно значение указывают несколько имён, каждое из них называют <Term id="alias">псевдонимом</Term> этого значения (англ. alias; само явление — aliasing). Вы их уже встречали: параметр функции — псевдоним аргумента, поэтому `add_item(cart, item)` могла дописать товар в чужую корзину.

<Mark>Присваивание никогда не копирует значение: оно привязывает ещё одно имя к тому же значению.</Mark>

## Почему со строками такого не бывает

```python
name = "кот"
other = name
name += "ик"
print(name, other)
```

```
котик кот
```

Строку изменить нельзя, поэтому `name += "ик"` собирает **новую** строку и привязывает к ней `name`, а `other` указывает на старую.

<Theorem kind="definition" title="Изменяемые и неизменяемые значения"
  formal="Значения, содержимое которых может меняться, называют изменяемыми; значения, содержимое которых после создания изменить нельзя, — неизменяемыми. Изменяемость определяется типом значения: числа, строки и кортежи неизменяемы, а словари и списки изменяемы. Кортеж, который содержит изменяемое значение, всё равно считается неизменяемым: его элементы нельзя заменить, но сами вложенные значения меняться могут."
  source="Python Language Reference, 3.1 «Objects, values and types» (пересказ)">

<Term id="mutable">Изменяемое значение</Term> можно поменять на месте: заменить элемент, дописать, удалить. Таковы списки и словари (их разберём в следующей теме). <Term id="immutable">Неизменяемое значение</Term> — `int`, `float`, `bool`, `str`, `tuple`, `None` — «изменить» можно, только собрав новое значение и привязав к нему имя.

</Theorem>

Отсюда главное: два действия выглядят похоже, но это разные вещи.

- **Изменить значение**: `marks.append(2)`, `marks[0] = 4`. Значение то же, содержимое другое — это видно через **все** его имена.
- **Привязать имя заново**: `marks = [4, 4]`, `name = name + "ик"`. Новое значение получает только это имя, остальные указывают на старое.

С неизменяемыми значениями возможно только второе, поэтому псевдонимы безопасны для чисел и строк, а для кортежа — если все его элементы неизменяемы. Вот почему нужна оговорка про кортеж:

```python
t = ("Аня", [5, 4])
t[1].append(3)
print(t)
```

```
('Аня', [5, 4, 3])
```

Кортеж неизменяем — его элементы нельзя заменить, — но список внутри него меняться может. Такой кортеж не может быть ключом словаря (словари — в следующей теме) или элементом множества; почему — узнаете в теме «Множества».

## Коварный +=

Для списка `a += [3]` — это не «собрать новый и привязать», а «изменить на месте», как `extend`:

```python
a = [1, 2]
b = a
a += [3]
print(b)
a = a + [3]
print(b)
```

```
[1, 2, 3]
[1, 2, 3]
```

После `a += [3]` изменение видно и через `b`: список один. А `a = a + [3]` собирает новый список и привязывает к нему только `a`. Для строк и кортежей `+=` всегда собирает новое значение.

## Равны или один и тот же?

Два списка могут быть равны и при этом быть разными списками:

```python
x = [1, 2, 3]
y = [1, 2, 3]
z = x
print(x == y, x is y, z is x)
```

```
True False True
```

<Theorem kind="rule" title="is и =="
  formal="Операторы is и is not проверяют тождество значений: x is y истинно тогда и только тогда, когда x и y — одно и то же значение. Оператор == сравнивает содержимое значений."
  source="Python Language Reference, 6.10.1 «Value comparisons» и 6.10.3 «Identity comparisons» (пересказ)">

- `x == y` — **равны ли** значения: одинаковое ли у них содержимое.
- `x is y` — **это одно и то же значение?** Указывают ли оба имени на одно и то же.

</Theorem>

`x` и `y` — два равных, но разных списка: допишите элемент в `x` — `y` останется прежним. А `z` — псевдоним `x`. Совпадение «одно и то же значение» в документации Python называют тождеством (англ. identity).

## Почему None проверяют через is

`None` в программе ровно одно, поэтому `result is None` точно отвечает на вопрос «это None?». А в своих типах (о них — в дисциплине «Объектно-ориентированное программирование») программист задаёт смысл `==` сам, и `== None` может удивить. Смысл `is` поменять нельзя.

<Callout kind="warning" title="Ловушка: is вместо ==">
`is` нужен для `None` и для вопроса «это одно и то же значение?», например, псевдонимы ли два имени. Числа и строки через `is` не сравнивают: равные числа и строки могут оказаться разными значениями. На `x is 1000` Python даже выводит предупреждение `SyntaxWarning: "is" with 'int' literal. Did you mean "=="?` — «Вы имели в виду "=="?».
</Callout>

</Page>

## Настоящая копия

Нужен новый список с теми же элементами:

```python
marks = [5, 4, 3]
backup = marks.copy()    # или marks[:], или list(marks)
marks.append(2)
print(marks, backup)
```

```
[5, 4, 3, 2] [5, 4, 3]
```

## Список в списке

Таблица оценок: строка таблицы — внутренний список (не путайте с типом `str`).

```python
table = [[5, 4], [3, 5]]
backup = table.copy()
backup[0][0] = 2
print(table)
```

```
[[2, 4], [3, 5]]
```

`table.copy()` создал новый внешний список, но его элементы указывают на **те же самые** внутренние списки — проверьте по шагам: у них один номер.

<Trace>

```python
table = [[5, 4], [3, 5]]
backup = table.copy()
backup[0][0] = 2
print(table)
```

</Trace>

Такую копию называют <Term id="shallow-copy">поверхностной</Term> (англ. shallow copy): новый только внешний список, а элементы общие. Для чисел и строк этого достаточно. Если элементы изменяемые, нужна <Term id="deep-copy">глубокая копия</Term> (англ. deep copy): копируется и всё изменяемое внутри. Её делает функция `deepcopy` из модуля `copy` (модуль — не то же, что метод `copy` у списка):

```python
import copy

table = [[5, 4], [3, 5]]
backup = copy.deepcopy(table)
backup[0][0] = 2
print(table, backup)
```

```
[[5, 4], [3, 5]] [[2, 4], [3, 5]]
```

<Callout kind="warning" title="Ловушка: [[0] * 3] * 3">
Таблица нулей, собранная как `grid = [[0] * 3] * 3`, выглядит правильно, но после `grid[0][0] = 1` получится `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`: умножение повторило **один и тот же** внутренний список. Строки таблицы создают по отдельности — в цикле три раза `grid.append([0] * 3)`.
</Callout>

## Не портите аргумент

ИИ-ассистент написал функцию «три самые дорогие покупки». Найдите, что в ней не так:

```python
def top3(prices):
    prices.sort(reverse=True)
    return prices[:3]

receipt = [120, 45, 300, 89, 210]
print(top3(receipt), receipt)
```

```
[300, 210, 120] [300, 210, 120, 89, 45]
```

Ответ верный, но порядок в `receipt` потерян: `prices` — псевдоним `receipt`, и `sort` переставил сам список. Это побочный эффект, о котором по имени функции не догадаться. Исправление:

```python
def top3(prices):
    return sorted(prices, reverse=True)[:3]
```

Теперь `receipt` не меняется, а функция стала чистой. <Mark>Функция меняет переданный список, только если это её прямая работа и об этом сказано в имени и строке документации.</Mark> Иначе она работает с копией или собирает новый список. А методы, которые меняют список нарочно, как `sort`, возвращают `None` — чтобы никто не подумал, что они вернули новый.

Внутри функции работает то же различие: изменить значение или привязать имя заново. Предскажите, что станет со списком `a`:

## Ловушка: список как значение по умолчанию

Значение по умолчанию вычисляется один раз — когда выполняется `def`. Возьмём функцию «добавить товар в корзину; нет корзины — начать новую» (корзина необязательна, поэтому параметр `cart` стоит вторым):

```python
def add_to_cart(item, cart=[]):
    cart.append(item)
    return cart

print(add_to_cart("хлеб"))
print(add_to_cart("сыр"))
```

```
['хлеб']
['хлеб', 'сыр']
```

Второй покупатель получил хлеб первого: список `[]` создан один раз, при выполнении `def`, и все вызовы без второго аргумента получают его же. Правильно — `None` по умолчанию и новый список внутри функции:

```python
def add_to_cart(item, cart=None):
    if cart is None:
        cart = []
    cart.append(item)
    return cart
```

Теперь оба вызова вернут по одному товару: `['хлеб']` и `['сыр']`.
