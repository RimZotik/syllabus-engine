## Последние три дня

Нужна температура только за последние три дня недели. Срезы строк вы знаете — со списками они работают так же:

```python
temps = [12, 15, 9, -2, 7, 4, 10]
print(temps[-3:])
print(temps[:3])
print(temps[1:3])
```

```
[7, 4, 10]
[12, 15, 9]
[15, 9]
```

<Term id="slice">Срез</Term> `temps[a:b]` — новый список из элементов с индекса `a` до индекса `b`, не включая `b`. Если оба индекса внутри списка, длина среза — `b - a`: в `temps[1:3]` два элемента, а не три. Здесь легко ошибиться на единицу, как с `range`: конец не входит.

У среза есть третье число — **шаг**: `temps[a:b:k]` берёт каждый `k`-й элемент (у строк тоже).

```python
temps = [12, 15, 9, -2, 7, 4, 10]
print(temps[::2])
print(temps[::-1])
```

```
[12, 9, 7, 10]
[10, 4, 7, -2, 9, 15, 12]
```

Отрицательный шаг идёт с конца: `temps[::-1]` — список задом наперёд. Исходный список не меняется. А чтобы просто пройти список с конца, не собирая нового списка, пишут `for t in reversed(temps)`.

## Срез не падает

Индекс за границей даёт `IndexError`, а срез за границей берёт то, что есть: `temps[5:100]` даст `[4, 10]`, `temps[10:]` — пустой список. Нужно ровно пять элементов — проверяйте длину сами.

## Методы, которые меняют список

Корзина в магазине:

```python
cart = ["хлеб", "молоко"]
cart.extend(["сыр", "чай"])
cart.insert(0, "яйца")
print(cart)
last = cart.pop()
print(last, cart)
cart.remove("молоко")
print(cart)
```

```
['яйца', 'хлеб', 'молоко', 'сыр', 'чай']
чай ['яйца', 'хлеб', 'молоко', 'сыр']
['яйца', 'хлеб', 'сыр']
```

- `extend(other)` дописывает в конец все элементы другого списка. `append(other)` дописал бы весь список как один элемент.
- `insert(i, x)` вставляет `x` перед элементом с индексом `i`; остальные сдвигаются вправо.
- `pop()` убирает последний элемент и возвращает его; `pop(i)` — элемент с индексом `i`.
- `remove(x)` убирает первый элемент, равный `x`. Если такого нет — `ValueError: list.remove(x): x not in list`.

Не меняют список `cart.count("хлеб")` (сколько раз встречается) и `cart.index("сыр")` (индекс первого такого элемента). Умножение на число собирает новый список с повторами: `print([0] * 3)` выведет `[0, 0, 0]`.

<Callout kind="remember" title="pop — исключение из правила">
Метод, который меняет список, возвращает `None` — так устроены `append`, `extend`, `insert`, `remove`. `pop` — исключение: он меняет список **и** возвращает убранный элемент. Поэтому `last = cart.pop()` — правильный код.
</Callout>

## Сортировка: sort и sorted

```python
marks = [4, 5, 3, 5]
print(sorted(marks), marks)
marks.sort()
print(marks)
```

```
[3, 4, 5, 5] [4, 5, 3, 5]
[3, 4, 5, 5]
```

`sorted(marks)` возвращает **новый** список. `marks.sort()` переставляет элементы в самом списке и возвращает `None`, поэтому `marks = marks.sort()` теряет список. `reverse=True` у обоих даёт порядок от большего к меньшему. Сортировку по своему правилу разберём в теме «Функции как значения и lambda».

## Обещанный разбор

Добавлять и удалять элементы, пока по списку идёт `for`, нельзя. Посмотрим почему: уберём из выручки дни с нулём. Предскажите, что выведет программа, — результат может удивить, ошибиться здесь нормально. Потом пройдите её по шагам:

<Trace>

```python
sales = [0, 0, 500, 0, 900]
for s in sales:
    if s == 0:
        sales.remove(s)
print(sales)
```

</Trace>

Выведется `[500, 0, 900]`. Цикл `for` по списку помнит не элемент, а индекс: 0, потом 1, потом 2. После первого `remove` элементы сдвинулись влево, второй ноль встал на индекс 0, а цикл взял индекс 1 — `500`. На индексе 2 цикл нашёл ноль, но `remove` убрал первый ноль в списке, а не тот, на который указывает `s`. Ноль остался.

Сообщения об ошибке нет: программа молча выдаёт неверный ответ, а это хуже, чем traceback. Решение — завести пустой список `nonzero` и в том же цикле дописывать туда ненулевые дни: получится `[500, 900]`.

<Mark>Пока по списку идёт цикл, длину списка не меняют: нужный результат собирают в новый список.</Mark> Заменять элементы по индексу при этом можно — длина не меняется.

</Page>

## Запись из нескольких полей

Дата — ровно три числа: день, месяц, год. Добавлять и удалять в ней нечего, поэтому для таких записей есть другой тип:

```python
birthday = (12, 4, 2008)
print(birthday[0], len(birthday), type(birthday))
```

```
12 3 <class 'tuple'>
```

<Theorem kind="definition" title="Кортеж"
  formal="Кортеж — неизменяемая последовательность из нескольких значений, разделённых запятыми. Кортежи обычно содержат разнородные элементы, к которым обращаются распаковкой или по индексу; списки обычно однородны, и их элементы перебирают."
  source="Python Tutorial, 5.3 «Tuples and Sequences» (пересказ)">

<Term id="tuple">Кортеж</Term> (тип `tuple`) — последовательность, элементы которой после создания нельзя заменить, добавить или удалить. Индексы, срезы, `len`, `in`, цикл `for` — всё как у списка. Что будет, если элемент кортежа — список, разберём в теме об изменяемых и неизменяемых значениях.

</Theorem>

Попробуем исправить месяц:

```python
birthday = (12, 4, 2008)
birthday[1] = 5
```

```
TypeError: 'tuple' object does not support item assignment
```

«Кортеж не поддерживает присваивание элементу». Такую же ошибку дают строки (тип `str`). Методов `append`, `pop`, `sort` у кортежа нет. Дату собирают заново и привязывают к ней имя: `birthday = (12, 5, 2008)`.

<Callout kind="warning" title="Ловушка: кортеж из одного элемента">
Кортеж делает **запятая**, а не скобки: `(5)` — просто число 5 в скобках, а кортеж из одного элемента — `(5,)`. И `point = 3, 4` без скобок — уже кортеж.
</Callout>

## Разложить запись по именам

Что такое `birthday[2]`, сразу не скажешь. Лучше дать каждому полю имя:

```python
birthday = (12, 4, 2008)
day, month, year = birthday
print(day, month, year)
```

```
12 4 2008
```

<Theorem kind="definition" title="Распаковка"
  formal="Распаковка последовательности — присваивание, в котором слева стоят несколько имён через запятую, а справа — последовательность. Имён слева должно быть столько же, сколько элементов в последовательности."
  source="Python Tutorial, 5.3 «Tuples and Sequences» (sequence unpacking, пересказ)">

<Term id="unpacking">Распаковка</Term> — присваивание сразу нескольким именам: первое имя привязывается к первому элементу, второе — ко второму, и так далее. Распаковать можно кортеж, список, строку — всё, что перебирается в `for`.

</Theorem>

Число имён должно совпасть с числом элементов. Строка ввода «Аня 5 4» состоит из трёх слов, а имён два:

```python
line = "Аня 5 4"
name, mark = line.split()
```

```
Traceback (most recent call last):
  File "C:\work\marks.py", line 2, in <module>
    name, mark = line.split()
    ^^^^^^^^^^
ValueError: too many values to unpack (expected 2)
```

«Слишком много значений для распаковки (ожидалось 2)».

## Обмен без временного имени

Помните, как меняли местами `a` и `b` через `temp`? С распаковкой это одна строка кода:

```python
a, b = 1, 2
a, b = b, a
print(a, b)
```

```
2 1
```

Правая часть `b, a` — кортеж `(2, 1)`, собранный **до** того, как имена привяжут заново, поэтому ничего не теряется.

## Функция возвращает два значения

Функция может вернуть только одно значение. Но это значение может быть кортежем:

```python
def min_max(temps):
    return min(temps), max(temps)

low, high = min_max([12, 15, 9, -2, 7])
print(low, high)
```

```
-2 15
```

`return min(temps), max(temps)` возвращает один кортеж `(-2, 15)`, а распаковка раскладывает его по двум именам. Именно это в Python и называют «функция возвращает несколько значений».

## Номер и элемент сразу

Вместо `for i in range(len(names))` и `names[i]` номер и элемент вместе даёт функция `enumerate`:

```python
names = ["Аня", "Борис", "Вера"]
for n, name in enumerate(names, start=1):
    print(f"{n}. {name}")
```

```
1. Аня
2. Борис
3. Вера
```

`enumerate` выдаёт кортежи `(1, 'Аня')`, `(2, 'Борис')`…, и каждый распаковывается в два имени цикла. Без `start` счёт идёт с нуля.

## Два списка параллельно

Имена — в одном списке, оценки — в другом, в том же порядке. Функция `zip` идёт по обоим сразу и на каждом шаге даёт пару. Предскажите вывод, потом проверьте по шагам:

<Trace>

```python
names = ["Аня", "Борис", "Вера"]
marks = [5, 4, 3]
for name, mark in zip(names, marks):
    print(name, mark)
```

</Trace>

Если списки разной длины, `zip` останавливается на самом коротком, а лишние элементы молча пропускает. Потерянную оценку никто не заметит, поэтому длины проверяют заранее.

`zip` и `enumerate` выдают элементы по одному, по мере перебора, поэтому `print(zip(names, marks))` покажет лишь `<zip object at 0x…>`. Функция `list(...)` строит список из всего, что перебирается в `for`: `list(zip(names, marks))` даёт `[('Аня', 5), ('Борис', 4), ('Вера', 3)]`.

Перебрать результат `zip` или `enumerate` можно только один раз: второй `for` или второй `list(...)` не получит ничего. Нужен результат несколько раз — сохраните `list(zip(...))`. Почему так, разберём в дисциплине «Инженерный Python».
