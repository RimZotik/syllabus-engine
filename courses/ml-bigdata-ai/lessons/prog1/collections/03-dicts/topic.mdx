## Два списка — неудобно

Цены в магазине можно хранить двумя списками: `names = ["молоко", "хлеб", "сыр"]` и `prices = [89, 45, 320]`. Чтобы узнать цену хлеба, придётся найти индекс названия, `names.index("хлеб")`, и по нему взять цену. Добавили товар в один список, а во второй добавить забыли — данные разъехались. Хочется спрашивать сразу: «сколько стоит хлеб?»

```python
prices = {"молоко": 89, "хлеб": 45, "сыр": 320}
print(prices["хлеб"], len(prices))
```

```
45 3
```

<Theorem kind="definition" title="Словарь"
  formal="Словарь — набор пар «ключ: значение», в котором ключи уникальны в пределах одного словаря. В отличие от последовательностей, которые индексируются числами, словарь индексируется ключами; ключом может быть любое неизменяемое значение. Основные операции — сохранить значение под ключом и получить значение по ключу."
  source="Python Tutorial, 5.5 «Dictionaries» (пересказ)">

<Term id="dict">Словарь</Term> (тип `dict`) — набор пар: по <Term id="dict-key">ключу</Term> находится значение. Записывается в фигурных скобках: ключ, двоеточие, значение, пары через запятую. Здесь ключи — названия товаров, значения — цены. В квадратные скобки пишут не номер, а ключ: `prices["хлеб"]`. Ключом может быть и число, но это не позиция: в `d = {10: "a"}` запрос `d[0]` даст `KeyError`, а не первую пару.

</Theorem>

У слова «значение» здесь два смысла. В общем смысле значение — любые данные программы. А «значение словаря» — вторая половина пары, то, с чем связан ключ. Из контекста всегда понятно, о чём речь.

Ключи в словаре не повторяются: каждый ключ связан с одним значением. Значения повторяться могут — у двух товаров может быть одна цена. Пустой словарь — `{}`, в условии он ложен, как пустой список.

</Page>

## Присваивание по ключу

```python
prices = {"молоко": 89, "хлеб": 45, "сыр": 320}
prices["чай"] = 150
prices["хлеб"] = 50
del prices["молоко"]
print(prices)
```

```
{'хлеб': 50, 'сыр': 320, 'чай': 150}
```

- `prices["чай"] = 150` — такого ключа не было, пара добавилась.
- `prices["хлеб"] = 50` — ключ был, значение заменилось. Код одинаковый, а действие зависит от того, есть ли ключ.
- `del prices["молоко"]` — инструкция `del` удаляет пару.

Пары хранятся в том порядке, в котором их добавляли: новый ключ встаёт в конец, а замена значения порядок не меняет. Словарь изменяем, поэтому у него те же ловушки с псевдонимами, что и у списка. А при сравнении `==` порядок не важен: `{"a": 1, "b": 2} == {"b": 2, "a": 1}` даёт `True` — совпадают сами пары.

## Ключа нет — ошибка

Попросим цену товара, которого нет в словаре. Программа `shop.py`:

```python
prices = {"молоко": 89, "хлеб": 45}
print(prices["кофе"])
```

```
Traceback (most recent call last):
  File "C:\work\shop.py", line 2, in <module>
    print(prices["кофе"])
          ~~~~~~^^^^^^^^
KeyError: 'кофе'
```

Снизу вверх: тип ошибки `KeyError` — «ошибка ключа», а после двоеточия — сам ключ, которого не нашлось. Строка кода 2, значки `^` под `["кофе"]`. Словарь не возвращает `None` для отсутствующего ключа — он падает. Так ошибка в названии не проходит незамеченной.

Если отсутствие ключа — обычная ситуация, есть два способа обойтись без ошибки:

- спросить заранее: `"кофе" in prices` — оператор `in` у словаря проверяет **ключи**. `"сыр" in prices` даёт `True`, а `320 in prices` — `False`, хотя такая цена есть. Среди значений ищут так: `320 in prices.values()` даёт `True`;
- метод `get`: `prices.get("кофе")` вернёт `None`, а `prices.get("кофе", 0)` — `0`. Второй аргумент — что вернуть, если ключа нет.

## Ключи, значения, пары

Цикл `for` по словарю перебирает **ключи**. Чтобы получить ключ и значение сразу, используют метод `items()` — он выдаёт пары-кортежи, а распаковка раскладывает их по двум именам цикла:

```python
prices = {"хлеб": 50, "сыр": 320, "чай": 150}
for name, price in prices.items():
    print(f"{name}: {price} руб.")
print(sum(prices.values()))
```

```
хлеб: 50 руб.
сыр: 320 руб.
чай: 150 руб.
520
```

`values()` выдаёт только значения, `keys()` — только ключи. Это не списки: `print(prices.keys())` покажет `dict_keys(['хлеб', 'сыр', 'чай'])`. Перебирать их в `for` и передавать в `sum`, `max`, `sorted` можно. Нужен настоящий список — `list(prices)` даст список ключей.

<Callout kind="warning" title="Ловушка: удалять ключи во время перебора">
Список при такой ошибке молча выдаёт неверный результат, а словарь сразу падает: если в цикле `for k in prices` удалить или добавить ключ, будет `RuntimeError: dictionary changed size during iteration` — «словарь изменил размер во время перебора». Решение то же, что со списком: собрать нужное в новый словарь или перебирать копию ключей, `for k in list(prices)`. Менять значения у существующих ключей можно — размер не меняется.
</Callout>

</Page>

## Сколько раз встречается каждое слово

Одна из самых частых задач с текстом и данными — посчитать, сколько раз встречается каждое значение. Словарь подходит идеально: ключ — слово, значение — счётчик. Это шаблон накопителя, только накопителей много, по одному на каждое слово. Предскажите словарь в конце, потом пройдите программу по шагам:

<Trace>

```python
words = "мама мыла раму мама".split()
counts = {}
for w in words:
    counts[w] = counts.get(w, 0) + 1
print(counts)
```

</Trace>

Выведется `{'мама': 2, 'мыла': 1, 'раму': 1}`. Главная строка кода читается справа налево, как любое присваивание: `counts.get(w, 0)` — сколько уже насчитали (0, если слово встретилось впервые), плюс один, и тот же ключ связывается с результатом.

## Каким может быть ключ

Продажи по городам и годам: ключ — пара «город, год».

```python
sales = {("Москва", 2024): 120, ("Казань", 2024): 85}
print(sales[("Москва", 2024)])
```

```
120
```

С кортежем всё работает. А если ключом сделать список:

```python
sales[["Москва", 2024]] = 50
```

```
TypeError: unhashable type: 'list'
```

<Theorem kind="rule" title="Ключ словаря — неизменяемое значение"
  formal="Ключом словаря может быть любое неизменяемое значение: строки и числа, а также кортежи, если они содержат только строки, числа или кортежи. Списки ключами быть не могут: их можно изменить на месте."
  source="Python Tutorial, 5.5 «Dictionaries» (пересказ)">

Ключи — строки, числа, кортежи из неизменяемых значений. Списки и словари ключами не бывают. Значения — какие угодно, в том числе списки и другие словари. Пока этого правила достаточно.

</Theorem>

Почему так: Python находит пару по числу, которое вычисляет из самого ключа; если бы ключ изменился, это число указывало бы не туда, и пара потерялась бы. `unhashable type` — дословно «нехешируемый тип»: тип, для которого такое число не вычисляют. Подробнее — в теме «Множества».

## Запись — словарь

Журнал — это таблица: у каждой записи (строки таблицы) одни и те же столбцы «имя, группа, оценка». Одну запись удобно хранить словарём, где ключи — названия столбцов. А всю таблицу — списком таких словарей:

```python
students = [
    {"name": "Аня", "group": "9А", "mark": 5},
    {"name": "Борис", "group": "9Б", "mark": 3},
    {"name": "Вера", "group": "9А", "mark": 4},
]
for s in students:
    if s["group"] == "9А":
        print(s["name"], s["mark"])
```

```
Аня 5
Вера 4
```

Читать такой код легко: `s["mark"]` — «оценка этого ученика», а не загадочное `s[2]`. Порядок столбцов неважен, а новый столбец можно добавить, и старый код не сломается.

## Группировка

Задача: списки учеников по группам. Результат — словарь, где ключ — группа, значение — список имён:

```python
by_group = {}
for s in students:
    g = s["group"]
    if g not in by_group:
        by_group[g] = []
    by_group[g].append(s["name"])
print(by_group)
```

```
{'9А': ['Аня', 'Вера'], '9Б': ['Борис']}
```

Если группа встретилась впервые, её ключ связывают с новым пустым списком. Потом в этот список дописывают имя: `by_group[g].append(...)` меняет сам список, связанный с ключом `g`, поэтому присваивать `by_group[g]` заново не нужно.
