## Всё вперемешку

Программа считает сумму чека и даёт скидку 5%, если сумма не меньше 400 рублей:

```python
lines = ["молоко 89", "хлеб 45", "сыр российский 320"]
total = 0
for line in lines:
    parts = line.split()
    total += int(parts[1])
if total >= 400:
    total = total - total * 5 / 100
print(f"Итого: {total:.2f} руб.")
```

```
ValueError: invalid literal for int() with base 10: 'российский'
```

У сыра название из двух слов, поэтому цена — третье слово. В восьми строках это видно сразу. Но представьте программу на сто строк кода, где чтение, разбор, скидки и вывод перемешаны. Чтобы проверить разбор одной строки чека, придётся запускать всю программу. Выход — разбить программу на части, которые можно понять и проверить отдельно.

<Theorem kind="definition" title="Декомпозиция"
  formal="Декомпозиция — разбиение задачи на самостоятельные части, каждую из которых можно понять, проверить и использовать повторно. В программировании декомпозиция достигается, в частности, с помощью функций."
  source="MIT 6.100L «Introduction to CS and Programming Using Python», лекция «Decomposition, Abstraction, Functions» (пересказ)">

<Term id="decomposition">Декомпозиция</Term> — деление большой задачи на маленькие, пока каждую не станет просто решить. Каждая часть — функция с понятным именем, входом и результатом.

</Theorem>

## Сначала план

Помните план в комментариях перед циклом? Здесь то же, только каждый пункт плана становится функцией:

1. Из строки чека достать цену — `item_price(line)`.
2. Сложить цены всех строк — `receipt_sum(lines)`.
3. Применить скидку — `apply_discount(total)`.

```python
def item_price(line):
    words = line.split()
    return int(words[-1])

def receipt_sum(lines):
    total = 0
    for line in lines:
        total += item_price(line)
    return total

def apply_discount(total):
    if total >= 400:
        return total - total * 5 / 100
    return total

lines = ["молоко 89", "хлеб 45", "сыр российский 320"]
total = apply_discount(receipt_sum(lines))
print(f"Итого: {total:.2f} руб.")
```

```
Итого: 431.30 руб.
```

Цену теперь берут из последнего слова, `words[-1]`, — так заодно исправили ошибку: теперь название может состоять из любого числа слов. Если в разборе найдётся ещё ошибка, она может быть только в `item_price`.

Обратите внимание, как устроена программа:

- **Одна функция — одна работа.** Имя — глагол (`apply_discount`) или то, что функция возвращает (`item_price`). Если в имени напрашивается `and` (`parse_and_sum`), функция делает слишком много.
- **Функции считают, программа печатает.** Все три функции чистые, `print` — один, в самом конце.
- **Функции вызывают друг друга.** `receipt_sum` пользуется `item_price`, не зная, как та устроена: изменится формат чека — `receipt_sum` не тронем.

## Проверки — до кода

Каждую часть можно проверить отдельно. Проверки с `assert` удобно придумывать ещё по плану, до кода; в этом разделе их записывают сразу под функциями:

```python
assert item_price("хлеб 45") == 45
assert item_price("сыр российский 320") == 320
assert receipt_sum([]) == 0
assert apply_discount(400) == 380
assert apply_discount(399) == 399
```

Последние две проверки стоят на самой границе и рядом с ней: если вместо `>=` написать `>`, проверка `apply_discount(400) == 380` упадёт — так ловят ошибку на единицу. Писать свои проверки систематически научимся в теме «assert и свои проверки» раздела «Ошибки и отладка».

## Описание для того, кто будет пользоваться функцией

Чтобы пользоваться `len` или `round`, вы не читаете их код: достаточно знать, что они принимают и возвращают. Своим функциям такое описание дают прямо в коде. Текст в тройных кавычках `"""…"""` — обычное строковое значение (`str`), только его можно растянуть на несколько строк кода. Если такой текст стоит первой инструкцией тела функции, это описание:

```python
def item_price(line):
    """Вернуть цену из строки чека.

    line — строка чека вида "название цена"; название может быть из нескольких слов.
    Цена — последнее слово строки, целое число рублей.
    Пример: item_price("сыр российский 320") даёт 320.
    """
    return int(line.split()[-1])

help(item_price)
```

```
Help on function item_price in module __main__:

item_price(line)
    Вернуть цену из строки чека.

    line — строка чека вида "название цена"; название может быть из нескольких слов.
    Цена — последнее слово строки, целое число рублей.
    Пример: item_price("сыр российский 320") даёт 320.
```

Это <Term id="docstring">строка документации</Term> (docstring) — текст в тройных кавычках, первая инструкция тела функции (так её определяет PEP 257). Python запоминает её вместе с функцией. Её покажет встроенная функция `help`: `help(item_price)`, а редакторы кода — во всплывающей подсказке. `__main__` в выводе — так Python называет вашу программу. Комментарий `#` пишут для того, кто читает код, и комментарий внутри тела функции `help` не покажет.

Что писать в строке документации:

- первая строка текста описания — что делает функция, одной фразой; PEP 257 советует для неё форму команды: «Вернуть…»;
- что означают параметры и что возвращается;
- крайние случаи — здесь название из нескольких слов;
- пример вызова с результатом.

Описывают, *что* функция делает, а не *как*: как — видно из кода.

## Подписать типы

Строка документации говорит, что цена — целое число. Это можно записать короче, прямо в строке кода с `def`:

```python
def item_price(line: str) -> int:
    return int(line.split()[-1])

def apply_discount(total: float) -> float:
    if total >= 400:
        return total - total * 5 / 100
    return total

def show_total(total: float) -> None:
    print(f"Итого: {total:.2f} руб.")
```

После параметра через двоеточие — ожидаемый тип аргумента, после `->` — тип возвращаемого значения. Читается: «`item_price` принимает строку и возвращает целое число». Где ждут `float`, подходит и `int`. Функция, которая только печатает, возвращает `None` — так и пишут: `-> None`.

<Theorem kind="definition" title="Аннотация типов (type hints)"
  formal="Аннотация типов (type hints) указывает ожидаемый тип переменной, параметра функции или её возвращаемого значения. Аннотации типов необязательны, Python не проверяет их при выполнении, но полезны инструментам статической проверки типов и помогают в работе редакторам кода."
  source="Python Glossary, «type hint» и «annotation» (пересказ)">

<Term id="type-hint">Аннотация типов</Term> — подпись к параметрам и результату: какие значения функция ждёт и что вернёт. Это подсказка для человека и для программ, а не правило для Python.

</Theorem>

Python аннотации не проверяет. Передайте не тот тип — функция выполнится, как без подписи:

```python
def double(x: int) -> int:
    return x * 2

print(double(21))
print(double("ха"))
```

```
42
хаха
```

Зачем же они нужны? Человек сразу видит, что передавать. Редактор кода подсвечивает подозрительный вызов. А специальные программы проверяют аннотации во всём проекте до запуска — ими займёмся в дисциплине «Инженерный Python». Аннотации пишут всё чаще, особенно в библиотеках и больших проектах.
