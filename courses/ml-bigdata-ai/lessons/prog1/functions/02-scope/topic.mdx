def double_price(price):

У блока «Программа» свой `price`, у блока `double_price()` — свой: два разных имени, которые просто пишутся одинаково. В начале вызова оба указывают на 100, а присваивание внутри функции привязывает заново только внутреннее.

<Theorem kind="rule" title="Где Python ищет имя"
  formal="Имя, которому где-либо в теле функции присваивают значение, локально во всём теле (в том числе переменная цикла for). Каждое присваивание в функции привязывает имя в наборе локальных имён, если имя не указано в инструкции global; при обращении к имени поиск идёт сначала среди локальных имён, затем среди глобальных и, наконец, среди встроенных."
  source="Python Tutorial, 4.8 «Defining Functions»; Python Language Reference, 4.2 «Naming and binding» (пересказ)">

- <Term id="local-variable">Локальные имена</Term> (их ещё называют локальными переменными) — параметры и все имена, которым в теле функции что-то присваивают, включая переменную цикла `for`. Они появляются при вызове и исчезают, когда он заканчивается.
- <Term id="global-variable">Глобальные имена</Term> (глобальные переменные) — те, что заведены в самой программе, вне функций, в том числе имена функций, созданные `def`.
- Python решает, какие имена локальные, когда читает определение функции. Локальное имя ищется **только** среди локальных. Остальные имена — сначала среди глобальных, потом среди встроенных (`print`, `len`, `sum`).

Часть программы, где имя доступно, называют <Term id="scope">областью видимости</Term> имени.

</Theorem>

Функции, определённые внутри других функций, добавляют ещё один уровень поиска; о них — в дисциплине «Инженерный Python».

</Page>

## Снаружи локальных имён не видно

```python
def with_discount(price, percent):
    cut = price * percent / 100
    return price - cut

print(with_discount(1200, 15))
print(cut)
```

```
1020.0
Traceback (most recent call last):
  File "C:\work\shop.py", line 6, in <module>
    print(cut)
          ^^^
NameError: name 'cut' is not defined
```

`cut` — локальное имя: вызов закончился, имя исчезло. Из локальных имён наружу попадает только то, что вернули через `return`.

## Изнутри глобальные видно

В обратную сторону всё иначе: функция может *читать* глобальное имя. Для настроек, которые программа не меняет, это нормально; по PEP 8 их пишут заглавными буквами: `VAT_RATE = 0.2` (ставка НДС). Беда начинается, когда глобальное имя привязывают заново во время работы:

```python
percent = 15

def with_discount(price):
    return price - price * percent / 100

print(with_discount(1200))
percent = 50
print(with_discount(1200))
```

```
1020.0
600.0
```

Один и тот же вызов дал разные ответы, а по самому вызову не понять почему. Надёжнее сделать процент параметром.

<Callout kind="warning" title="Ловушка: встроенное имя внутри функции">
Локальное имя перекрывает одноимённое встроенное во всём теле функции. Если в теле есть `sum = 0`, то `sum([1, 2])` до этой строки кода даст `UnboundLocalError` (что это за ошибка — на следующей странице), а после — `TypeError: 'int' object is not callable`: число, в отличие от функции, вызвать нельзя. Параметр с именем `sum` или `list` тоже перекрывает встроенную функцию.

Когда вызов функции закончится, встроенная `sum` снова будет доступна. А `sum = 0` вне функций сломает встроенную `sum` до конца работы программы. Не называйте свои имена так же, как встроенные.
</Callout>

</Page>

## Настоящий traceback

Счётчик посещений сайта. ИИ-ассистент предложил такой код:

```python
visits = 0

def register():
    visits += 1
    return visits

register()
```

```
Traceback (most recent call last):
  File "C:\work\visits.py", line 7, in <module>
    register()
  File "C:\work\visits.py", line 4, in register
    visits += 1
    ^^^^^^
UnboundLocalError: cannot access local variable 'visits' where it is not associated with a value
```

Теперь пар «файл — номер строки» две. Читаем по-прежнему снизу вверх:

1. **Последняя строка сообщения.** «Нельзя обратиться к локальной переменной `visits`: она ещё не привязана к значению».
2. **Пара `line 4, in register`** — где именно программа упала: внутри функции.
3. **Пара `line 7, in <module>`** — откуда туда пришли: вызов из программы. Подробнее — в разделе «Ошибки и отладка».

**Почему.** Проследим вручную. `visits += 1` — это присваивание `visits = visits + 1`. Читая `def`, Python видит присваивание и делает `visits` локальным во всём теле. При вызове Python в строке 4 сначала вычисляет правую часть, `visits + 1`. Локальный `visits` ещё ни к чему не привязан, а к глобальному `visits` Python внутри этой функции не обращается — ошибка.

## Как исправить

Передайте значение аргументом и верните новое:

```python
def register(visits):
    return visits + 1

visits = 0
visits = register(visits)
visits = register(visits)
print(visits)
```

```
2
```

Есть и инструкция `global`: она разрешает функции присваивать глобальному имени.

```python
visits = 0

def register():
    global visits
    visits += 1

register()
register()
print(visits)
```

```
2
```

Пользуются `global` редко и осознанно: по вызову `register()` не видно, что она что-то меняет, а результат зависит от того, сколько раз её вызывали раньше.

## Список, переданный в функцию

Присваивание параметру внешнее имя не меняет. Но параметр указывает на то же значение, что и аргумент. Если значение — список и функция меняет сам этот список, изменение видно снаружи:

```python
def add_item(cart, item):
    cart.append(item)

my_cart = ["хлеб"]
add_item(my_cart, "молоко")
print(my_cart)
```

```
['хлеб', 'молоко']
```

`cart` и `my_cart` — два имени одного списка, а `append` меняет этот список. По той же причине функция может вызвать `orders.append(x)` для глобального списка без `global`: имени ничего не присваивают. А `orders += [x]` — уже присваивание, и получится `UnboundLocalError`. Как не испортить переданный список — в теме «Изменяемые и неизменяемые значения».

<Theorem kind="definition" title="Чистая функция и побочный эффект"
  formal="Чистая функция не делает ничего, кроме возврата значения, и при одинаковых аргументах всегда возвращает одно и то же. Нечистая функция, помимо возврата значения, производит побочные эффекты — изменения вне самой функции; типичный побочный эффект — вывод текста функцией print."
  source="J. DeNero, «Composing Programs» (курс CS61A, UC Berkeley), 1.2 «Elements of Programming» (пересказ)">

<Term id="pure-function">Чистая функция</Term> — как формула: одни и те же аргументы дают один и тот же результат, а вокруг ничего не меняется. <Term id="side-effect">Побочный эффект</Term> — всё, что вызов делает, кроме возврата значения: печатает на экран, меняет переданный список, присваивает глобальному имени.

</Theorem>

`with_discount(price, percent)` — чистая. `add_item` и `area_print` — нечистые: одна меняет список, другая печатает. Нечистая и вторая версия `with_discount`, без параметра `percent`: она читает глобальный `percent`, который меняется. Читать имена, которые никто не меняет (встроенные и другие функции, константы), чистоте не мешает; вредит чтение значения, которое программа может изменить.

Теперь понятно, почему `print` и `append` возвращают `None`: они работают ради побочного эффекта, отдавать им нечего. Так принято у встроенных методов, которые меняют сам список: `s.upper()` возвращает новую строку, а `cart.append(x)` меняет список и возвращает `None`. Исключения есть — метод `pop` вы встретите в «Коллекциях».

## Зачем стремиться к чистоте

- Чистую функцию легко проверить: `assert with_discount(1200, 15) == 1020.0` верно, где бы и когда бы её ни вызвали. Здесь результат точный, поэтому `==` годится; дробные результаты в общем случае сравнивают через `math.isclose`.
- Её легко читать: всё, от чего зависит результат, видно в вызове.
- Без побочных эффектов не обойтись: программа должна что-то вывести. Но их собирают в одном месте — считают чистые функции, а печатает программа снаружи.
