## Две двери, через которые приходит ошибка

Ошибаются все программисты, каждый день. Разница между новичком и опытным разработчиком не в том, что второй не ошибается, а в том, что он читает сообщение об ошибке и за минуту понимает, где искать. Этому и научимся.

Python может остановить программу в двух разных ситуациях: до запуска и во время работы.

<Theorem kind="definition" title="Синтаксическая ошибка и исключение"
  formal="Синтаксические ошибки обнаруживаются при разборе текста программы. Ошибки, обнаруженные во время выполнения, называются исключениями."
  source="Python Tutorial, гл. 8 «Errors and Exceptions», 8.1–8.2">

- <Term id="syntax-error">Синтаксическая ошибка</Term> — Python не может даже прочитать программу: не хватает скобки, кавычки, двоеточия. Он находит такие ошибки, прежде чем выполнить первую строку кода, — поэтому программа не запускается вовсе.
- <Term id="exception">Исключение</Term> — программа записана правильно, но во время работы случилось то, что выполнить нельзя: сложить строку с числом, превратить `"abc"` в число, обратиться к несуществующему имени. Строки кода до этого места успевают выполниться.

</Theorem>

Формально `SyntaxError` — тоже исключение, но возникает оно до выполнения первой строки кода.

</Page>

## Разбираем настоящее сообщение

Вот программа, которая должна сказать, сколько вам будет через год:

```python
age = input("Сколько вам лет? ")
next_year = age + 1
print("Через год вам будет", next_year)
```

Если запустить её на компьютере и ввести 20, Python выведет:

```
Сколько вам лет? 20
Traceback (most recent call last):
  File "C:\work\age.py", line 2, in <module>
    next_year = age + 1
                ~~~~^~~
TypeError: can only concatenate str (not "int") to str
```

Такое сообщение называется <Term id="traceback">traceback</Term> — «обратная трассировка»: путь, который прошла программа до места падения.

<Theorem kind="rule" title="Как читать сообщение об ошибке"
  formal="Последняя строка сообщения об ошибке указывает, что произошло: тип исключения и подробности. Предшествующая часть показывает контекст, в котором возникло исключение, в виде трассировки стека."
  source="Python Tutorial, 8.2 «Exceptions»">

Читайте **снизу вверх**: последняя строка сообщения — **что** случилось, строки над ней — **где**.

</Theorem>

Разберём по порядку:

1. **Последняя строка сообщения — первой.** Слева до двоеточия — тип ошибки: `TypeError`, ошибка типа. Справа — текст: «склеивать можно только str (не int) со str». Значит, где-то строку пытаются сложить с целым числом.
2. **Где.** `File "C:\work\age.py", line 2` — файл и номер строки кода. Слово `<module>` означает «в основной программе», а не внутри функции.
3. **Какая операция.** Ниже показана сама строка кода, а значки `~~~~^~~` подчёркивают выражение, где произошла ошибка; `^` указывает на виновный знак `+`.
4. **Почему.** Тип и место известны — теперь думаем: `age` — строка, ведь `input()` всегда возвращает строку. Строку и число `1` сложить нельзя. Исправление из второй темы: `age = int(input("Сколько вам лет? "))`.

Первая строка сообщения, `Traceback (most recent call last)`, означает «последний вызов — внизу». Когда появятся свои функции, над последней строкой окажется несколько пар «файл — номер строки», и нужно будет найти ту, что указывает на ваш код. Это разберём в разделе «Ошибки и отладка».

## SyntaxError

У синтаксической ошибки нет строки `Traceback`: программа даже не начала работать. Python показывает файл, номер строки кода и значок `^` под местом, где он «споткнулся»:

```
  File "C:\work\hello.py", line 1
    print("Привет"
         ^
SyntaxError: '(' was never closed
```

«Скобка `(` так и не закрылась». Три самые частые синтаксические ошибки новичка и их сообщения в Python 3.12:

<div className="table-scroll">

| Код | Сообщение | Что случилось |
|---|---|---|
| `print("Привет"` | `'(' was never closed` | не закрыта скобка |
| `print("Привет)` | `unterminated string literal (detected at line 1)` | строка не закрыта кавычкой |
| `if x > 5` | `expected ':'` | нет двоеточия в конце строки кода |

</div>

Инструкцию `if` вы изучите в следующем разделе; сейчас запомните только, что такие строки кода заканчиваются двоеточием.

Python часто сам предлагает исправление — например, «Perhaps you forgot a comma?», «может, вы забыли запятую?». Но это догадка. Если подсказка не подходит, смотрите на место под `^` и на строку кода выше: иногда ошибка сделана раньше, а заметна становится позже.

## IndentationError

Отступ — пробелы в начале строки кода — в Python имеет смысл, и лишний отступ даёт `IndentationError: unexpected indent`, «неожиданный отступ». Пока все строки кода должны начинаться с самого края. В следующем разделе отступы станут обязательными внутри условий и циклов.

## NameError: имя не найдено

Python не знает такого имени. Две частые причины — опечатка и использование имени раньше, чем его создали:

```python
name = input()
prnt("Привет,", name)
```

```
NameError: name 'prnt' is not defined. Did you mean: 'print'?
```

```python
total = price * 3
price = 100
print(total)
```

```
NameError: name 'price' is not defined. Did you mean: 'print'?
```

Во втором случае подсказка «Did you mean: 'print'?» — «может, вы имели в виду print?» — ошибочна: Python просто нашёл похожее по написанию имя. Настоящая причина — порядок строк кода: программа идёт сверху вниз, и в первой строке имени `price` ещё нет. Подсказки помогают, но думать за вас не могут.

<Callout kind="remember">
На платформе подсказок вида «Did you mean» нет — только тип, номер строки и основной текст. Полные сообщения вы увидите, когда начнёте запускать Python на своём компьютере.
</Callout>

## TypeError: операция не подходит к типу

Значения не того типа для этой операции. Самый частый случай вы уже видели в разборе traceback: `"5" + 1` — строка и число. Лечение — привести к одному типу: `int("5") + 1` или `"5" + str(1)`.

## ValueError: значение не годится

Тип правильный, но само значение не подходит:

```python
n = int("abc")
```

```
ValueError: invalid literal for int() with base 10: 'abc'
```

`int` ждёт строку и получил строку, но разобрать `"abc"` как целое число не может. Так бывает, когда пользователь ввёл не то, что программа ждала, — например, `3.5` вместо целого.

## EOFError: ввод закончился

`EOF` — end of file, «конец файла»: программа вызвала `input()`, а читать уже нечего. На компьютере сообщение `EOFError: EOF when reading a line`, на платформе — по-русски: «входные данные закончились: программа ждёт больше строк, чем ей дали».

В задачах это почти всегда значит, что вы читаете ввод не так, как сказано в условии. Например, два числа даны в одной строке ввода `3 5`, а программа вызывает `input()` дважды: первый вызов забирает всю строку `"3 5"`, второму ничего не остаётся. А если `input()` обёрнут в `int(...)`, первой упадёт `int("3 5")` — с `ValueError`.

## Порядок действий при ошибке

1. **Прочитайте последнюю строку сообщения.** Тип ошибки уже сужает поиск: `SyntaxError` — смотрите на запись, `NameError` — на имена, `TypeError` — на типы значений, `ValueError` — на сами данные.
2. **Найдите номер строки** и посмотрите на эту строку кода и на строку выше.
3. **Сформулируйте причину своими словами**: «во второй строке кода я складываю строку с числом, потому что `input()` вернул строку».
4. Если причина не видна — пройдите программу по шагам и посмотрите, на какое значение указывает каждое имя перед падением.
5. Исправьте и запустите снова. Новая ошибка ниже по коду — это прогресс: программа продвинулась дальше.

## Ошибка и ИИ-ассистент

Сначала прочитайте ошибку сами: чаще всего ответ уже в последней строке сообщения. Если всё же спрашиваете ассистента:

- передайте полное сообщение и код и просите объяснить **причину**, а не просто прислать исправление;
- проверьте исправление трассировкой: если вы не можете проследить, почему оно работает, — вы его ещё не поняли.
