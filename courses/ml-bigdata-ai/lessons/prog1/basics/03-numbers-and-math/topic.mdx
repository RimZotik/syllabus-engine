## Два вида чисел

В Python у чисел два основных типа, которые вы уже видели в прошлой теме:

- <Term id="int">int</Term> — целые числа: `7`, `-12`, `0`;
- <Term id="float">float</Term> — дробные числа, их ещё называют числами с плавающей точкой: `3.5`, `-0.25`, `2.0`.

Дробную часть отделяют **точкой**, а не запятой: `3.5`, а не `3,5`. Число `2.0` — это `float`, хотя дробной части у него нет: тип определяет запись, а не величина.

Если в операции участвует хотя бы одно дробное число, результат тоже дробный:

```python
print(3 + 4)
print(3 + 2.0)
print(10 * 0.5)
```

```
7
5.0
5.0
```

Целые числа в Python не переполняются, как во многих других языках: `print(2 ** 100)` выведет все 31 цифру точно.

## Три вида деления

Знаки `+`, `-` и `*` работают как в школе. Деления в Python три вида:

<div className="table-scroll">

| Знак | Что делает | Пример | Результат |
|---|---|---|---|
| `/` | обычное деление, результат всегда `float` | `7 / 2`, `6 / 3` | `3.5`, `2.0` |
| `//` | целочисленное деление: сколько раз делитель целиком помещается в делимое | `7 // 2` | `3` |
| `%` | остаток от деления (к процентам отношения не имеет) | `7 % 2` | `1` |

</div>

Для целых чисел `//` и `%` дают целое. Если хотя бы одно число дробное, результат тоже будет `float`: `7.0 // 2` даёт `3.0`.

Целочисленное деление и остаток нужны постоянно. Классический пример — перевести 3725 секунд в часы, минуты и секунды:

```python
seconds = 3725
hours = seconds // 3600       # целых часов: 1
rest = seconds % 3600         # секунд осталось: 125
minutes = rest // 60          # целых минут: 2
secs = rest % 60              # секунд осталось: 5
print(hours, minutes, secs)
```

```
1 2 5
```

Предскажите, что выведет программа для 7384 секунд, и проверьте себя: должно получиться `2 3 4`.

Ещё два частых приёма: `n % 10` — последняя цифра числа, `n // 10` — число без последней цифры. А `n % 2` равно 0 для чётных чисел и 1 для нечётных.

## Отрицательные числа

`//` округляет **вниз**, к меньшему числу на числовой прямой, а не «отбрасывает дробную часть». Поэтому `-7 // 2` равно `-4`: обычное деление даёт −3,5, а вниз от него — −4. Остаток подбирается так, чтобы сходилась проверка «частное × делитель + остаток = делимое»: `-7 % 2` равно `1`, ведь −4 · 2 + 1 = −7. Для положительных чисел «вниз» и «отбросить дробную часть» совпадают, разница видна только на отрицательных.

## Возведение в степень

Степень записывается двумя звёздочками: `2 ** 10` даёт `1024`, `9 ** 0.5` — квадратный корень, `3.0`. Знак `^`, которым степень пишут в калькуляторах, в Python означает совсем другую операцию: `2 ^ 10` молча даст `8`.

## Порядок действий

Python соблюдает приоритеты почти как в математике. От более сильных к более слабым:

<div className="table-scroll">

| Приоритет | Операции |
|---|---|
| 1 | скобки `( )` |
| 2 | степень `**` |
| 3 | минус перед числом: `-x` |
| 4 | `*`, `/`, `//`, `%` |
| 5 | `+`, `-` |

</div>

Операции одного уровня выполняются слева направо: `10 - 4 - 3` даёт `3`. Одна ловушка: степень сильнее минуса перед числом, поэтому `-2 ** 2` даёт `-4` — сначала `2 ** 2`, потом минус. Нужен квадрат отрицательного числа — ставьте скобки: `(-2) ** 2` даёт `4`. Не уверены в порядке — тоже ставьте скобки: лишние ничего не ломают.

## Короткая запись изменения

Строки кода вида `count = count + 5` встречаются так часто, что для них есть сокращение:

```python
count = 10
count += 5      # то же, что count = count + 5
print(count)
count *= 2      # то же, что count = count * 2
print(count)
```

```
15
30
```

Так же работают `-=`, `/=`, `//=`, `%=`. Правило присваивания из прошлой темы не меняется: сначала вычисляется новое значение, потом имя привязывается к нему.

## Где взять квадратный корень

Синуса, логарифма или числа π среди встроенных функций Python нет. Они лежат в <Term id="module">модулях</Term> — наборах готового кода, которые подключают к программе, когда они нужны.

Математические функции лежат в модуле `math`. Подключают его инструкцией `import`, обычно в самом начале программы:

```python
import math

print(math.sqrt(16))
print(math.sqrt(2))
print(math.pi)
```

```
4.0
1.4142135623730951
3.141592653589793
```

После `import math` имя `math` указывает на модуль, а функции из него вызываются через точку: `math.sqrt` — «функция `sqrt` из модуля `math`». `sqrt` — квадратный корень, он всегда возвращает `float`. Если забыть `import`, Python не узнает имя `math` и остановится с ошибкой `NameError` — как читать такие сообщения, разберём в последней теме раздела.

</Page>

## 0.1 + 0.2

Предскажите вывод, потом читайте дальше:

```python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

```
0.30000000000000004
False
```

Компьютер хранит дробные числа в двоичной системе, и `0.1`, `0.2`, `0.3` в ней записываются с крошечной погрешностью — как 1/3 нельзя точно записать десятичной дробью. Сумма округляется до ближайшего числа, которое компьютер умеет хранить, и это число не совпадает с тем, что хранится для `0.3`. Подробно это разбирается в дисциплине «Язык математики», в разделе «Числа, степени и логарифмы».

<Theorem kind="rule" title="Дробные числа не сравнивают через =="
  formal="Большинство десятичных дробей нельзя точно представить двоичными дробями."
  source="Python Tutorial, гл. 15 «Floating-Point Arithmetic: Issues and Limitations»">

Поэтому результаты вычислений с `float` часто неточны в последних знаках, и проверка «равны ли два дробных числа» через `==` может дать `False` там, где по математике должно быть `True`. Вместо неё спрашивают «достаточно ли они близки» — функцией `math.isclose`.

</Theorem>

```python
import math

print(math.isclose(0.1 + 0.2, 0.3))
```

```
True
```

`math.isclose` считает числа равными, если они отличаются меньше чем на крошечную долю своей величины. Сравнение с нулём — отдельный случай: там нужен параметр `abs_tol`, он описан в документации модуля. С целыми числами такой проблемы нет: `int` всегда точен.

## Округление

`round(x)` округляет до целого, `round(x, n)` — до `n` знаков после точки: `round(3.14159, 2)` даёт `3.14`. Сюрприз: `round(2.5)` даёт `2`, а `round(3.5)` — `4`. Половинки округляются к ближайшему чётному. Округлять лучше при выводе, а не в середине вычислений; как вывести число с двумя знаками, разберём в следующей теме.
