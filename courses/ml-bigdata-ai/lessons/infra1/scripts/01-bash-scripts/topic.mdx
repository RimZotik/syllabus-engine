## Записать рутину один раз

Каждое утро вы копируете выгрузки в `backup` и считаете в них строки: `mkdir -p backup`, `cp data/*.csv backup/`, `wc -l data/*.csv`. Через месяц вы перепутаете папки. Команды можно записать в файл и запускать одной строкой.

<Theorem kind="definition" title="Скрипт оболочки"
  formal="Скрипт оболочки (shell script) — текстовый файл с командами оболочки; bash, получив его аргументом, выполняет команды из него по порядку. Если исполняемый файл запущен по пути и его первая строка начинается с #!, ОС запускает программу, названную в остатке этой строки, и передаёт ей путь к файлу."
  source="GNU Bash Reference Manual, 3.8 «Shell Scripts» (пересказ); man7.org, execve(2); W. Shotts, «The Linux Command Line», гл. 24">

<Term id="shell-script">Скрипт оболочки</Term> (bash-скрипт) — команды, которые вы набираете после приглашения, записанные в файл. Первая строка вида `#!/bin/bash` — <Term id="shebang">шебанг</Term> (shebang): она говорит ОС, какой программой выполнить файл.

</Theorem>

Это такой же скрипт, как на Python, только читает его bash. `#` начинает комментарий; для bash шебанг — тоже комментарий, читает его ОС.

Предскажите ответ каждой команды, потом нажимайте «Следующая команда»:

<Shell
  files={{"data/jan.csv": "id,amount\n1,10\n2,20\n", "data/feb.csv": "id,amount\n3,5\n", "morning.sh": "#!/bin/bash\nmkdir -p backup\ncp data/*.csv backup/\nwc -l data/*.csv\n"}}
  script={["cat morning.sh", "./morning.sh", "bash morning.sh", "chmod u+x morning.sh", "./morning.sh", "ls backup", "morning.sh"]}
/>

## Два способа запуска

`bash morning.sh` запускает программу `bash`, а файл она только читает: хватает права на чтение (r). `./morning.sh` запускает сам файл: нужно право на выполнение (бит x), а программу ОС узнаёт из шебанга. `morning.sh` без косой черты ищется по `PATH`, где текущей папки нет. Часто пишут `#!/usr/bin/env bash`: `env` найдёт `bash` по `PATH`.

Скрипт — дочерний процесс. Он видит только экспортированные переменные (`x=5; ./s.sh` — внутри `$x` пуст), а его `cd` и переменные не меняют ваше окно. В текущей оболочке файл выполняет `source` (или точка: `. файл`) — так включают и виртуальное окружение.

<Callout kind="warning" title="Скрипт из Windows: $'\r': command not found">
Редакторы Windows часто пишут концы строк `\r\n`, а bash считает `\r` частью команды:

```text
student@forge:~$ ./hello.sh
bash: ./hello.sh: /bin/bash^M: bad interpreter: No such file or directory
student@forge:~$ bash hello.sh
hello.sh: line 3: $'\r': command not found
```

`^M` и `$'\r'` — это байт `\r`; в непустой строке он прилипает к последнему слову: `cd data` ищет папку `data\r`. Починить: Alt+D при сохранении в `nano`, как в теме о nano, или `sed -i 's/\r$//' hello.sh` — программа `sed` удалит `\r` в конце строк.
</Callout>

## Всё — строки

Переменная оболочки задаётся как `имя=значение`, без пробелов: `n = 5` оболочка поймёт как команду `n` с аргументами `=` и `5`: `bash: n: command not found`. Значение — всегда строка: после `n=5` команда `echo $n+1` печатает `5+1`. Считает конструкция `$(( … ))`: `echo $((n + 1))` печатает `6`. Внутри неё строки становятся целыми числами, `$` перед именем можно не ставить; дробей нет: `$((7 / 2))` даёт `3`.

## Вывод команды — в переменную

<Term id="command-substitution">Подстановка команды</Term> `$(команда)` выполняет команду и подставляет вместо себя то, что она напечатала в stdout, без завершающих `\n`. Как и `$ИМЯ`, её раскрывает оболочка до запуска команды.

```text
student@forge:~$ today=$(date +%F)
student@forge:~$ echo "Сегодня $today"
Сегодня 2026-11-23
```

`date +%F` печатает дату в виде ГГГГ-ММ-ДД.

## Кавычки вокруг переменной

Подставив переменную без кавычек, оболочка **ещё раз** делит её значение — по пробелам и переводам строк — и раскрывает в нём шаблоны. В папке есть `отчёт май.csv` и черновик с именем `отчёт`:

```text
student@forge:~$ f="отчёт май.csv"
student@forge:~$ cat $f
черновик
cat: май.csv: No such file or directory
student@forge:~$ cat "$f"
id
1
```

`cat $f` получил два аргумента и показал другой файл — `отчёт`; `rm $f` удалил бы не тот. <Mark>Переменную в команде берут в двойные кавычки: `"$f"`</Mark> — тогда значение остаётся одним аргументом.

## Аргументы скрипта

Внутри скрипта аргументы — <Term id="positional-parameters">позиционные параметры</Term>: `$1`, `$2`, … `$9` по порядку, `$#` — их число, `"$@"` — все, каждый отдельным словом, `$0` — имя, под которым запустили скрипт.

<Shell
  files={{"args.sh": {content: "#!/bin/bash\necho \"скрипт: $0\"\necho \"аргументов: $#\"\necho \"первый: $1\"\nfor a in \"$@\"; do\n  echo \"[$a]\"\ndone\n", mode: "755"}}}
  script={["cat args.sh", "./args.sh jan.csv \"отчёт май.csv\"", "./args.sh"]}
/>

Непереданный аргумент — пустая строка: проверять, что аргументы есть, придётся самим. Значение по умолчанию: `${1:-data}` — `$1`, а если его нет, `data`.

## Команда вместо выражения

В Python `if` вычисляет выражение и проверяет его истинность. В bash после `if` стоит **команда**.

<Theorem kind="rule" title="Как if выбирает ветку"
  formal="if команды; then команды; [elif команды; then команды;] … [else команды;] fi: если код возврата команд после if равен нулю, выполняются команды после then; иначе так же проверяется каждый elif, а если ни один не дал нуля — выполняются команды после else."
  source="GNU Bash Reference Manual, 3.2.5.2 «Conditional Constructs» (пересказ); IEEE Std 1003.1 (POSIX), Shell Command Language, 2.9.4">

`if` запускает команду и смотрит на её код возврата: 0 — ветка `then`, не 0 — `elif` или `else`. «Истинно» и «ложно» здесь нет — только успех команды или неудача. Конец — `fi`.

</Theorem>

В `if grep -q молоко todo.txt; then echo "уже в списке"; fi` код 0 у `grep -q` — «нашёл». В Python `0` — ложь, а здесь — успех, и `then` выполнится на нём.

## [ — тоже команда

Для сравнений есть команда `test`, её второе имя — `[`; последним аргументом она требует `]`. Возвращает 0 — верно, 1 — неверно, 2 — ошибка в самой проверке. Раз `[` — команда, пробелы вокруг обязательны: при `x=5` в `[$x -eq 5]` оболочка увидит слово `[5` и ответит `bash: [5: command not found`.

| Проверка | Что значит |
|---|---|
| `[ -f "$f" ]`, `[ -d "$f" ]`, `[ -e "$f" ]` | есть файл, папка, что угодно |
| `[ -z "$s" ]`, `[ -n "$s" ]` или просто `[ "$s" ]` | строка пустая, непустая |
| `[ "$a" = "$b" ]`, `[ "$a" != "$b" ]` | строки равны, не равны |
| `[ "$n" -eq 5 ]`, `-ne`, `-lt`, `-le`, `-gt`, `-ge` | числа: равно, не равно, меньше, не больше, больше, не меньше |

`[ 007 = 7 ]` — код 1, `[ 007 -eq 7 ]` — код 0: строки и числа сравнивают разные операторы. `==` в `[ ]` bash понимает как сравнение **строк**, а `<` и `>` примет за перенаправление.

Кавычки и здесь обязательны. Пустая `$name` без них превращает `[ $name = Анна ]` в `[ = Анна ]`, и `[` жалуется: `bash: [: =: unary operator expected`. С `"$name"` получится честное «не равны».

## Скрипт сообщает об ошибке

При ошибке скрипт завершается с ненулевым кодом: `exit N`, а сообщение пишут в stderr: `echo "…" >&2` — та же запись, что `2>&1`, только наоборот: поток 1 туда же, куда поток 2.

<Shell
  files={{"check.sh": {content: "#!/bin/bash\nif [ $# -ne 1 ]; then\n  echo \"использование: $0 ФАЙЛ\" >&2\n  exit 2\nelif [ -f \"$1\" ]; then\n  echo \"$1: $(wc -l < \"$1\") строк\"\nelse\n  echo \"$1: нет такого файла\" >&2\n  exit 1\nfi\n", mode: "755"}, "sales.csv": "id,amount\n1,10\n2,20\n"}}
  script={["cat check.sh", "./check.sh sales.csv", "./check.sh nope.csv; echo \"код: $?\"", "./check.sh; echo \"код: $?\""]}
/>

`$?` редко читают отдельно — команду ставят после `if` или `||`: `./check.sh "$f" || exit 1`.

## for — по списку слов

`for имя in слово1 слово2 …; do команды; done` выполняет команды для каждого слова по очереди. Чаще всего слова — имена файлов из шаблона. Предскажите все три вывода, прежде чем нажимать:

<Shell
  files={{"data/jan.csv": "id,amount\n1,10\n2,20\n", "data/feb.csv": "id,amount\n3,5\n", "data/отчёт май.csv": "id\n1\n"}}
  dirs={["empty"]}
  script={["for f in data/*.csv; do echo \"$f: $(wc -l < \"$f\")\"; done", "for f in $(ls data); do wc -l \"data/$f\"; done", "for f in empty/*.csv; do echo \"файл: $f\"; done"]}
/>

- **Шаблон** даёт список имён, каждое имя — одно слово, даже с пробелом.
- **`$(ls)` — ловушка:** вывод `ls` — просто текст, и оболочка делит его, так что `отчёт май.csv` распалось надвое.
- **Совпадений нет** — шаблон остаётся как есть, и цикл выполнится один раз со словом `empty/*.csv`. Защита — первой строкой тела: `[ -e "$f" ] || continue`; `continue`, как в Python, переходит к следующему шагу.

## while — пока команда успешна

`while команда; do …; done` повторяет тело, пока команда возвращает 0. Так читают файл построчно: `read -r line` берёт строку из stdin в `line` (`-r` не трогает `\`), `< todo.txt` после `done` подаёт файл в stdin цикла, а в конце файла `read` возвращает 1. Здесь у последней строки нет `\n`:

<Shell
  files={{"todo.txt": "купить молоко\nпозвонить маме\nоплатить свет"}}
  script={["while read -r line; do echo \"- $line\"; done < todo.txt", "while read -r line || [ -n \"$line\" ]; do echo \"- $line\"; done < todo.txt"]}
/>

Последнюю строку без `\n` `read` прочитает, но вернёт 1, и тело на ней не выполнится; `|| [ -n "$line" ]` пропускает в тело и её.

## Ошибка — а скрипт идёт дальше

Команда в скрипте не удалась — она печатает ошибку, а bash идёт дальше. В `go.sh` после шебанга — `cd /data/today` и `echo "я в $PWD"`:

```text
student@forge:~$ ./go.sh; echo "код $?"
./go.sh: line 2: cd: /data/today: No such file or directory
я в /home/student
код 0
```

Если бы вместо `echo` стояло удаление временных файлов, оно прошло бы не в той папке, а код 0 сказал бы, что всё хорошо.

## set -euo pipefail

Строка `set -euo pipefail` сразу после шебанга включает три настройки:

- `-e` — завершить скрипт, как только команда вернула не 0. Кроме команды-условия в `if` и `while` и команд слева от `&&` и `||`: там ненулевой код — ответ, а не ошибка.
- `-u` — переменная, которую ни разу не задали, — ошибка: опечатка `$fiel` остановит скрипт, а не даст пустую строку. Непереданный `$1` — тоже ошибка `$1: unbound variable`, поэтому сначала проверяют `$#` или пишут `${1:-}`.
- `-o pipefail` — конвейер неуспешен, если упала хотя бы одна его команда. Без этого `grep ERROR nope.log | wc -l` вернёт код `wc`, то есть 0.

С `set -e` скрипт `go.sh` остановится на `cd` с кодом 1. Но `-e` ловит не всё: в `echo "строк: $(wc -l < nope.csv)"` ошибку `wc` заглушит успешный `echo`. Важный результат сначала кладут в переменную — `n=$(wc -l < "$f")`, тогда `-e` сработает. И наоборот, «не нашёл» для `-e` — тоже неудача: `n=$(grep -c ERROR "$f")` на файле без ошибок вернёт 1 и молча оборвёт скрипт. Там, где «не нашёл» — нормальный ответ, пишут `|| true`: `true` возвращает 0.

  options={["Ошибка cp, остановка с кодом 1, без «готово»", "Только «готово»: цикл по пустой папке не выполнится", "Ошибка cp, затем «готово»: в цикле set -e не действует", "В archive появится файл *.log"]}

/>

Bash склеивает готовые программы; появились дроби, словари, разбор CSV или полсотни строк — пора на Python. На своей машине пригодится `bash -x script.sh`: печатает каждую команду перед выполнением.
