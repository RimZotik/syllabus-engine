## От nano к редактору кода

nano хорош на сервере, где ничего другого нет. Для проекта нужен <Term id="code-editor">редактор кода</Term> — текстовый редактор, который понимает программы: подсвечивает синтаксис, подчёркивает ошибку до запуска, подсказывает имена, запускает программу и отладчик. Программу, где всё для разработки собрано вместе, называют IDE (integrated development environment — среда разработки). В курсе — **VS Code**: он бесплатный и умеет работать с кодом внутри WSL.

## Окно в Windows, код в Linux

Проект, Python и терминал — в Ubuntu, а окно VS Code — в Windows. Связывает их расширение **WSL** от Microsoft: оно ставит в Ubuntu серверную часть VS Code — программу-помощника, которая работает в Linux и выполняет всё, что касается кода.

Порядок такой (названия — из английского интерфейса VS Code):

1. Поставьте VS Code в Windows и в нём — расширение WSL.
2. В Ubuntu перейдите в папку проекта и наберите `code .` — точка значит «текущая папка». В первый раз VS Code скачает в Ubuntu серверную часть. В левом нижнем углу окна — индикатор `WSL: Ubuntu-24.04`.
3. В этом окне откройте **Extensions** (`Ctrl+Shift+X`) и поставьте **Python** от Microsoft кнопкой **Install in WSL: Ubuntu-24.04**: расширения для кода ставятся отдельно в WSL. Вместе с Python встанет **Python Debugger**.
4. Терминал в VS Code (`` Ctrl+` ``) — bash вашей Ubuntu.

Своего Python у VS Code нет: он запускает тот, что выбран для проекта. Выбирают его в строке состояния внизу или командой **Python: Select Interpreter** (`Ctrl+Shift+P`). Пока выбран системный `/usr/bin/python3`; про окружения проекта — следующая тема.

<Callout kind="warning" title="Если code не находится">
WSL при запуске добавляет к `PATH` Ubuntu папки из `PATH` Windows — поэтому из Ubuntu запускаются `explorer.exe` и `code`. Установщик VS Code дописал свою папку в `PATH` Windows, а уже открытый терминал получил `PATH` раньше. Закройте Windows Terminal целиком и откройте снова; не помогло — переустановите VS Code с отмеченным пунктом **Add to PATH**. Подсказку Ubuntu `sudo snap install code` не выполняйте: она поставит отдельный VS Code внутрь Linux.

## Остановить программу на строке

Помните тёплые дни из темы об отладке? Ошибку там искали через `print`, `assert` и деление пополам. <Term id="debugger">Отладчик</Term> делает это без правки кода: запускает программу под наблюдением, останавливает её и показывает все имена — как пошаговое выполнение в песочнице, но на вашей настоящей программе.

<Theorem kind="definition" title="Точка останова"
  formal="Точка останова (breakpoint) — отметка в исходном коде, при достижении которой отладчик приостанавливает программу до выполнения отмеченной строки и позволяет изучить её состояние: значения переменных и стек вызовов. Условная точка останова приостанавливает программу, только если её условие истинно."
  source="VS Code Docs, «Debug code with Visual Studio Code» — Breakpoints, Conditional breakpoints (пересказ); GDB Manual, 5.1 «Breakpoints, Watchpoints, and Catchpoints»">

<Term id="breakpoint">Точка останова</Term> — красная метка слева от номера строки. Программа замирает **перед** этой строкой: значение, которое строка присваивает, ещё не присвоено.

</Theorem>

Программа должна печатать среднюю температуру тёплых дней — 3, 5 и 4, то есть 4.0. Она печатает 3.0:

```python
def average(values):
    total = 0
    for v in values:
        total += v
    return total / len(values)


def report(temps):
    warm = [t for t in temps if t >= 0]
    return round(average(warm), 1)


print(report([3, -2, 5, 0, 4]))
```

## Как запустить и куда смотреть

1. Щёлкните слева от номера строки `total += v` или поставьте на неё курсор и нажмите `F9` — появится красная точка.
2. Запустите отладку: стрелка рядом с кнопкой запуска над редактором → **Python Debugger: Debug Python File**.
3. Программа остановится, а строка подсветится: она выполнится следующей. Слева откроется вид **Run and Debug** (`Ctrl+Shift+D`), в нём панели:
   - **VARIABLES** — имена текущего вызова и их значения: `values`, `total`, `v`;
   - **WATCH** — выражения, которые вы вписали сами, например `len(values)`; пересчитываются на каждой остановке;
   - **CALL STACK** — <Term id="call-stack">стек вызовов</Term>. Здесь стопка стоит наоборот, чем в traceback: последний вызов **сверху**. Сверху `average`, под ней `report`, внизу основная программа. Щелчок по `report` покажет её имена — там видно `warm`.

Предскажите, что покажет `values` на первой остановке, — потом проверьте. `[3, 5, 0, 4]`: в список попал ноль. Ошибка не в `average`, а в условии `t >= 0` — тёплый день значит `t > 0`.

## Шаги

| Клавиша | Что делает |
|---|---|
| `F10` | шаг без захода: выполнить строку целиком, даже если в ней вызов функции |
| `F11` | шаг с заходом: войти в вызываемую функцию |
| `Shift+F11` | выйти: досчитать текущую функцию и остановиться там, откуда её вызвали |
| `F5` | продолжить до следующей точки останова |
| `Shift+F5` | остановить отладку |

Шагать назад отладчик не умеет: выполненное уже выполнено. Значение имени можно поменять на ходу — правый щелчок в VARIABLES → **Set Value**, чтобы проверить догадку, не перезапуская программу.

## Условная точка

Условная точка нужна, когда интересна не первая остановка, а сотая. Щёлкните правой кнопкой по полю слева от номера строки → **Add Conditional Breakpoint** → **Expression** и условие, например `v > 4`. **Hit Count** останавливает на N-м проходе.

Отладчик выполняет программу так же, как обычный запуск, только медленнее и с паузами. Условие точки проверяется на каждом проходе, поэтому в цикле на миллионы шагов отладка заметно тормозит. А если ошибка зависит от времени, паузы могут её спрятать.

На сервере по SSH окна VS Code нет. Там ту же остановку даёт строка `breakpoint()` в коде: Python остановится на ней и откроет текстовый отладчик pdb — `n` выполняет строку, `c` продолжает, `q` выходит.
